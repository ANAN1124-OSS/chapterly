# 章回 · 项目结构

> 面向想读代码 / 二次开发的人。只想用软件的话看 [README](../README.md) 就够了。
> 铁律：**规范以仓库里的代码与测试为准**，本文只负责指路。

## 一、三层结构

章回是 Electron + 原生 HTML/CSS/JS（无框架、无打包器）。进程边界就是安全边界：

```
renderer/            界面与交互（渲染进程：无 Node、无文件系统权限）
   │  只经 preload.js 暴露的窄接口
   ▼
preload.js           白名单桥（contextBridge）
   │  ipcRenderer.invoke → 频道白名单
   ▼
ipc/                 主进程 IPC 注册（每个领域一个文件，参数校验 + 结果归一）
   │  调用纯逻辑
   ▼
core/                纯逻辑：存储 / 书目 / 导入导出 / 搜索 / 统计 / 安全策略
   │
   ▼
磁盘                书架目录（一本书一个文件夹）+ %APPDATA%\chapter-writer
```

- `main.js`：应用入口。窗口、菜单、单实例、退出前置检查（未保存拦截 / flush 看门狗）都在这里；启动参数（`--books-root`、`--user-data`、`--screenshot`、`--e2e`）也在这里解析。
- `preload.js`：**唯一**的渲染进程 → 主进程通道。新增 IPC 必须同时改它、`ipc/`、主进程白名单与相关静态闸门。
- `renderer/index.html` 只是骨架；版本号等运行时信息由主进程注入，**不写死**。

## 二、目录与职责

| 路径 | 内容 | 备注 |
|---|---|---|
| `main.js` / `preload.js` | 进程入口与桥 | 入口改动会影响打包与 E2E |
| `core/` | 纯逻辑（68 个模块；数量以 `git ls-files "core/*.js"` 为准） | 不碰 DOM；多数可单测直接 require |
| `ipc/` | `book.js` / `book-data.js` / `book-mutations.js` / `save.js` / `export.js` / `proofread.js` / `soft-error.js` | 每个文件一组频道，参数上限见 `core/ipc-limits.js` |
| `renderer/` | 前端模块 + `index.html` + `styles.css`（76 个模块，清单见 `renderer/assembly-manifest.js`） | `renderer.js` 只做装配与事件分发；各域在独立 `*-ui.js` |
| `scripts/` | 开发、构建、门禁、E2E、bench | 见第五节 |
| `tests/` | `*.test.js` 用例 + `fixtures/`（256 个，以 `git ls-files "tests/*.test.js"` 为准） | `node:test`；静态闸门与行为断言并存 |
| `build/` | 图标 + Electron 官方校验清单 | 供应链门禁的数据源 |
| `docs/` | 你我正在看的这些文档 | 公开文档 |
| `.github/` | CI 三套工作流 + dependabot | 见 `.github/workflows/` |

## 四、renderer 的组织方式

- `renderer.js`：装配入口（按 `scripts/assembly-sync.js` 生成的清单加载模块），只保留启动、状态与事件分发。
- `*-ui.js`：每个面板 / 视图一个模块（`bookinfo-ui.js`、`chapter-directory-ui.js`、`find-ui.js`、`settings-ui.js`、`shelf-filter-ui.js`、`tidy-card-ui.js`…），统一由 `createXxxUi(host)` 注入依赖，缺成员直接抛错（`assert-host.js`）。
- `*-logic.js`：可纯函数化的规则（`editor-logic.js`、`find-logic.js`、`save-logic.js`、`reading-logic.js`、`stats-logic.js`…），便于单测。
- `test-hooks.js`：仅开发 / E2E 在 `?test=1` 时动态加载，**不进安装包**（`package.json` 的 `build.files` 已排除）。
- `assembly-manifest.js` + `scripts/assembly-sync.js`：模块装配清单，`--check` 会拦住"清单与实际不一致"。

## 五、scripts 与门禁

| 类别 | 脚本 |
|---|---|
| 启动 / 演示 | `start.js`、`demo-data.js`、`screenshot-driver.js` |
| 打包 / 供应链 | `make-icon.py`、`supply-chain-check.js`、`verify-electron-checksum.js` |
| 测试 | `run-e2e.js`、`e2e-scenario.js`、`e2e-scope.js`、`bench*.js`、`contrast.js`、`a11y-gate.js` |
| 一致性闸门 | `version-sync.js`、`assembly-sync.js`、`wiring-check.js`、`lint-gate.js`、`sweep-unused.js`、`gen-shortcut-doc.js` |

E2E 在 `scripts/e2e/groups/` 下按组编号（`00-…` 到 `83-…`，共 84 组）；跑全量用 `pnpm run e2e`，PR 级只跑受改动影响的组（`e2e-scope.js`）。

## 六、tests 的两种形态

1. **行为断言**：真实调用 core / renderer 模块，比对结果（新增功能优先写这种）。
2. **静态闸门**：读源码 / `index.html` 再断言字符串，钉"接线、顺序、唯一实现、逐字文案"。这类是**有意的防漂移锚点**，不为了数量好看去删（策略见 [维护与自检](维护与自检.md)）。

命名约定、审计编号与夹具用法见 `tests/README.md`。

## 七、常用命令

```bash
pnpm start            # 开发版启动
pnpm test             # 单测（node:test）
pnpm run e2e          # 全量 E2E（真实 Electron）
pnpm lint             # eslint 门禁（0 ERROR）
pnpm run dist         # 打 Windows 安装包（predist 先跑供应链校验）
node scripts/version-sync.js --check     # 版本 / 计数锚点校验
node scripts/assembly-sync.js --check    # 模块装配清单校验
```
