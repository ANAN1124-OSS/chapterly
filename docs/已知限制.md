# 章回 / Chapterly · 已知限制（完整清单）

> 本文件是 README「已知限制（要点）」的完整版：逐条记录各版本审计结论留下的边界与有意取舍（审计 M-N3 从 README 拆出）。
> 这些不是待修 bug 清单——每条都写明「为什么保留 / 代价是什么」。要改变其中任何一条，先改实现、测试与文档，不要只改代码。

## 已知限制（仍有意不做）

- 安装包**未签名**：首次安装 Windows SmartScreen 会提示「已保护你的电脑」，点「更多信息 → 仍要运行」即可；自动更新只做了**轻量版**（手动检查 → 打开 GitHub 下载页），**没有自动下载、自动安装、后台静默升级，也没有代码签名**，升级仍需你自己下载安装包覆盖安装
- **Electron 安全开关之外的残余风险（v0.9 C-1 审计结论，本阶段只记录不修改）**：页面仍用 `file://` 加载（没有换成自定义协议），打包配置**已开** `enableEmbeddedAsarIntegrityValidation` 与 `onlyLoadAppFromAsar` 这两个 fuse（`grantFileProtocolExtraPrivileges` 未显式关，仍是 Electron 默认）——它们只有打包后才验证得出来，本阶段按约定不打包，发版时由打包后的冒烟检查覆盖；`Ctrl+Shift+I` 只在**开发 / 自检构建**里能打开开发者工具（**打包后的正式版已不绑定**，见 2026-11-05 审计整改；窗口开着 `sandbox` + `contextIsolation`，里面同样没有 Node 能力）。这些都不改变「渲染层没有文件系统权限、正文只能由主进程按既有校验读写」这条主线
- **路径校验的剩余边界（v0.9 C-2 / C-2b 审计结论；2026-11-22 三审后收窄一条）**：①书文件夹如果本身是**符号链接 / 目录联接**并指向书架外，文本路径判定拦不住（要先有人在你自己的书架上造出这种链接）——**2026-11-22 起书入口多了一道 realpath 复核**：书目录解析出的真实路径不在书架根（也按真实路径解析）下面时直接拒绝（`BAD_PATH`，中文提示，不带本机路径），「在新窗口打开」同口径；联接书库根本身、网络盘 / UNC 路径照常放行，realpath 解析不出来（书还没建 / 目录刚被删 / 盘离线）也放行，绝不把正常读写挡在门外。仍剩一条：**单个章节文件**若是链接、而书目录本身在库内，本版不做逐文件 realpath；②`config:set` 里的 `booksRoot` 与两份词表路径现在只认**主进程自己弹出的对话框刚选中的那个**（来源校验见第 35 条），所以设置里的「书架目录」输入框改成只读——改目录请点右侧「选择…」，行为与提示跟以前一致；③来源校验按**字符串等价**判断：如果你先在对话框里选了 `D:\书架`，再手动写出它的子目录 `D:\书架\子目录` 当书架，会被当成「来源不明」忽略（重新点「选择…」选一次即可）；④改坏了也只是读不到，不会写坏书库
- **目录联接书库（2026-11-06 拍板）**：书架根目录可以是指向别的盘 / 别的目录的**目录联接**（Windows junction）——列书、打开、读章、保存都照常走真实目录，「整个书库放在别的盘、用联接挂进来」这种用法**受支持**，并由回归用例 `tests/junction-library.test.js` 钉住（防止以后的路径规范化改动把它弄坏）。代价是应用**不做 realpath、也不校验符号链接指向**：安全边界依赖本机文件系统权限（只有你自己能在这台机器上造链接）；同一个物理书库用两个不同路径名打开时会被当成两本（正常从书架入口打开不会发生——书架永远只用配置里那一个书库路径）。另一条现有边界：**书文件夹本身**若是联接，书架列举只认直接子目录，它不会自动出现在书架（路径已知时仍能读章 / 保存）；要让它自动出现属于行为变更，本版未做（见 `下一阶段提案.md` §6）。
- **2026-11-05 审计整改后的四条边界**：①`config.json` 只认已知字段——手动往配置里塞的未知键在加载 / 保存时会被丢弃（旧配置缺新键照常打开、自动补默认值）；路径字段（书架目录 / 两份词表 / 编辑器自定义字体）只认「原值 / 设置里刚用「选择…」选中的那个」，其它来源一律忽略并留一条日志。②`font:read` 先 `realpath` 再按真实路径校验 `.ttf` / `.otf` / `.ttc` 与 24MB 上限；按书 / 全局配置解析出的本机绝对路径**不再额外扩散**（这条只是「这一个回包不带路径」，不代表渲染层拿不到本机路径——见下一条清单）。
- **渲染层可见的本机路径清单（N-19 口径，2026-11-23）**：`config:get` 返回整份配置，渲染层能看到 `booksRoot`、`editorCustomFontPath`、`sensitiveWordsPath`、`proofreadWordsPath`、`lastBook.path` 等由你自己在设置 / 对话框里选过的路径；`book:get-display` 是通用只读接口，按 `bookId` 返回该书的显示覆盖（字号 / 纸色 / 字体等，字体字段里带路径）；`font:pick` 只把「刚选中的那一趟」的路径回给渲染层；错误文案与日志按 C-4 脱敏（只留最后一节）。所以：**应用不把「渲染层不知道书库路径」当安全前提**——纵深防御靠主进程的来源校验（`config:set` / `book:set-display` 里的路径只认对话框刚选中的值或原值），以及书入口 / 章节路径的 realpath 与书架根复核。③打包后的正式版**不认** `--e2e` / `--bench` / `--contrast` / `--screenshot` 这些自动化开关（自检频道不注册、窗口与关闭流程都走正常路径）；安装版冒烟用的 `--user-data` / `--books-root` 与 Chromium 自己的 `--remote-debugging-port` 保留。④关窗放行由主进程按「自己掌握的未保存状态 + 最近一次保存成功回执」交叉判定，界面单方说「可以关」不再足够；「不保存退出」会在界面侧先如实清掉脏状态再放行
- **错误文案 / 日志脱敏的两条边界（v0.9 C-4 审计结论）**：①界面与日志里的本机绝对路径只留最后一节（`…\001-第1章.txt`）——**文件名仍在**（书里的章节文件名本来就带章号，看得出是哪一章；书名只在文件夹名里，已经不会出现）。分享日志 / 截图前扫一眼仍然是好习惯。②「设置」里看到的书架目录、词表路径是你自己选的那几个配置值（设置界面需要显示），它们**不会**被脱敏；脱敏只作用于错误提示、状态行与诊断日志。原始英文错误信息（`EPERM: operation not permitted, open '…'`）只留在本机日志里，界面上看到的是中文结论 + 文件名
- **导入 / 导出的两条边界（v0.9 C-3 审计结论）**：①「导入小说」的单本 txt 上限是 **128 MB**（纯文本小说远到不了：1000 万字中文约 30 MB）；超过会提示体量并跳过，**不会先读进内存**。把图片 / 程序改名成 `.txt`（含 NUL 字节）或没有 BOM 的 UTF-16 会被当成「不是纯文本」拒绝；UTF-8（含 BOM）/ 带 BOM 的 UTF-16 / GBK 照常识别。整本书文件夹导入与「一本书的章节目录」导入也是**原样复制、不读正文**，但从 1.6.1 起复制前逐 txt 过同一条 128 MB 闸门（V25）：超限的单个文件不复制、记进导入结果的「跳过 N 个」汇总，其余文件照常导入，整批不中断；现成书形态里被跳过的那一章会从复制出的书目里去掉，不留打不开的悬挂章节（单章特别大时，打开那一章的编辑体验仍受 30 万字标记层上限保护）。②EPUB / DOCX 的 zip 条目名**只用本应用生成的 ASCII 名字**（`OEBPS/text/chapter-0001.xhtml` / `word/document.xml` 这种），书名 / 卷名 / 章名只进正文——所以包里的文件名与书名无关（用阅读器 / Word 打开看到的内容才是书名），这是长期设计，现在由 `core/zip.js` 的条目名闸门强制保证：以后谁把作者输入拼进条目名，会直接在导出时报错，而不是产出解压时能把文件写到包外面的包。③**2026-11-22 三审 P1 起**，导入侧还要过「单章 500 万字」的保存上限：整本一章（raw）超过 500 万字、或按原文切出的某一章超过 500 万字时，在写第一个章节文件之前**明确拒绝并提示**（整本一章不自动拆分——它对作者的承诺是「原样一章」，静默改章名会改变书目结构）；导入回包进「失败（原因）」，书架里不留半本书。要导入这样的书，请在源文件里把那一部分拆小，或改用「按原文章节导入」
- **单本书的章节记录最多 20,000 章（书目层硬上限，2026-11-22 三审 E1 / D7）**：`书目.json` 的 `chapters` 超过 20,000 条时，读侧按「书目损坏」处理（书卡标 corrupt、按损坏态提示，一个字节的正文都不动），**写侧在写盘前直接拒绝**（`META_TOO_MANY_CHAPTERS`，连 `.bak` 都不轮换）——导入切出 20,001 章会整本拒绝并提示、建章 / 从目录重建同样受这一条约束，绝不写出「自己能写、自己打不开」的书。正常长篇远到不了（20,000 章 × 每章 3 万字 ≈ 6 亿字）；Ctrl+G 跳章列表的「2 万条」是**另一个**上限（只影响跳章列表取前 2 万条），两者不是同一条规则
- **书架目录的路径长度预算（2026-11-22 二轮 N3）**：Windows 未开长路径支持时全路径上限 **260 字符**，而书架目录由你自选（网络共享盘同样算）。换根保存时会按「书架目录 + 最长可能子路径（书文件夹 40 字 + `_trash` + 备份 / 快照目录 + 章节文件名 50 字 + 后缀余量 = 125 字符）」做一次预算：超过 260 就直接拒绝这次换根并给出中文说明（含上限与超出多少字符），**配置一个字都不写**，不会等到建书 / 写章 / 备份时才透出系统英文错误（`ENAMETOOLONG`）。已经设好的深目录不影响改字号之类**其它**设置（只有「书架目录真的变了」才校验）。想在深目录里用书架，可以把书库放到更靠上的目录，再用目录联接挂进来（见下一条）
- **默认拆章导入对「部 / 集 / 篇 + 无分隔符 + 直接接字」按正文处理（审计残留 #50/E15）**：为了不把「第一部电影…」「第三集播出后…」「第一篇论文…」误切成章，这类行不会当标题；代价是「第一部风起」这类无分隔符短标题会被并进上一章正文 —— 真标题请用空格 / 冒号分隔（「第一部 风起」「第一部：风起」），或把「第一部」单独写成一行
- **单章 128 MB 读取闸门的三条边界（1.5.1 H6 起，1.6.1 R3 补齐）**：① 编辑区打开超限章一律 `CHAPTER_TOO_LARGE`，不整份读进内存；② **书架扫描的字数回填**（含「从目录重建」后缺 `chars` 的章、老版本书目）先 `stat` 再读，超限章跳过、字数保持未缓存、书照常列出且**不标「书目损坏」**，下次扫描再试；③ **「还原到替换前」刷字数**只重算本次真正还原的章（不再整本重读），超限章同样跳过。三者共用 `MAX_CHAPTER_READ_BYTES = 134217728` 与同一套 `readSizeProblem` 文案；扫描的全局并发上限 **≤ 8**（外层 4 × 内层 2），1000 章的书不再 96 路同时读盘。④ **整本查找 / 替换 / 排版预览 / 整理**（1.6.1 R4 起）遇到超过 128 MB 的章**跳过并汇总**：超限章不读盘、不写盘，结果里多一个可选 `skippedTooLarge`（跳过章数），界面提示「有 N 章超过 128 MB，本次已跳过（文件没动）」，**不整批失败**；导出与校对仍按章读正文，碰到超限章会照旧明确报错（这两条路径本轮没动）。⑤ **2026-11-22 三审 P1 起，载入编辑区另有一道「单章 3,000 万字符」上限**（约 90 MB UTF-8 中文，与「能打开就能救稿」同口径：比保存上限 500 万字宽 6 倍）—— 128 MB 字节闸门拦不住字符数（纯 ASCII 的 128 MB 文件解码后是 1.28 亿字符，整份塞进 textarea 会把界面拖死），超过时报同一个 `CHAPTER_TOO_LARGE`、不载入。这条只管「进编辑区」：另存 / 复制正文的救稿出口与保存链不受它影响
- **打开 / 保存 / 导出大书的性能边界（2026-11-23 二次审查 B5 实修后）**：①**打开书**不再在窗口出现前逐章读盘回填字数——`book:open` 只汇总书目里已有的 `chars` 缓存，缺缓存的章由后台单飞补齐（同一本书只跑一趟，只补缓存、不改 `updatedAt`）；打开时仍会逐章 `stat` 找缺失的章节文件（界面的「N 个章节文件缺失」提示依赖它），这一趟在网络盘 / 机械盘上仍是每章一次 stat。②`书目.json.bak` 的轮换改成时间窗：结构性变更（增删章 / 改名 / 分卷 / 导入 / 还原）每次都轮换；普通保存（只改字数缓存 / 上次打开章节 / updatedAt）距上次轮换 ≥ **5 分钟**才轮换——短时间连按 Ctrl+S 不再每次重写这份备份，`.bak` 最多落后「一个 5 分钟窗口 + 一次保存」的结构性版本（章节正文另有 `_trash` 与可选每日快照兜底）。③书架卡片每本最多带前 **500** 个章节名（`chapterNamesTruncated` 标记是否还有更多）；再靠后的章名请进书用章节栏 / Ctrl+G 跳章，或搜正文（走索引），书架搜索摘要会写明「较大的书只按前 500 个章节名匹配」。④导出 / 救稿的「上次导出目录」探测改成**异步 + 2 秒有界等待**：目录在断开的网络盘 / 休眠 USB 上时按「不存在」处理并落回「文档」，保证保存对话框一定打得开；代价是真有目录但 2 秒内没应答时默认落点会退回文档（仍可手选）。⑤导出范围预览的字数**只用书目缓存**：缺缓存的章不在对话框出现前读正文，摘要标「另有 N 章字数待统计」，正式导出仍按确认后读全文。⑥`book:copy` 整本复制改成逐块拼装（读一章拼一块），但**最终整串仍必须整份给剪贴板**——极端大书（几十 MB）整本复制的内存峰值约为「一份拼装块 + 一份最终串」，同时受进程可用内存限制；特别大的书请用「导出 TXT」而不是整本复制。⑦搜索侧隐式校验有 **3 秒**独立超时：慢盘上首搜先显示「正在建索引」并在完成后自动重搜；全程的索引校验进度会实时转给界面。
- **IPC 参数上限（v0.9 C-5 审计结论）**：渲染层交给主进程「一次算完」的数据有硬上限——**正文 500 万字**、**查找词 / 替换词各 1 万字**、**替换结果约 2000 万字**（按「原文 + 命中 × 增长」估算，不先生成字符串）、**Ctrl+G 章节列表 2 万条**（超出只取前 2 万条）、编辑区未保存内容（override）同样 500 万字；超过时回固定错误码 + 中文提示（如「正文太长（5,000,001 字，最多 5,000,000 字）」）。这些值远高于正常写作（一章通常几千到几万字），碰到只可能是手误或注入脚本；被拒的调用**不写盘、不改书目、不留 `_trash`**。**单章正文超过 500 万字时**排版 / 查找 / 替换 / 校对 / 朗读都会提示太长；**`chapter:save` 同样受这条 500 万字上限约束**（2026-11-05 审计 E6 补齐；正常一章远到不了），编辑与复制不受影响。这类章仍可打开（载入上限见第 16 条），保存被拒时界面会给「另存这一章为 txt… / 复制正文」的救稿出口（2026-11-22 三审 P1 补齐），先把这一版落成文件再回源文件拆章；导入（写作者自己的整本文件）不是保存，但超过上限的单章导入会在写盘前明确拒绝（见第 14 条的 ③）。导出范围 / 覆盖内容沿用「坏形状降级」的旧口径（非对象 range 当全书、越界收紧到 1–总章数；override 形状不对当没传），只有非文本 / 超长正文会报错。另有一条边界：整本替换入口限制替换词 1 万字、单章命中上限 5000 处，极端输入下单章最多多出 5000 万字——正常换词 / 换句远到不了，且整本替换写前会先把原文备份到 `_trash`（1.4.0 起不再弹确认框，改为 10 秒撤销条）
- **对比度审计覆盖到扩展态后的边界（v0.9 A-4 起，v1.0 V-3 扩展）**：`node scripts/contrast.js` 现在覆盖 ① 书架 / 写作页默认态；② **六个弹层内部**（设置 / 导出范围 / 排版 / 查找 / 校对 / 历史）；③ **`:hover` / `:active`**（书卡、顶栏按钮、章节条目、下拉菜单、查找 / 校对 / 历史结果行；顶栏按钮、主按钮、菜单条目）。交互态由主进程用 CDP `CSS.forcePseudoState` 在**真实元素**上强制伪类（与真实指针 / 按键走同一套样式解析，不是往产品 DOM 里加测试类），采样前用 CSSOM 关掉颜色过渡、采完删除；**禁用态按 WCAG 1.4.3 豁免**（inactive controls 不适用对比度要求），只记录实测比值、不计失败。仍有的边界：①**表单描边**（`--line-strong`）在纸色上只有 1.5–1.9:1，低于 WCAG 1.4.11 要求的 3:1——有意保留纸感，输入框的边界同时靠白底 / 深色底与「点进去后的光标」提示，要提到 3:1 会让整个界面变成硬边框风格；②牛皮纸 / 网格纸的纹理（alpha ≤ .10）与正文编辑区的纹理**没有计入底色**（影响远小于 0.1 的比值）；③主题仍是作者手选（`editorPaper`），**没有**跟随系统深色自动切换（作者没要求，且会让「按书显示设置」的优先级变复杂）；④交互态覆盖的是**代表性元素**（书卡 / 按钮 / 章节 / 菜单 / 三种结果行），不是每一个可交互元素；⑤弹层内部覆盖上述六个，灵感箱 / 书籍信息 / 跳章 / 同步冲突等沿用同一套令牌与弹层通用外观，由 6 主题截图抽查。审计脚本只读、书库全在系统临时目录，跑一次会在临时目录留一套演练书库（可留可手动清）
- **弹层焦点管理只管「用户按 Tab」这条路，三条边界（v0.9 A-5）**：新增的 `renderer/dialog-focus.js` 让 13 个 `.backdrop` 弹层里的 11 个（设置 / 书籍信息 / 通用询问框 / 排版 / 查找替换 / 跳章 / 历史 / 灵感箱两条 / 校对 / 敏感词）做到「打开时把焦点带进来、Tab 与 Shift+Tab 在首尾绕回、关闭后把焦点还给打开前的元素」。①**不抢程序化焦点**：查找面板的「替换这一处」依赖编辑区真的拿到焦点（`document.execCommand('insertText')` 才生效），所以业务代码自己 focus 别处时焦点管理不插手——它只在用户按 Tab 时兜回弹层、关闭时焦点真丢到 `<body>` 才归还；②只管 `.backdrop` 弹层，顶栏下拉（「整理 ▾」/「显示 ▾」/「导出 ▾」）与右键菜单不是模态，不在这一层管——它们的键盘通道由 `renderer/menu-keyboard.js` 单独负责（v0.9 A-5c，见下一条）；③**没有**用 `inert` 屏蔽背景——背景点击本来就被弹层遮罩挡住，`inert` 会连带影响读屏与程序化点击，收益不值这个风险。另外「减少动效」只把过渡 / 动画时长压到 0.01ms（跟 Windows「在 Windows 中显示动画」的开关走，`prefers-reduced-motion`），**不改颜色 / 布局 / 功能**，也没有应用内开关。

- **本书历史只扫描书内 `_trash` 顶层目录 / 散文件和书文件夹根部的 `书目.json.bak`**，不递归子目录；`书目.json.bak` 只供预览，**不提供一键覆盖还原**（书目损坏请走书卡「修复」）；删除章节放回书文件夹后**不会自动加回章节列表**（需要时用「从目录重建」，注意重建会生成新的书目 id、丢掉状态/备注与按书显示设置）
- **每日快照不是自动保存**：只在 `Ctrl+S`（含建章前的自动保存）时留一份，且每章每天只留当天第一份（同一天再改再存不会刷新快照）；开快照**不会**让你少丢没保存的内容
- 每日快照只按**本机本地日期**分目录，跨时区/手动改系统时间会显示成另一天的目录；保留期只按目录名里的日期算，不读文件时间
- 快照目录的清理**只认名字严格等于 `快照-YYYYMMDD` 的目录**，并且只在这种目录里删；把别的备份改名成这个格式会被当成快照清理，请别这么做
- **「清空这天的快照」只移入 Windows 回收站**（不是硬删，可从回收站恢复），一次只清一个「快照-YYYYMMDD」目录；回收站不可用时只报错返回，一个文件都不动。没有「快照总览 / 一次清空全部快照」：想批量腾空间，可以逐天清空、到书内 `_trash` 按文件夹名手动删，或在设置里把保留天数改成 1 天（下次保存自动清旧目录）
- **每日字数只统计「保存动作」带来的正增量**：没按保存的编辑、切章、导出、整理（未写盘时）都不算；删字/替换变短**不会倒扣**当天进度。如果章节在应用外被别的程序改过，应用按书目里缓存的上次字数算增量，这一次的统计可能和你的手感略有出入
- 每日字数统计按**本机本地日期**归天（跨时区/手动改系统时间会记到另一天）；`stats.json` 只保留最近约 400 天，更早的日期在下次记录时清掉（不影响书库）。目标只有**全局一份**，写作页按书设置里不显示目标/柱状图/日历
- **码字日历只读最近约 400 天**的统计：更早的日期在下次保存时被清掉，日历翻到更早的月份会是空格子；连续写作天数也只看这段窗口。日历按**周一开头**，翻月不记录「上次看到哪个月」（重开设置回到本月）。「连续 N 天」按当天有没有正字数算：今天还没写时连续天数先保留（从昨天往前数），到第二天仍没写才会断；只在本机时区算，手动改系统时间可能让连续天数看起来不对
- **写作时长默认关**，只有你自己点「写作计时」才累计：忘了点开始 / 忘了暂停，数字就不准（它是手动秒表，按实际经过时间算，不做「检测到打字才计时」）。计时中最小化 / 窗口被挡、或者离开电脑却没暂停，这段时间也会算进去——离开前记得点一下暂停（回书架 / 换书 / 关窗会自动停表）。时长按本机本地日期归天，跨午夜的那一轮可能把不到 30 秒算到次日；单日上限 24 小时（坏数据也夹住）
- 写作时长只按天合计，**不按书 / 不按章节分开**，也不和字数目标联动；「连续写作天数」仍按「当天有保存的新字数」算，只计时不存字的日子不算连续。计时只在你点暂停 / 按保存 / 每 30 秒 / 回书架 / 关窗时把整秒写进 `stats.json`（每 30 秒一次是为了少写盘），应用被强杀最多丢不到 30 秒；上报失败只影响统计数字，不影响写正文
- 自定义字体只记路径、不复制字体文件：换电脑、挪走/删掉字体文件后会自动退回宋体；字体文件只由主进程按「刚在对话框里选的 / 当前书的显示设置 / 全局设置」这三种路径读取，**渲染层不能指定任意路径**（v0.8.6 R4，代码审计 F1）
- 查找是**字面量**查找，不支持正则/通配符（`.*` 只是三个字符）
- 书架搜索的**正文部分**是**字面量、不区分大小写**：不做正则 / 通配符 / 繁简转换 / 同音字 / 拼音；正文至少 **2 个字**才搜（一个字不搜）。结果按「书 + 章」分组，组头显示本章真命中数（单章计数上限 10000，超过显示 `N+`）；默认每章最多列 3 处，「展开本章全部」只读目标那一章、单章最多返回 200 条（更多时明确提示只列出前 N 处），一次整搜最多 40 条；常见两字词可能命中很多书，这时只查**最近修改的 60 本**并标「只查了最近的一部分书」，单次搜索约 1.8 秒预算（超出先返回已有结果；展开一章同样受时间预算保护，但不受整次 40 条限制）。书名 / 章名过滤仍然是输入即出的内存过滤。**结果里的章号按全书顺序显示**——书架不读每本书的编号设置，所以按卷编号的书在这里显示的是全书第几章，与写作页目录里的卷内号不同（本版只写清这个已知差异，不改显示语义）
- 正文索引是**每本书一份双字 Bloom 位图 + 每章 mtime/size 指纹**（存在 `%APPDATA%\chapter-writer\search-index.json`，280 本约 20MB），只用来「筛掉肯定没命中的书、再读真实 txt 核对」：位图有误报、**不会漏报**。索引里**没有正文句子**，所以不能当全文预览或离线备份用；索引里会存书名 / 章名 / 章节文件名 / mtime/size（分享索引文件前留意一下书名章名）。索引总量有 **32 MB** 预算（审计修复 #33）：超过时按书目最后修改时间从旧到新丢掉整本书的位图（**章节指纹保留**，不是把书从索引里删掉），被丢掉位图的书以后每次搜索都逐章核对——**只慢一点，结果不会少**；正文变过 / 换书架根时位图会重新建；预算是**尽力而为**：若超限时所有书都已没有可丢的位图（只剩章节指纹），索引仍照常写出（不为了凑预算删指纹），读侧另有 64 MB 兜底、超限按空索引重建；每章指纹是 mtime/size + 首尾各 4 KB 内容采样，只改文件中段且保留大小 / 修改时间的改写不会被指纹发现（要等大小 / mtime 变化或重建索引，审计残留 #R20）
- **首次打开书架会在后台建索引**（280 本 / 3256 章约几十秒），界面上有「正在为书架建正文索引 N/M 本」；建好前书名 / 章名搜索照常可用，正文结果建好后自动补上，**不需要作者手动点任何东西**
- 索引校验分两档：**回书架 / 启动时**逐章 stat 校验（约 10 秒节流，用来发现外部改过的 txt），**每次搜索**只做轻量的书目校验（约几十毫秒，不拖慢输入），距上次逐章校验超过 1 分钟时顺带做一次兜底。在别的编辑器里改过 txt：回一次书架或等约一分钟再搜就能看到；应用里按 `Ctrl+S` 保存会**立即**标记这本书重建索引。改章名 / 删章 / 删书同样由下一次校验发现。索引文件损坏、版本不对或书架目录换了会自动重建；删掉 `search-index.json` 只会让下次多扫一遍
- 搜索结果点一条只是**打开那一章并选中命中位置**（只移动光标 / 选区 + 滚动，不改正文、不会替你保存；当前章有未保存修改时照常询问）。「展开本章全部」也只在主进程读目标那一章、把命中片段交给界面，界面不读整章正文、不写盘。搜索全程只读：不写 `书目.json`、不改章节 txt、不生成 `_trash`
- 搜索时章节 txt 被别的程序占用 / 刚好被删掉，这一章会跳过（结果可能少几条），不会让整次搜索失败；索引写不进去（磁盘满 / 没权限）只影响下次重建，不挡保存和搜索
- 拖拽排序本身仍是「按住一章上下拖」（一次只拖一章）；要一次移动多章请用多选批量条的「移卷」（多选目前只在**章节列表**里，书架书卡还没有多选 / 批量动作）
- 多窗口同时编辑两本书已支持（书卡右键「在新窗口打开」），但仍是**同一个应用进程里的两个普通窗口**，不是标签页：没有「窗口分组 / 合并窗口 / 窗口间拖拽」，关掉窗口后也不能从应用内恢复「上次开了哪些窗口」（每次启动只开一个窗口）。**同一本书禁止同时开两个窗口**（会互相覆盖未保存内容），再点只聚焦已有窗口
- 跨窗口保护是**按「打开中的书」登记**做的：别的窗口正开着的书，不能从当前窗口**删除 / 改书名 / 改章名 / 删章 / 整理 / 整本替换 / 导入覆盖**，会提示「请先关掉另一个窗口，或先切换到那个窗口」。如果你在应用外（资源管理器 / 同步盘）把书文件夹或章节 txt 删了 / 改名了，另一个窗口再按保存会**报错阻止写盘**，不会偷偷 mkdir 重建一个「影子 txt」或影子书文件夹；这时请回书架刷新，或把文件放回原位
- 多窗口**共用同一份全局配置**：书架 →「设置」里改全局显示设置后，已经开着的其它窗口不会实时换装（重新打开书 / 重启后生效）；按书的显示设置（`bookDisplay`）、章节栏宽度仍只影响对应书。窗口的未保存状态彼此独立，A 窗口的「保存 / 不保存」不会动 B 窗口的编辑区
- **书籍信息（作者 / 简介 / 分组 / 标签）是纯文本的可选字段**：作者 ≤ 80 字、分组 ≤ 40 字、简介 ≤ 1000 字（多行会保留换行、合并多余空行）、标签最多 10 个、每个 ≤ 20 字（逗号 / 顿号 / 分号分隔，重复的自动去掉），超长会被截断；分组是**精确匹配**的一个名字，不做二级分组 / 分组重命名 / 批量改分组，也不会按分组移动或重命名书文件夹。分组筛选只记在**本次运行**里（重开应用回到「全部分组」），且只影响书架显示；书架搜索按作者 / 分组 / 标签是**字面量、不区分大小写**，不做拼音 / 同音字
- 书籍信息只在书架右键「书籍信息…」**显式保存**时写盘（原子写，只改 `书目.json` 和上一版 `.bak`），不会因为打开书 / 保存正文而自动补字段；书目损坏的书要先走「修复」才能改书籍信息。别的窗口正开着这本书时，当前窗口保存书籍信息会被拒绝并提示（和删除 / 改名一样的跨窗口保护）。书卡简介最多显示两行，鼠标悬停可看全文
- 书架自动刷新只发生在**正停在书架的窗口**：写作页里的窗口不打断你（避免一边写一边看到书架跳动），回书架时会自动刷新；别的窗口改了同一本书的情况已经被「同一本书不开两个窗口」挡住
- 「上次窗口位置 / 大小」只有**一份**（最近使用的窗口），第二窗口的位置不会单独记住；关机 / 注销时的未保存拦截是**每个窗口各问一次**的尽力而为（Windows 不强等应用，可能来不及）
- 章节状态只有**草稿 / 待修 / 完稿**三档（不做自定义状态、不按状态筛选/排序）；备注是一条 ≤200 字的一句话，不做多行便签、不进正文、也不参与搜索
- 复制本章（平台格式）**只复制正文、不含章名**，排版固定按「段首缩进两格 + 空一行（含缩进）」，不跟随「排版设置…」对话框里记住的规则（不改标点 / 引号 / 文字）；空章不覆盖剪贴板
- 范围导出（全书 / 按卷 / 第 X–Y 章）**TXT / EPUB / DOCX 都支持**，但「复制整本到剪贴板」始终是整本。按卷导出只列书里已有的卷（没分卷的书不显示这一项）；第 X–Y 章按**全书连续章号**算（按卷编号的书也一样：范围输入填的是全书第几章，不是写作页的卷内号；导出文件里的章标题才按卷内号），导入的原文标题章节也按序号排，不按标题里的数字。一次只能选一种范围（全书 / 某一卷 / 章节区间），不能「未分卷 + 某卷」拼着导
- **导出 / 复制里的「当前章未保存内容」（override）按章节 id 认章**：编辑区那一章还在书目里时，用它现取的内容替掉磁盘正文（返回 `includedUnsaved: true`）；如果那一章刚被删除、或编辑区已经换了书（传给主进程的 chapterId 在书目里找不到），TXT / EPUB / DOCX 导出与「复制整本」**不报错，直接按磁盘内容导出**（`includedUnsaved: false`；也不会拼进同名 / 同文件名的别的章）。只有单章动作「复制本章（平台格式）」找不到这一章时明确报「找不到这一章（可能刚被删除）」——它本来就是「复制这一章」，章不在就不能拿别的章冒充
- EPUB 按卷 / 按范围导出**只打选中的章节**：卷名页只生成选中章所在的卷，封面章数 = 本次导出的章数，按卷 / 按范围的副本使用**独立的 identifier**（阅读器不会把它当成整本书的另一个版本）；章标题按这本书的编号方式（默认全书连续；按卷编号时卷内从第 1 章起）。本书没有封面图，固定生成一页纯文字封面；不含插图、脚注等富内容，也**不跟随**「排版」对话框里记住的规则（固定「段首缩进 2 字 + 段间空一行」）。正文里的空行会合并成段间留白（不再单独输出空段落），所以习惯用空行分段的书，导出后段距是统一的
- **DOCX 导出是固定版式**：标题页（书名 / 作者 / 范围与章数）+ 卷标题 + 章标题 + 正文，正文段首缩进 2 字、1.5 倍行距、宋体；**不跟随**「排版」对话框里记住的规则，不含页码 / 页眉 / 目录域 / 封面图；正文里的空行会合并成段间留白，一章不拆文件，章标题按这本书的编号方式（默认全书连续；按卷编号时卷内从第 1 章起）。按卷 / 按范围只写选中的章（卷标题只生成选中章所在的卷）。导出全程只读；当前章未保存内容参与但不写盘；简繁转换只作用于副本（书名 / 作者 / 卷名 / 章名 / 正文一起转）
- 「继续上次写作」只记**最近一本书**（不提供历史列表 / 最近打开的书单）；入口显示的是记录时的章号，若之后在别处删过章，点进去仍以书内 `lastOpenChapterId` 为准（失效时回退第 1 章）。上次那本书被删掉或移出书架后入口自动隐藏，不会提示「书不见了」
- Ctrl+G 跳章只在写作页生效，只匹配**当前这本书**的章节名（不做拼音/模糊纠错，不搜正文、不搜卷名）；输入纯数字按全书连续章号算，超出范围只提示不跳转；跳章本身不写正文，但切章会更新书目里的「上次打开章节」
- 同步冲突副本只检测**书文件夹顶层**的 `*conflicted*` / `*冲突副本*` 文件：不扫描子目录、不处理「整个书文件夹被同步盘复制成另一个文件夹」的情况，也**不提供自动合并**（冲突内容可能都没合并过，自动处理风险太大）。提示只针对当前书卡，处理完手动移走副本、回书架刷新即可
- 校对**只报告、不改动**，没有「一键修正」：半角标点要改请回到写作页点「整理」（或选择卡「排版设置…」里先看预览）；其它八条内置规则目前都只能在正文里自己改。阈值固定（超长段落 500 字、重复用词 300 字内 3 次、连续标点 3 个），**没有阈值设置项**；1.5.0 起每条规则可以在校对面板里临时关掉（只对本次会话有效，不写配置）。重复用词按「双字词 + 不重叠命中」算，相邻二字词（如「突然想起」）会归并成一条，常用词多出现几次也会列为疑似，不是判定错误
- 单章校对明细最多保留 400 条、面板一次最多显示 300 条（总数 / 各规则条数照实统计，可切成当前章分开看）；整本明细上限 1500 条，超出时提示「明细只列出一部分」。整本只读磁盘（当前章未保存内容按编辑区算），章节文件缺失的章会跳过
- 敏感词预检**只报告、不改动**，没有「一键替换成星号」；词表完全由你自己维护，应用不内置、不下载任何词表，也不判断「该不该屏蔽」。词表文件本身只读，应用不复制、不改写
- 敏感词匹配是**字面量、区分大小写**（不做正则、不做大小写折叠、不处理同音字 / 拆字 / 拼音）；同一处有多个词重叠时只报最长的那个。词表每行一个词，空行忽略、重复的词只算一次，一行超过 100 字视为误粘的正文跳过
- 词表上限 **4MB / 5000 个词**（超出部分不读，设置里会提示）；单章明细最多 500 条、整本明细上限 1500 条，面板一次最多显示 300 条，总数照实统计。整本只读磁盘（当前章未保存内容按编辑区算），缺文件的章跳过并提示
- 词表文件被移走 / 编码不是 UTF-8 / UTF-16 / GBK / 是空文件时，预检只给出明确提示，**不会退回「内置词表」**（应用根本没有内置词表）；删掉配置里的 `sensitiveWordsPath` 只会忘掉路径，不会动你的词表文件
- 校对词表是**可选**的，只参与「校对」面板（不影响敏感词预检），和敏感词表是两份独立文件；不设置时校对照常跑内置九条规则
- 校对词表每行一个词，可写「错词 → 建议」（箭头 `=>` / `->` / `→` 都认），`#` 开头是注释；空行和重复的词忽略，一行超过 100 字跳过，最多 4MB / 5000 个词
- 校对词表只做**字面量、区分大小写**匹配（不做正则 / 同音字 / 拼音 / 繁简转换），同一处多个词重叠时只报最长的那个；「建议」只显示在结果里，**不会自动改字**，也不写词表文件
- 校对词表文件被移走 / 编码不对 / 是空文件时，面板只在词表状态行提示，**内置九条规则照常跑**；删掉配置里的 `proofreadWordsPath` 只会忘掉路径，不会动词表文件
- **简繁转换默认「不转换」**，只在「设置 → 导出」里主动选「简体 → 繁体 / 繁体 → 简体」才生效，而且**只作用于导出副本**（导出 TXT / EPUB / DOCX）：书库里的章节 txt、`书目.json`、复制整本 / 复制本章、阅读 / 校对 / 朗读 / 统计全部**不转换**，原稿一个字节不动。它是导出动作的一部分，不写盘就不会影响书库
- 简繁转换用的是**内置常用字表**（简→繁约 900 字、繁→简约 1000 字）+ 常见歧义词纠正（发 / 髮、干 / 乾 / 幹、后 / 後、里 / 裡、面 / 麵、只 / 隻、系 / 係 / 繫、台 / 臺 / 颱、周 / 週、松 / 鬆、余 / 餘、谷 / 穀、舍 / 捨、志 / 誌、制 / 製、表 / 錶、历 / 曆、复 / 複 / 覆、钟 / 鐘 / 鍾、须 / 鬚、脏 / 髒 / 臟、赞 / 贊 / 讚……），**不联网、不装依赖、不读参考软件的数据**
- 转换**不做分词 / 专名 / 地名 / 人名表**：一简对多繁只取常用写法，常见例外由短语表纠正（头发 → 頭髮、干净 → 乾淨、皇后 → 皇后、乾隆 → 乾隆）；**歧义字宁可保持原样也不硬转**（只 / 系 / 面 / 余 / 谷 / 舍 / 志 / 制 / 表 / 松 / 向 / 周 / 采 / 游 / 折 / 征 / 致 / 占 / 注 / 卷 / 刮 / 胡 / 回 / 家 / 克 / 困 / 累 / 蒙 / 佣 / 秋 / 姜 / 郁 / 丑 单独出现时不转，常用词走短语表）。繁→简里「著」也只在常见动词短语里改成「着」（著作 / 著名 / 显著 / 乾隆 保持原样），所以导出后**请通读校对一遍**，不要直接上架
- 简繁转换**只换字形、不改长度**（逐字或等长词替换）：BOM、CRLF、标点、数字、英文、表情、空行、章节标题行结构都不动，所以字数统计不受影响；TXT / EPUB / DOCX 的**默认文件名仍用原书名**（不转），EPUB 与 DOCX 里的书名 / 作者 / 目录 / 章名 / 正文会一起转。没有「只转选中文字」「简繁字体切换」「按书设置」——它是**全局一份**设置，写作页的按书设置里不显示
- **导出范围对话框里的字数预览优先用书目里保存时算好的字数缓存**（每章 `chars`）：如果章节 txt 在应用外被别的程序改过、而这本书还没重新打开 / 刷新书目，预览字数可能暂时和磁盘正文略有出入（正式导出仍逐章读全文，文件名 / 章数 / 正文内容不受影响，重新打开书或回书架刷新后就一致）。当前章有未保存内容时，这一章按编辑区实时算，不用缓存
- 灵感箱的碎片是**所有书共用**的（放在书架根目录 `_碎片`，不按书分文件夹），只扫描 `_碎片` **顶层**的 `.txt`，不递归子目录，也没有标签 / 搜索 / 分组 / 批量整理
- **不提供「用后删除」**：插入碎片只改编辑区，原碎片永远保留；要清理请自己到书架根目录的 `_碎片` 里处理（删除请走回收站，应用内不会真删）
- 单条碎片写入上限 **10 万字**；从磁盘读取上限 **4MB / 20 万字**（超过会明确提示先拆分，不会把超长内容硬塞进编辑区）。列表一次最多显示 300 条，总数照实显示
- 碎片文件名按**本机日期** + 当天最大序号 + 1；删掉的号不回收（避免和回收站里的旧文件撞名）。你自己放进 `_碎片` 的 txt 也会列出来，只是没有日期 / 序号标识
- 插入位置固定为**打开「插入碎片…」面板前**的光标 / 选区；碎片不会自动加换行或空行，和上下文怎么衔接由你自己决定
- 朗读用的是**系统本地语音**（Windows SAPI，Electron 内置 speechSynthesis），不联网、不下载、不打包语音包；语音下拉里有什么取决于系统里装了什么，声音 / 音色由 Windows 决定（可在「设置 → 时间和语言 → 语音」里装更多）
- 朗读**只读正文**：不导出音频、不做字幕 / 逐字高亮 / 背景音乐 / 定时停止；「跟随高亮」只改编辑区选区（不改字），而且编辑区没有焦点时看不到高亮
- 语速（0.8×–2.0×）和语音选择**只在本次朗读小条打开期间有效**，不写配置；重新打开回到 1.0× + 系统默认
- 切分按**自然段**：一段超过 160 字按句末标点拆成几段再念；系统语音自己的断句 / 停顿由语音引擎决定，应用只保证不把字念漏
- 单章最多切 **5000 段**、正文超过 **100 万字**只念前面的部分（正常一章远小于这个数）；朗读中途改字 / 切章 / 回书架 / 收起小条会立刻停止，需要重新打开
- 「显示不可见字符 / 超长段落提示」两个开关**也按书记忆**（`config.json` 的 `bookDisplay`，没单独设置过的书默认关），重启 / 换书都还在；**「当前段落高亮」的开关和颜色按书记忆**（`config.json` 的 `bookDisplay`，没单独设置过的书用全局默认），重启 / 换书都还在。**超长段落阈值**同样按书：全局默认 500，写作页设置里改只影响当前这本书（`bookDisplay[本书].longParagraphThreshold`），书架设置里改全局默认（`longParagraphThreshold`）；没单独设置过的书回落全局默认。这些都只改显示层，只写 `config.json`，不碰正文 / 书目 / 章节文件
- 「当前段落高亮」按「**一个非空行 = 一段**」算（和朗读、`Alt+↑↓` 段落导航同一口径）：光标停在空行时不高亮；整段折成好几行时按行分别铺底；正文超过 **30 万字**（按去空白字数；原文超过 60 万字符也按超长处理，防空白灌水）时整层标记收起（不可见字符 / 超长段落 / 当前段落高亮都不画，只提示一次；`renderer/editor-logic.js` 的 `marksTooLarge` 门控），正文照常编辑 / 保存。默认「跟随主题」时高亮色 / 光标颜色跟着 6 套背景主题走；自定义颜色只认 `#rgb` / `#rrggbb`（色板 6 色 + 取色器），写坏了自动回落主题色。自定义色是**整章统一**的淡色底，不会按主题再调深浅；颜色 / 开关只作用于写作页，阅读模式没有当前段落高亮
- 「不可见字符」只标**全角空格（U+3000）**和**行尾空白**（空格 / 制表符 / 全角空格）：不标行内半角空格、换行符、零宽字符等其它不可见内容；纯空白行不标（避免整行泛色）；一次最多画 4000 个标记，正文超过 **30 万字**（按去空白字数）或原文超过 60 万字符时整层标记都不画（不可见字符 / 超长段落 / 当前段落高亮一起收起，只提示一次；30 万字以内三样照常）
- 超长段落阈值默认 **500 字**（按去掉空白后的字数，和「本章字数」同口径），可在「设置 → 正文显示设置 → 超长段落阈值」里改成 **50–20000**：写作页里改只影响这本书，书架设置里改全局默认；输入越界会夹到边界，留空 / 非数字保存时回落 500。黄线画在正文左边距里，左右边距调得很小时会贴着正文左缘
- 标记层是**画在正文上面**的一层只读影子层（不是富文本）：极少数情况下会和选区高亮叠在一起（字仍然看得清），它不参与编辑、不被复制、不会进导出，也不改 `书目.json` / txt
- **查找高亮本身仍是一次性的**：不点「存成书签」的话，它只服务当前这一次查找——改正文、改查找词 / 大小写 / 范围、切章、回书架或离开写作页就自动结束，不记历史、不写配置；关掉面板后 `F3` / `Shift+F3` 继续跳，`Esc` 清除。想保留就用面板里的「存成书签」（见下面一条）。整本查找只列章节清单，**点进某一章后**才高亮那一章，不会一次把整本书的命中都画出来
- **查找书签是「查询条件」不是「位置」**：按「书 + 章」只记查询词与大小写选项（最多 200 条；同一章再存 = 更新那一条），**不存正文、不记命中位置 / 上下文**；打开这一章时按**当前正文**重新扫描定位，所以正文改过、命中位置移动了也跟着走，改到没有命中就暂时不亮（书签还在，改回来或删掉即可）。书签存在 `%APPDATA%\chapter-writer\config.json`（和书库分开，删书 / 换书架不会跟着书走）；删除书签只删配置里这条记录，**不删章节、不动正文**；书签只在写作页生效，阅读模式没有
- 单章命中超过 **500 处**时正文里只画**当前附近的一屏**（500 处），导航仍对全部命中有效；单章命中上限 **5000 处**，到上限还多找出一处时会明确提示「命中太多」。当前命中同时是编辑区的系统选区（方便直接替换），所以会和蓝 / 灰的选中底色叠在一起；高亮层不参与选择、复制、导出，也不会写盘
- 章节列表的字数来自 `书目.json` 的缓存（打开书时补齐、保存后更新）：在应用外改过 txt 不会立刻变，回书架刷新 / 下次保存后才更新；「比上章短」只在上一章 **≥500 字**时提示，只是软提醒，不判断你是不是故意写短
- **专注模式只改应用自己的界面**：隐藏的是左栏、分隔条和顶栏，按 `F11` **不会**让 Windows 窗口全屏 / 最大化（窗口大小、标题栏都不变）；它只在写作页有效，书架页按 F11 不响应
- 专注模式的开关（专注 / 打字机）**只记在内存里**：回书架、切到别处或重启应用都回到普通布局；不会写进 `config.json`，也不按书记忆
- 「打字机」在**正文超过 30 万字**时暂停自动对齐（每次按键都去量光标位置开销太大），正文编辑 / 保存照常；正常一章远小于这个数
- 打字机对齐按**光标所在行**算（长段落自动换行后，光标在段中间就按那一行对齐），到章首 / 章尾会停在 0 / 最底部，不会滚出正文；它只调滚动，不移动光标、不改字
- 专注模式下顶栏按钮不可见，但快捷键照常可用（`Ctrl+S` / `Ctrl+F` / `Ctrl+G` / `Ctrl+N` / `Ctrl+Shift+C` / `Alt+↑↓`）；`Esc` 会**先**关弹层、停朗读（如果开着），**再**退出专注模式
- **阅读模式是只读视图**：里面没有编辑框 / 保存按钮，不能改字、新建章节或保存；顶栏的字号、行距只记在**本次运行**里，而且**按书各记一份**（换一本书回到默认档，回到这本书还是刚才的档位；重启应用都回到「大 / 标准」），不写 `config.json`，也不影响写作页的正文显示设置。阅读位置**只在本次运行内记一份**（按书分：退出阅读再进、换本书再回来，回到上次读到的那一章和章内位置；在编辑器里明确换了章则以编辑器当前章为起点），同样不写 `config.json` / 不改 `书目.json`，重启应用回到默认（从当前写作章开始）——所以它**不是书签 / 断点**，想从头读点「从头」
- 阅读模式**按章节连续滚动**：滚到接近底部自动接下一章，一次最多接 8 章（很多空章时避免一口气扫全书）；同时最多保留 40 章在页面上，再多只从最前面回收显示（不写盘、不影响书）。目录一次列出全书章节（**有分卷的书按卷分段**，卷名就是左侧章节栏里的那个卷名；单卷 / 没有分卷的书仍是平铺一串，外观与以前一样），特别大的书打开阅读时目录会稍慢
- 阅读模式显示的是**磁盘上的正文**：当前章如果还有未保存修改，阅读视图不会显示这些修改（顶栏会明确提示），退出阅读后它们仍在编辑区、照常可以保存。阅读不计入码字日历 / 写作时长（进入阅读会自动停掉写作计时）
- 阅读时章节文件被外部删掉 / 挪走，这一章会显示「读取失败」提示，**不会重建 txt、不会改书目**；把文件放回原位再重新进入阅读即可。阅读模式不检测外部修改（不会弹「外部修改」对话框）
- **章节模板是全局一份、只作用于新建 / 插入章节**：不做按书不同模板，也不会给已有章节补模板；模板上限 **2000 字**（超长截断），只有空白的模板视为没设置。套用后只是编辑区里的未保存内容，**不自动写盘**——按 `Ctrl+S` 才会进章节 txt，按 `Ctrl+Z` 可退回空章；如果模板展开后是空串（例如只写了 `{title}` 但章名为空），则不会套用
- 模板占位符只有 **`{n}`（章号，阿拉伯数字）/ `{title}`（章名）/ `{date}`（本机本地日期 YYYY-MM-DD）**，大小写敏感，别的花括号原样保留（不做 `{{` 转义、不做条件 / 循环 / 日期格式自定义）。`{n}` 没有章号上下文时也会原样保留，不会悄悄替换成空
- 章节模板**不跟随按书设置**：写作页「正文显示设置」里的设置只影响当前这本书，模板统一在**书架 →「设置 → 新建章节」**里改（写作页的设置弹层里不显示模板项）。设置了模板时导出 TXT / EPUB / DOCX 仍会自己加章节标题，模板里再写「第{n}章：」导出后会出现两遍，按需使用
- 错误日志**没有内置查看器 / 一键上传 / 一键清空**：设置里只有「打开日志文件夹」，要清空请自己删 `logs` 里的文件（应用下次出错会重新建）。日志目录就是 `%APPDATA%\chapter-writer\logs\`，删日志不会动书库和设置
- 日志按**本机日期**分文件（跨时区 / 手动改系统时间会记到另一天的文件）；单份超过 **256KB** 换下一个序号，最多保留 **12 份**，超出时删最旧的。只删名字严格是 `chapter-writer-YYYY-MM-DD[.N].log` 的文件，日志目录里其它文件一律不碰
- 日志只覆盖**主进程错误**：保存失败 / 主进程未捕获异常 / 未处理的 Promise / IPC 出错 / 渲染进程崩溃 / 窗口无响应。渲染层普通 JS 报错（DevTools 控制台里那种）不会自动进日志；`Ctrl+Shift+I` 的开发者工具报错也照常只在控制台
- 日志虽然只记元数据、还会把连续 24 个以上汉字当正文隐去，但**文件路径 / 章节文件名 / 书名**会出现在日志里（其中可能有你的书名、章名）。把日志发给别人排查前请自己先看一眼；日志里没有正文句子，但路径隐私要你自己判断
- 主进程未捕获异常时应用**不会退出**（先让你 `Ctrl+S` 保存再重启），界面只弹一句固定提示；这属于尽力兜底，如果异常反复出现，建议保存后重启应用，别在异常状态下继续写
- **检查更新只在手动点「检查更新」时联网**：启动、写作、切章、保存都不会自动访问网络，也没有「启动时静默检查」开关。检查失败不会重试、不会后台轮询，想再试就再点一次
- 更新检查走的是 GitHub 的 **Release 接口**：未登录时每小时最多 60 次（正常手点远不到）；被限流 / 被代理拦截 / 没网时只提示，不影响写作。GitHub 的「latest」接口通常只返回正式版，但如果仓库只有预发布版本，可能会拿预发布版来比较（会如实显示版本号，是否升级由你决定）
- 「打开下载页」只是用**系统默认浏览器**打开本仓库的 GitHub Release 页：应用**不下载安装包、不校验 SHA256 / 数字签名、不自动安装**，下载哪个文件、装不装、什么时候装都由你自己决定；下载页链接只接受 `https://github.com/ANAN1124-OSS/chapterly/releases...`，Release 数据里的其它链接会被丢弃
- 检查更新**不写配置、不写书库、不上传任何内容**：只发一次 GET 请求拿版本号（请求头只有 User-Agent / Accept），不发送书名、章节或正文；检查结果只记在内存里，关掉设置或重启就没了
- `书目.json` 的 `schemaVersion` 目前是 1，迁移函数是空的（为将来加字段留口子）；旧版应用读新版本书目时只会保留版本号、按已知字段尽力读，不保证能理解将来版本新增的字段
- 「Windows 关机拦截」是尽力而为：系统关机不强等应用，可能来不及弹提示
- **原子写会重试 3 次（间隔 80ms）后就报错**：正常写作里碰不到（同一个文件本来就被串行化：书锁 + 同一本书只开一个窗口 + 一次只保存一章），只有杀掉软 / 同步盘 / 备份软件长时间霸占目标文件时才会走到「保存失败」——这时磁盘上仍是完整的上一个版本，等占用结束后再 `Ctrl+S` 即可。极端情况下（同一路径十余路并发写同一个文件）重试会被争用耗尽，同样只报错、不写半截；这一条由 `tests/atomic.test.js` 钉住
- **每次保存都会重建章节文件（原子写）**：临时文件 → rename 覆盖目标，所以 Windows 上文件的**创建时间会被重置**，文件上的**自定义 ACL / 备用数据流（ADS）不保留**（权限通常继承父目录，书库放在自己的目录时感觉不到；书库放在共享 / 受控目录，或用「按创建时间归档」的备份工具时才可能注意到）。磁盘上永远不出现半截文件比保住这些元数据重要，这是有意取舍（审计 V304）
- **导出中断会在导出目录留下隐藏临时文件（2026-11-22 三审 F1 起自动回收）**：导出走「写临时文件 → 成功才 rename」，所以崩溃 / 断电 / 强退可能在**你选择导出到的那个目录**留下一个 `.书名.epub.tmp-pid-时间-随机` 隐藏半成品（几十 KB～几十 MB）。应用会自己收拾：启动时与**下次成功导出后**，对「最近导出过的目录（最多记 10 个）+ 当前导出目录」逐个按同一口径回收（只删本应用命名、不是本进程、且超过 1 小时的临时文件；目录不在 / 无权限都只跳过）。以前只扫「当前导出目录」，换过导出目录后旧目录里的孤儿没人回收——这条修复了。想立刻清干净，把导出目录设回那个目录再导出一次即可；也可以按 `.名.tmp-<pid>-<时间>-<随机>` 的形状手动删
- **剪贴板捕获的边界（2026-11-07 单列表改造 + 漏记修复后）**：只取**纯文本**（剪贴板里的图片 / 富文本格式不会带进来）；面板一条复制记录只新建一章，不做批量拆章 / 自动分卷（要整本拆章请走「导入小说」）；单章正文上限 30 万字（按去空白字数，与界面「N 字」/ 队列同一口径），标题行（≤40 字）后正文 ≥50 字才把首行认成标题；整条不足 100 字时整条当章名（这种短标题允许超过 40 字，文件名仍按 40 字截断）；**记录口径：后台监听开着时，每次复制（非空白）都记一条，20 字门槛只控制「要不要弹轻提示」**；**点「正文」插入成功后该条也立即从队列删除**（2026-11-08 起与「章节」一致，失败保留）；轮询间隔 300ms，打开面板前会主动补读一次；全局快捷键 `Ctrl+Alt+V` 被其它程序占用时注册失败只写日志、不挡启动，界面上的「捕获」按钮照常可用；**队列只驻本次运行内存**（最多 50 条 / 单条 30 万字按字数 / 总量 300 万字按原文长度，超了淘汰最旧；每条最多保留 30 分钟，超时的记录在你下次打开面板 / 复制时顺手清掉，不额外起定时器），**不落盘、不写日志、不做磁盘历史**，关闭监听或退出应用即清空；记录只对打开捕获面板的那扇窗口可见可读（后台监听记下的无主记录也只在面板打开时认领，且认领只给复制发生所在的窗口）——别的窗口按 id 猜也读不走正文；单条超上限（字数 > 30 万）会给一条明示提示，不再静默丢弃；捕获面板「正文」插入 > 2 万字时走整串赋值（快通道），代价是会清空浏览器撤销栈——可用提示条「撤销」或正文上第一下 `Ctrl+Z` 退回插入前；默认**不做后台全量记录**（剪贴板里可能有密码 / 验证码，后台监听必须由你在设置里主动打开）；**一次性「读剪贴板」凭证是提高门槛、不是强隔离**（#1）：`capture:flush` 对任何调用方都会给本窗口签一张 60 秒凭证，同源注入脚本仍可用「flush → clipboard」两步读到剪贴板；真正要挡注入，需要主进程维护捕获面板的 UI 状态并在 flush 时校验——工作量中等，本版只做注释与本条文档的口径降级，不宣称「渲染层读不到剪贴板」
