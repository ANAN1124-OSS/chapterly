# 章回 / Chapterly v2.2.0

**给写中文小说的 Windows 桌面写作工具**：纯文本、整本一键保存、绝不丢稿。
一本书就是一个文件夹，正文是记事本能直接打开的 `.txt`——没有数据库、没有私有格式、不依赖云。

![书架](docs/images/shelf.png)

> 下载：`chapterly-2.2.0-win-x64-setup.exe`（[v2.2.0](https://github.com/ANAN1124-OSS/chapterly/releases/tag/v2.2.0)，已于 2026-11-25 发布）
> 平台：Windows 10 1809+ / Windows 11 · 安装版不需要 Node · 许可：Apache-2.0 · 当前 v2.2.0

## 这是什么

- **写作工具，不是编辑器插件**：书架 → 一本书 → 若干章，章号自动生成（「第12章：」你只填名字），整本结构存在书内的 `书目.json`。
- **纯文本优先**：每一章都是独立的 UTF-8 `txt`，你可以用记事本、VS Code、git、同步盘直接看和备份；删掉章回也不会把稿子锁死。
- **默认手动保存，并把「不丢稿」做在底层**：只有 `Ctrl+S` 才写盘；但所有写盘都是原子写、删除进 `_trash`、未保存状态四处可见、切章 / 关窗 / 回书架三处拦截。

## 适合谁

| 适合 | 不适合 |
|---|---|
| 写长篇 / 连载中文小说，想要「一本书一文件夹」的透明结构 | 想要自动保存、云同步、多端协作 |
| 喜欢纯文本、愿意自己备份（同步盘 / 移动硬盘） | 需要 Markdown / 富文本 / 图文混排 |
| Windows 用户，想要本地离线、无账号、无广告 | 手机 / Mac / 网页版用户 |
| 在意键盘操作与可访问性（全部可 Tab 到达） | 需要在线发布、阅读器商店、写作社区 |

## 三步开始

1. **下载**上面的安装包，双击安装（安装包没有代码签名，SmartScreen 点「更多信息 → 仍要运行」）。
2. 从桌面快捷方式打开，点书架顶部的「新建作品」，输入书名。新书是 **0 章**，章节由你自己建。
3. 点左下「＋ 新建章节」（或 `Ctrl+N`）写第一章，写完**按 `Ctrl+S` 保存**。就这样。

![写作页](docs/images/editor.png)

> 第一次用建议读一遍 [使用手册](docs/使用手册.md)（导入、分卷、多选、导出、快照都在那里）；担心稿子存在哪，看 [数据在哪与怎么备份](docs/数据安全.md)。

## 安装与启动

### 方式一：安装包（推荐，不用命令行）

从 [GitHub Releases](https://github.com/ANAN1124-OSS/chapterly/releases) 下载 `chapterly-2.2.0-win-x64-setup.exe`；也可以本地 `pnpm run dist` 自打包（产物在 `dist\`）。

1. 没有代码签名，Windows 可能弹「已保护你的电脑」→「更多信息」→「仍要运行」。
2. 可以自选安装目录（默认当前用户目录，不需要管理员），装完有桌面快捷方式与开始菜单入口。
3. 卸载在 Windows「设置 → 应用」里；**卸载不会删你的小说**（书架目录自己定，应用配置在 `%APPDATA%\chapter-writer`）。

### 方式二：开发版（代码方式）

环境要求：

- Windows 10 1809+ / Windows 11
- Node.js ≥ 22（实测 v24）
- pnpm ≥ 12（`pnpm-workspace.yaml` 的 `allowBuilds` 是 v12 字段）
- Python ≥ 3.7（只有重新生成图标 `pnpm run icon` 用到；纯标准库，不参与运行与打包）

```bash
cd <仓库目录>
pnpm install        # 第一次会下载 Electron（约 100MB，走 npmmirror 镜像）
pnpm start          # 启动应用
```

- 如果 `pnpm start` 报「此系统上禁止运行脚本」，双击根目录 `启动章回.cmd`，或改用 `pnpm.cmd start`，或 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 后再试（PowerShell 7 不受影响）。
- `.npmrc` 默认国内镜像；海外或换源用 `npm_config_electron_mirror=<镜像 URL> pnpm install` 覆盖（优先于 `.npmrc`）。
- 某些宿主环境带 `ELECTRON_RUN_AS_NODE=1` 会让 Electron 退化成纯 Node；`pnpm start` 走 `scripts/start.js` 会自动清掉它。

## 数据在哪

| 内容 | 位置 | 性质 |
|---|---|---|
| 书稿 | 书架目录（默认 `文档\我的小说`，可在设置改） | 一本书一个文件夹，每章一个 `txt`；`书目.json` 是结构与元数据的唯一事实来源 |
| 应用配置 | `%APPDATA%\chapter-writer\config.json` | 书架目录、显示设置、模板、词表路径等 |
| 字数统计 | `%APPDATA%\chapter-writer\stats.json` | 只记按保存时新增的正字数 |
| 日志 / 索引 / 崩溃草稿 | `%APPDATA%\chapter-writer\` 下各自目录 | 日志不含正文；索引只存哈希位图；草稿默认关 |

**备份就一句话**：把书架里的书文件夹整个复制走即可，正文全是普通 txt；建议把书架放进 OneDrive / 坚果云，或打开 Windows 文件历史记录。卸载应用不会删书，也不会删 `%APPDATA%` 里的配置（安装包没勾「卸载时删数据」）。

详细说明（每一项配置、`_trash` 结构、哪些操作绝不落盘）见 [数据在哪与怎么备份](docs/数据安全.md)。

诊断日志单独存放在 `%APPDATA%\chapter-writer\logs\`（每天一份，超过 256KB 换序号，最多留 12 份）。日志只记时间、错误类型、错误码、IPC 频道、文件名、版本与调用栈，本机路径会脱敏——**绝不写任何正文**；但除了错误码和文件名，**也可能出现书名 / 章名**（它们不是正文，仍是作品信息）。**把日志发给别人**（贴 issue / 群里反馈）之前，请**先自己看一遍**。日志写不进去也不影响正文保存。

## 常见问题

**会丢稿吗？** 只有你得按 `Ctrl+S` 才写盘，这一点必须先接受；底层用原子写 + `_trash` + `.bak` 兜底，但**硬盘坏了 / 误删整份文件夹仍然要靠你自己的外部备份**。

**数据在云端吗？** 不在。没有账号、没有服务器、不联网也能写。

**能导入别的写作软件吗？** 能导入纯文本小说：按「第X章」等标题拆章，或整本一章；也支持章回自己导出过的文件夹结构。

**卸载会删书吗？** 不会。书在书架目录，配置在 `%APPDATA%`，卸载程序都不动。

**为什么安装包这么大、还要 SmartScreen 警告？** Electron 应用体积就在这里，且没有买代码签名证书；介意的话用开发版。

**支持 Markdown / 富文本 / 图片吗？** 不支持，设计上只做纯文本。

**字数怎么算的？** 按 UTF-16 码元，emoji 算 2 字，与 `String.length` 一致，全应用同一口径。

**有手机版 / Mac 版吗？** 没有，只做 Windows 桌面。

更多（导入细节、导出格式、同步冲突、词表、朗读、多窗口…）见 [完整常见问题](docs/常见问题.md)。

## 已知限制（要点，完整清单见 [docs/已知限制.md](docs/已知限制.md)）

- 安装包**未签名**：首次安装 Windows SmartScreen 会提示「已保护你的电脑」，点「更多信息 → 仍要运行」即可；自动更新只做了**轻量版**（手动检查 → 打开 GitHub 下载页），**没有自动下载、自动安装、后台静默升级，也没有代码签名**，升级仍需你自己下载安装包覆盖安装
- **Electron 安全开关之外的残余风险**：页面仍用 `file://` 加载（没有换成自定义协议），打包配置**已开** `enableEmbeddedAsarIntegrityValidation` 与 `onlyLoadAppFromAsar` 这两个 fuse（`grantFileProtocolExtraPrivileges` 未显式关，仍是 Electron 默认）；`Ctrl+Shift+I` 只在开发 / 自检构建里能打开开发者工具（打包后的正式版已不绑定），窗口开着 `sandbox` + `contextIsolation`，里面同样没有 Node 能力。渲染层没有文件系统权限，正文只能由主进程按既有校验读写。
- **目录联接书库**：书架根目录可以是指向别的盘 / 别的目录的目录联接（Windows junction），列书 / 打开 / 读章 / 保存都照常走真实目录；书入口在文本判定之外还有一道 realpath 复核（书目录真实路径必须在书架根的真实路径下，联接书库根本身与网络盘照常放行），因此书文件夹本身若是指向库外的联接会在打开时被拒绝——它本来也不会自动出现在书架。完整边界（路径校验 / 来源校验 / 错误脱敏 / 联接）见 [docs/已知限制.md](docs/已知限制.md)。
- **无自动保存、默认无每日备份**：自动保存只有「新建 / 插入章节前自动保存当前章」这一处例外；每日快照要手动在设置里打开（默认关）；也没有云同步 / 多端。
- **单本书目最多 20,000 章**：`书目.json` 的章节记录超过 20,000 条时，读侧按「书目损坏」处理、写侧在写盘前直接拒绝（导入 / 建章 / 从目录重建同样受约束），绝不写出「自己能写、自己打不开」的书。正常长篇远到不了（20,000 章 × 每章 3 万字 ≈ 6 亿字）；Ctrl+G 跳章列表的「2 万条」是另一个上限。
- 其余边界（单章 128 MB 闸门 / 单章 500 万字保存上限与 3,000 万字符载入上限 / IPC 参数上限 / 导入导出 / 简繁转换 / 统计 / 索引 / 阅读 / 模板 / 日志 / 检查更新等）逐条列在 [docs/已知限制.md](docs/已知限制.md)。

- **字数口径（X3）**：全应用按 **UTF-16 码元** 计（与 JavaScript 的 `String.length` 一致）——普通汉字 / 英文 / 标点算 1 字，emoji 与扩展区汉字（U+20000 以上）算 2 字；状态栏、章节列表、书架统计与各处阈值共用这一口径。
- **段落空行口径**：整理正文时，所有模式都会丢掉正文开头的空行、结尾连续空行只保留一个；「保持原样」保持的是段与段之间的空行数。首尾空行不在「保持原样」的范围内。

## 防丢稿设计（当前保证）

> 完整的逐轮改动记录（25–82 条，v0.8.5 起）已归档到内部文档（`内部文档/归档-2026-11-15/沿革.md` 的「防丢稿设计逐轮记录」）；下面只列当前生效的保证。

虽然不做自动保存，但底层仍然为「不丢稿」做了这些：

1. **所有写盘都是原子写**：临时文件 → fsync → rename（失败重试 3 次）。不会出现写一半的半截文件。
2. **`书目.json` 每次写入前保留上一版 `.bak`**：json 写坏可以从上一版恢复。
3. **删除不真删**：章节文件移到 `_trash\{时间戳}-{原文件名}`。
4. **未保存状态四处可见**：窗口标题前 `*`、状态栏橙点、保存按钮高亮、章节名后 `•`。
5. **三处拦截**：切章、关窗、返回书架，都会先问。**导出 / 复制不拦**：当前章未保存的内容会直接拼进导出结果（不写盘），导出完仍保持未保存状态。
6. **关窗保存失败会阻止退出**：弹「返回保存 / 放弃修改退出」，不会静默关掉。
6b. **破坏性动作都能退一步（1.4.0；1.5.0 起可连退最近 3 步）**：删除章节、跨卷移动、移到卷、删除卷、一键整理本书、整本替换、
    还原到替换前、本书历史还原，都改成「直接执行 + 左下角撤销条」——**10 秒内**点「撤销」或按 `Ctrl+Z`
    就退回去（撤销资源来自各动作自己写的 `_trash` 备份，不额外存一份）。撤销条按后进先出留最近 3 条：
    撤销一条后条子换成更早那条，`×` 或没有弹层时按 `Esc` 收起；连做第 4 步会顶掉最旧一步并提示
    「上一步（…）的撤销已被新动作替换」。撤销失败（文件被占用等）条子会留着可再点，但不会重新续满 10 秒。
    **1.5.0 起撤销前会核对备份没变**：还原到替换前 / 本书历史还原 / 整本整理的撤销，登记时记下那份
    `_trash` 备份的目录名 + 文件数 + 最新修改时间；10 秒窗口里这份备份被外部增删或改写，就提示
    「备份已变化，撤销取消」并早退（不拿变了的备份覆盖正文）。
    弹确认框的只剩两处：**未保存拦截**（切书 / 关窗 / 还原前先处理没写盘的字）与**删除整本书**（整本进回收站，应用内没有还原通道）。
7. **外部修改检测 + 保存前置校验**：窗口重新获得前台时比对**当前章**的 mtime —— 没变不打扰；有未保存修改只 toast 警告；否则问「重新加载 / 保留我的」。其它章不主动查，打开时才核对（`renderer/statusbar-ui.js` 的 `setupExternalChangeWatch`）。保存链路另带 `expectedMtimeMs` 前置条件：载入 / 上次保存回执记下 mtime，保存前磁盘上的 mtime 已经变了就抛 `EXTERNAL_CHANGE`、**一个字节都不写**，界面给「取消 / 放弃我的修改并重载 / 仍然覆盖保存 / 先另存一份」四选（`saveCurrent({ force: true })` 才跳过校验；判定在 `core/open-books.js` 的 `verifySaveTarget`）。
8. **损坏恢复**：`书目.json` 坏了，可以从 `.bak` 恢复，或按目录里的 txt 文件名重建书目（损坏文件改名为 `.corrupt-时间戳` 保留）。
9. **保存失败不更新「已保存」状态**：状态栏红字显示具体错误。
10. **整本替换前自动备份**：改动的原章节先复制到书内 `_trash\替换备份-时间戳\`，再原子写盘；应用内可「还原到替换前」一键退回，还原前还会把当前内容再备份一份到 `_trash\还原前备份-时间戳\`；这些备份不会被自动删（每日快照是唯一例外，见下一条）。备份目录名精确到秒，**同一秒内连做两次替换会自动加 `-2`**（两份备份各存各的，不会互相覆盖）。**1.5.0 起还原读盘前先验大小**：还原到替换前 / 本书历史还原读备份文件前先看 `stat.size`，单文件超过 128 MB（与导入上限同一口径）就明确拒绝 —— 不读进内存、不建还原前备份、一个字节都不写。
11. **配置坏了不会悄悄回默认**：`config.json` 损坏时会先归档成 `config.json.corrupt-时间戳` 再回默认值，并在界面上提示一句（否则书架路径会突然变回「文档\我的小说」，像书全丢了一样）。
12. **可选每日快照（默认关）**：开启后每次保存前把当天第一次的上一版复制到 `_trash\快照-YYYYMMDD\`，同章每天一份、只增不覆盖；按保留天数清理时只删**名字严格是 `快照-YYYYMMDD`** 的目录，别的备份 / 文件 / 乱写目录一律不碰。快照失败不会阻塞保存，最多在保存结果里带一句原因。**1.5.0 起单章正文超过 128 MB 时直接跳过快照并写明原因（不把整份读进内存）**。
13. **每日字数统计不写书库**：只把「保存时新增的正字数」记到 `%APPDATA%\chapter-writer\stats.json`（按本地日期 + 书 id）；不统计未保存内容，删字不倒扣，统计读写出错只影响数字显示，**绝不阻塞正文保存**。每日目标是可选的全局设置（0 = 不设）。**码字日历 / 连续写作天数 / 月度汇总**都从这份统计现算（`core/stats.js` 纯函数），不另存日历缓存、不新增配置字段；日历只读，翻月不会写 `stats.json`。**写作时长**（默认关）只在你手动点「写作计时」时按实际经过时间累计整秒，只记秒数、不记内容，和字数存在同一份 `stats.json` 的 `seconds` 可选字段里；关掉后主进程直接忽略上报，不写盘。**按书 / 按年筛选**只是主进程在读取时用 `aggregate` 现算一份汇总（`stats:get` 多收一个可选 `filter` 参数），不改 `stats.json` 结构、不新增配置字段 / IPC 频道，也不缓存汇总结果；CSV 只生成文本（BOM + CRLF）供复制，落盘要新增写盘通道，留给作者拍板。
14. **校对只报告、不改正文**：都在 `core/proofread.js` 里算（纯函数），半角标点判定直接复用「排版」的 `convertPunct`，不会各判各的；当前章用编辑区里的最新内容（未保存也算），整本逐章**只读磁盘**。校对不写任何 txt / 书目、不生成 `_trash`，点结果只是选中正文位置。第六条「自定义词表」来自你自己的一份 txt（`core/glossary.js` 只读解析；可写「错词 → 建议」，`#` 开头是注释），和敏感词表是两份独立文件；没有词表时九条内置规则照常跑，词表有问题只在状态行提示。
15. **碎片独立存放、绝不覆盖**：灵感箱的碎片写在书架根目录 `_碎片\`（纯 txt），文件名按本机日期 + 当天最大序号 + 1 生成，写盘走原子写，**不会覆盖已有碎片**；不写 `书目.json`、不碰章节 txt，也不在书架上冒充成一本书。插入碎片只改编辑区（`Ctrl+Z` 可撤销），原碎片永远保留；应用不提供「用后删除」。
16. **敏感词预检只读你的词表、只报告**：词表是你自己的 txt，应用不内置、不复制、不改写；预检只读词表 + 只读正文（当前章可用编辑区未保存内容），不写任何 txt / 书目、不生成 `_trash`。词表路径存在 `config.json` 的 `sensitiveWordsPath`，删掉配置只会忘掉路径，不会动词表文件。
17. **朗读只说不动**：正文只在渲染层读给系统语音听，主进程只做纯文本切分（`core/tts.js`，不读盘、不写盘）；发声全程不改编辑区、不改 `书目.json`、不生成 `_trash`。一改字、一切章、一回书架或按 `Esc` 就立刻 cancel，不会拿着旧段落继续念。语速 / 语音选择只在本次朗读小条打开期间有效，不写配置。
18. **编辑器小件只画不写（三个开关的按书记忆、超长段落阈值与当前段落高亮颜色除外）**：超长段落黄线、全角空格 ␣、行尾空白标记、**当前段落高亮的底色与左侧细线**、选中字数、章节列表字数对比都只改显示层——标记画在 `pointer-events: none` 的影子层里，**正文不改一个字节、不写书库、不改 `书目.json`**。其中「不可见字符 / 超长段落提示」和「当前段落高亮」三个开关、**超长段落阈值**（默认 500，50–20000）**都是按书记忆的可选显示设置**，按书存在 `config.json` 的 `bookDisplay`（两个提示开关没设置过的书按默认关；阈值没设置过的书沿用全局默认；当前段落高亮的开关与颜色没设置过的书跟随顶层全局默认），保存设置时只原子写 config.json，**绝不碰正文 / 书目 / 章节文件**，旧 config 没有这些字段时照常启动（两个提示开关关；阈值 500；当前段落高亮按其全局默认；颜色跟随主题）。颜色只认 `#rgb` / `#rrggbb`，写坏了回落主题色；自定义色由 `core/caret-color.js` 换算成淡底 + 细线用的 rgba（有单测）。章节列表的字数来自 `书目.json` 的字数缓存（保存时更新），标记层的位置每次从编辑区实测字体 / 行高 / 宽度算，不写死也不会错位到正文之外。当前段落只按「光标落在哪一行（一个非空行 = 一段）」现算，不缓存、不写盘。正文超过 **30 万字**时整层标记直接不建（`renderer/editor-logic.js` 的 `marksTooLarge` 门控，正好 300000 字仍然画），只提示一次——不会为了几个标记去重建整章 DOM 镜像；正文 / 保存不受影响。
19. **专注模式只收起面板、不碰内容**：它只给写作页加一个 CSS class（隐藏左栏 / 分隔条 / 顶栏）并调 `textarea.scrollTop`，不改正文、不写 `书目.json`、不写配置；「打字机」开关只记内存。进入时只把焦点交回编辑区，不改变窗口大小、不进 Windows 全屏；退出时按「光标行顶端 - 滚动位置」还原视线，正文变宽导致换行变化也不会跳错位置。
20. **错误日志不含正文、也不挡写作**：日志只记元数据（时间、错误类型、错误码、IPC 频道、文件名、应用版本、栈），`core/logs.js` 只接受这些字段，还会把连续 24 个以上汉字当正文隐去、把本机绝对路径收成「`…\最后一节`」（见内部归档沿革第 37 条）；保存失败 / 主进程异常不会让应用退出（先让你 `Ctrl+S` 保存），写日志本身失败（目录被占用、磁盘满、没权限）只吞掉，绝不阻塞保存正文或弹出错误。日志文件按天 + 按大小滚动、只留 12 份，只删本应用命名的 `chapter-writer-*.log`，不碰日志目录里别的东西。
21. **正文搜索索引只读、不含正文**：索引存在 `%APPDATA%\chapter-writer\search-index.json`，不写书库、不写 `书目.json`、不动章节 txt；文件里只有「双字哈希位图 + 每章 mtime/size 指纹 + 书名章名」，**没有任何正文句子**。搜正文时只读章节 txt 来核对命中并截上下文，不改一个字；索引读写失败只让这一次搜索降级（显示为空 / 提示），绝不挡保存、不挡书架。删掉索引文件只损失「下次搜索要重建」这点时间。
22. **多窗口不会互相覆盖、也不会重建影子文件**：主进程用「窗口 → 打开中的书」登记（**只在内存**）做唯一事实来源：同一本书**只允许一个窗口打开**（再点只聚焦已有窗口），别的窗口正开着的书**禁止删除 / 改名 / 整理 / 整本替换 / 导入覆盖**（明确提示先关 / 先切窗口）。每次保存正文前都要校验「书文件夹、书目、章节记录、章节文件」都还在（且书不在别的窗口），任何一项失效就**报错阻止写盘**；保存用的原子写关掉了 `mkdir` 兜底，**绝不重建目录 / txt**，不会出现「另一个窗口删了章，这边一保存又长出一个不在书目里的影子 txt」。窗口之间有独立的编辑区 / 脏状态 / 关闭询问，关一个只关一个，最后一个关掉才退出。
23. **查找高亮只画不写**：当前章查找后，全部命中画在 `#editor-find-marks` 只读影子层上（和编辑器小件共用同一套「按编辑区实测字体 / 宽高对齐、跟着滚动」的逻辑），当前那处只切一个 class，**不重画正文、不改正文**；「上一处 / 下一处」只移动选区与滚动。命中超过 **500 处**时只画当前附近一屏，导航仍覆盖全部命中（单章上限 5000 处，`findMatchesAll` 会明确回报是否被上限截断）；绕回 / 窗口 / 正文切片 / 行号都在 `renderer/find-logic.js` 里，有单测。会话只记内存：改正文、切章、换书、离开写作页就结束，`Esc` 也能清除，不写配置、不写书库。
24. **查找书签只记查询条件、不记正文**：书签按「书 + 章」存 `config.json` 的 `findBookmarks`（`core/bookmarks.js` 负责清洗 / 按「书 + 章」去重 / 增删，有单测），每条只有 `bookId` / `chapterId` / `query` / `caseSensitive` 与几个显示字段（书名 / 章名 / 章号 / 书路径）+ 时间戳，**没有正文、没有命中位置**。打开这一章时由渲染层按**当前编辑区正文**重新扫描并高亮（正文改过也能重新定位；改到没有命中时高亮收起、书签保留）；面板里可以列出本机书签、跨书跳转、删除。存 / 跳 / 删全部走主进程的只读 IPC + 原子写配置：**绝不写书库 / 书目 / 章节文件**，渲染层仍然没有 fs 权限；旧 config 没有这个字段 = 没有书签，照常启动。最多 200 条，同一「书 + 章」只保留一条（再存 = 更新查询词 / 大小写）。
25. **可选崩溃草稿只写 userData、只用于崩溃恢复（默认关）**：**这不是自动保存**。「设置 → 数据安全」里打开后，写作页有未保存修改时每 30 秒把编辑区正文原子写进 `%APPDATA%\chapter-writer\crash-drafts\`（单条最多 500 万字、最多 8 份、超过 7 天自动清理），**绝不写书库 / `书目.json` / 章节 txt / `config.json`**；渲染进程崩溃重载或上次异常退出后，启动时逐条弹一次「恢复 / 丢弃 / 先留着」，恢复只把正文放进编辑区（仍为未保存状态，`Ctrl+S` 才写盘），当前编辑区已有未保存修改时不覆盖。干净退出删运行标记与全部草稿；目录不可写（ENOSPC / EPERM / 被占用）只回错误码、不抛、不挡保存；默认关时**一个字节都不写**。

## 开发与自检

```bash
pnpm test            # 单测（node:test，3625 项）
pnpm run e2e         # 全量 E2E：真实启动 Electron 走 1946 项主流程
pnpm lint            # eslint 门禁（0 ERROR）
```

- E2E 场景与 84 个组文件共用一份 harness；**84 个组文件（00–83）** 按组号派发。PR 改动 `renderer/` / `core/` / `ipc/` / 主进程时会跑受影响的组（`scripts/e2e-scope.js`）。
- **CI 上的 E2E 会跳过视觉断言**（2.1.0 起）：GitHub 托管 runner 没有交互式桌面会话，Chromium 对不可见窗口节流合成 / 动画 / 布局，动效 / 主题 / 几何测量这类断言（源码里 44 处 `checkVisual`，运行时按用例展开 50 项；跳过面由 `scripts/e2e/visual-assertions.js` 的静态清单约束，`scripts/wiring-check.js` 逐项核对）在那边必然偏，所以 CI 设 `E2E_SKIP_VISUAL=1` 跳过它们；功能断言与供应链闸门照常阻塞。**本地与发版前的 `pnpm run e2e` 不带该开关，跑全量 1933 项。**
- 版本 / 计数锚点：`node scripts/version-sync.js --check`（只核对 README 与验收清单互相对得上；带上 `--unit <N> --e2e <M>` 才与实测值强核对；发版用 `--write --unit <N> --e2e <M>` 同步）。
- 打包、构建供应链、静态闸门策略与验收纪律见 [docs/维护与自检.md](docs/维护与自检.md)；完整目录与模块地图见 [项目结构](docs/项目结构.md)。
- 历史分册（版本沿革、防丢稿逐轮记录、开发自检细节）已归档到内部文档：`内部文档/归档-2026-11-15/沿革.md`、`内部文档/归档-2026-11-15/README-开发自检细节.md`，不进公开仓库。
