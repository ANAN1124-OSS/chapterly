# 章回 / Chapterly v1.8.1

给写个人自用的 Windows 桌面写作工具：**整本书一键保存、绝不丢稿**；新建章节自动生成「第12章：」这样的标题，你只填名字。

技术形态：Electron + 原生 HTML/CSS/JS（无框架），Windows 安装包 + 开发版两种用法。

> **版本沿革**：本仓库从 **v1.0.0** 起（产品内容承接原「章节写作器」0.12.6 的最终构建），改名「章回 / Chapterly」时**数据目录名仍沿用旧名 `%APPDATA%\chapter-writer`**（改名不搬数据、零迁移）。**完整的版本沿革、逐轮改动记录与开发自检历史已归档到内部文档（`内部文档/归档-2026-11-15/`，不进公开仓库）**；本文件只保留当前文档。

---

## ⚠️ 先看这三条（本版是「完全手动保存」）

1. **保存是手动的，只有一个例外**：平时只有按 `Ctrl+S` 或点「保存」按钮时，正文才写进磁盘。例外是**新建 / 插入章节之前**——当前章有未保存修改时会**自动帮你存一下**再建新章（保存失败就停下报错、不建新章），省得每次建章都被问一次。
2. **默认不做每日备份**：应用默认不备份任何东西。只有在「设置」里手动打开**可选每日快照**（默认关）后，才会在每次保存时把当天第一次保存的**上一版**留一份到书内 `_trash\快照-YYYYMMDD\`，并按保留天数自动清理旧快照。**改坏了、崩溃了、关机了，最终还是靠你自己拷的副本。**
3. 切章节、**换另一本书**（命令面板 / 书签跨书 / 书籍信息里的章节命中 / 书架点书）、关窗口之前，如果当前章有未保存修改，应用会弹窗让你选「保存 / 不保存 / 取消」，**不会静默丢失，也不会偷偷替你保存**；选「取消」或保存失败就停在原地，正文和当前书都不动。
   **导出 / 复制不用先保存**：当前章在编辑区里还没保存的内容也会一起写进导出结果（只参与拼接，不写盘），不会因为忘记按保存而导出旧内容。

> 强烈建议：把书架目录（默认在「文档」下的 `我的小说` 文件夹）放进 OneDrive / 坚果云等同步盘，或打开 Windows 的「文件历史记录」。
> 即使打开了应用内的每日快照，也建议保留一份外部备份（同步盘 / 移动硬盘）——快照只覆盖「保存前一刻」，防不了整块硬盘坏掉。

## 环境要求

**安装版（作者日常用）**：Windows 11 / Windows 10 1809+，**不需要装 Node**。

**开发版（改代码时用）**：

- Windows 11（Windows 10 1809+ 也可）
- Node.js ≥ 22（开发机实测 v24.22.1；CI 用 **22 / 24 两档矩阵**各跑一遍，见下）
- pnpm ≥ 12（实测 12.11.2；`pnpm-workspace.yaml` 的 `allowBuilds` 是 v12 字段，旧版兼容性未实测，按实测下限写）
- Python ≥ 3.7（只有重新生成图标 `pnpm run icon` 用到；纯标准库，不需要 Pillow，不参与运行与打包）

> **CI**：GitHub Actions 三套工作流，所有 actions **固定到提交 SHA**（Dependabot 每周提更新，不跟 `@v4` 浮动标签），运行镜像固定 `windows-2022`（不用浮动的 `windows-latest`）：① `.github/workflows/verify.yml` 在每次 push / PR 上跑四步——全量 `node --check`、`npm test`、`npx eslint .`（no-undef / no-unused-vars 均为 error）、`node scripts/a11y-gate.js --static`；**Node 用 22 / 24 两档矩阵**（`fail-fast: false`，与 engines 的 ≥22 对齐，v1.8.0 审计 O4 / #56）；② `.github/workflows/e2e-pr.yml` 在 **PR 改动 `renderer/**` / `core/**` / `ipc/**` / `main.js` / `preload.js`（以及 E2E 基建与依赖清单）时整跑一次全量 E2E**——把 UI 时序 / 真实 DOM 的回归窗口从「每周」缩到「每个 PR」（WP16 / 审计中 #19 / F1）；触发路径的唯一事实源是 `scripts/e2e-scope.js`（工作流的 `paths:` 与它逐项一致，本地可用 `node scripts/e2e-scope.js --changed <文件…>` 自查）；③ `.github/workflows/e2e-weekly.yml` **每周定时整跑一次全量 E2E**（真实 Electron 窗口 + 临时书库），补上集成回归的自动拦截（v1.8.0 审计 O1 / #29）。②③ 都在装完依赖后先跑 `node scripts/supply-chain-check.js` 核对 Electron 二进制（WP15 / 审计 E1=O-N2）。**打包冒烟（`dist:dir` / NSIS 安装）仍按发版门禁在发版前本地执行**。提交前本地仍按 `pnpm lint` + `npm test` 自查。

## 安装与启动

### 方式一：安装包（推荐，不用命令行）

**下载**：从 [GitHub Releases](https://github.com/ANAN1124-OSS/chapterly/releases) 下载 `chapterly-1.8.1-win-x64-setup.exe`（已于 2026-11-16 发布，见 [v1.8.1](https://github.com/ANAN1124-OSS/chapterly/releases/tag/v1.8.1)），或者直接用本机打包产物 `dist\chapterly-1.8.1-win-x64-setup.exe`；开发时也可以先用开发版（`pnpm start`）。

安装：

1. 安装包**没有代码签名**，Windows 可能弹「已保护你的电脑」→ 点「更多信息」→「仍要运行」。
2. 可以自己选安装目录（默认装到当前用户目录，不需要管理员），安装完有**桌面快捷方式**和**开始菜单**入口。
3. 卸载：Windows「设置 → 应用」里卸载，或开始菜单里「卸载」。**卸载不会删你的小说**（书架目录默认在「文档」下、可自行修改，应用配置在 `%APPDATA%\chapter-writer`；安装包也特意没勾「卸载时删除应用数据」）。

> 安装版和开发版**共用同一份配置和书架设置**（同一个 `%APPDATA%\chapter-writer\config.json`），换着用不会丢设置。

> **数据目录为什么还叫 chapter-writer**：1.0.0 改名「章回 / Chapterly」时有意没搬数据目录——旧版的配置、统计、日志、搜索索引和书架设置全部原样沿用，首次打开就是原来的状态。下文所有 `%APPDATA%\chapter-writer\…` 都是**数据目录名**，与版本号无关。

### 方式二：开发版（代码方式）

```bash
cd <仓库目录>
pnpm install        # 第一次会下载 Electron（约 100MB，走 npmmirror 镜像）
pnpm start          # 启动应用
```

> **如果 `pnpm start` 报「无法加载文件 …pnpm.ps1，因为在此系统上禁止运行脚本」**
>
> 这是 Windows PowerShell 5.1 的默认执行策略（Restricted）拦住了 pnpm 的 `.ps1` 垫片，不是项目的问题。
> 任选一种即可：
>
> 1. **双击项目根目录的 `启动章回.cmd`**（最省事，不用记命令）；
> 2. 在当前 PowerShell 里改用 **`pnpm.cmd start`**（走 `.cmd` 垫片，不受脚本策略限制）；
> 3. 一次性放开当前用户策略（无需管理员）：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`，之后 `pnpm start` 就能用；想改回去：`Set-ExecutionPolicy -Scope CurrentUser Undefined`。
>
> 用 PowerShell 7（`pwsh`）打开终端也可以直接用 `pnpm start`。

说明：

- `.npmrc` 默认配了国内的 `electron_mirror=https://npmmirror.com/mirrors/electron/`，避免卡 GitHub；海外或其他镜像不必改文件，用 `npm_config_electron_mirror=<镜像 URL> pnpm install` 覆盖（这个环境变量形式的 config 优先于 `.npmrc`），两者都不设时回退官方 GitHub。
- 某些宿主环境（例如某些 AI 工具、CI）会带 `ELECTRON_RUN_AS_NODE=1`，会让 Electron 退化成纯 Node 而启动失败。
  `pnpm start` 实际执行的是 `scripts/start.js`，它会自动清掉这个环境变量再启动。
  （**安装版**从桌面/开始菜单双击启动不受影响；只有在那种环境里用命令行直接跑 exe 才要先清掉它。）
- 数据目录不在项目里：默认在当前用户「文档」下的 `我的小说` 文件夹，可在应用「设置」里改。
- 启动链的失败会说得清楚：`启动章回.cmd` 先确认 PATH 里有 `node`（没装就提示去 nodejs.org，不再只报 9009）；没装依赖时 `scripts/start.js` 会提示先跑 `pnpm install`；Electron 被信号杀死（拿不到退出码）按非 0 退出，不会被当成启动成功（审计 X15）。

## 打包（开发者/维护用）

```bash
pnpm run icon       # 重新生成图标（build/icon.ico / icon.png，纯标准库 Python 绘制，不需要 Pillow）
pnpm run dist       # 打 Windows 安装包 → dist\chapterly-<版本>-win-x64-setup.exe（NSIS，x64）
pnpm run dist:dir   # 只打免安装目录 → dist\win-unpacked\章回.exe（改完快速验证用）
```

- 配置在 `package.json` 的 `build` 字段：appId、产品名、NSIS 安装器选项（可选目录、桌面/开始菜单快捷方式、中文界面）。
- **`appId` 固定为 `local.chapter-writer`（历史身份，不随产品名 / `name` 改）**：它决定 NSIS 安装 / 卸载注册表键（`Software\<由 appId 派生的 GUID>`）、快捷方式 AppUserModelID 与「是否已安装」的识别。v1.8.0 已发布，现在换 appId 等于换一个应用身份——旧版卸载项残留、任务栏固定项分裂、新旧版还会装进同一个目录。正式反向域名（如 `com.anan1124.chapterly`）顺延到下一个大版本，随「先卸载旧版再装新版」的迁移说明一起改；它与应用数据目录 `%APPDATA%\chapter-writer` 无关（数据目录在 `main.js` 里显式指定，不随 appId / 产品名搬动）（审计残留 #31 / O3；处置口径＝保持现状 + 文档化，不改实现）。
- 国内网络打包时如果下载 Electron/NSIS 卡住，先设镜像：
  `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`、
  `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`。
- 镜像优先级（@electron/get）：`npm_config_electron_mirror`（`.npmrc` 或环境变量）> `ELECTRON_MIRROR` > `package.json` 的 `build.electronDownload.mirror` > 官方 GitHub；打包默认镜像仍写在 `build.electronDownload.mirror`，海外可直接用 `ELECTRON_MIRROR` 覆盖。
- 目前**没有代码签名**（个人自用省掉证书），所以每台新机器首次安装会看到 SmartScreen 提示。
- 安装包产物在 `dist/`（已加进 `.gitignore`，不进仓库）；`build/icon.*` 是图标源文件，会进仓库。
- 打包时排除 `renderer/test-hooks.js`（E2E / 截图自检用的调试钩子，只在开发版地址带 `?test=1` 时动态加载）：`build.files` 里的 `"!renderer/test-hooks.js"` 保证安装包内没有这份死代码（v1.8.0 审计 O2 / #30）。
- 产物文件名用 **ASCII**（`chapterly-<版本>-win-x64-setup.exe`）：`gh` 在 Windows 上传中文文件名会被吞成坏名，所以发布资产别用中文名；安装后的程序显示名 / 快捷方式为「章回」。
- 发布到 GitHub：`gh release create v<版本> "dist/chapterly-<版本>-win-x64-setup.exe" --title "章回 v<版本>" --notes-file <说明.md>`（`gh` 走 HTTPS，国内需 `HTTPS_PROXY`）。
- **版本号只有 `package.json` 一处权威（v1.8.0 / 审计 D10）**：`renderer/index.html` 不写版本串，界面由主进程 `app.getVersion()` 启动时经 `app:version` 注入；README / 验收清单的标题、下载名与单测 / E2E 计数用 `node scripts/version-sync.js --write --unit <N> --e2e <M>` 同步（`--check` 只校验漂移，`tests/version-sync.test.js` 同口径）。发版前先跑一次同步，再打包。
- **发版门禁（WP15 / 审计 E1=O-N2）**：打包前必须跑 `node scripts/supply-chain-check.js`，用仓库内置的官方 `SHASUMS256.txt` 核对 Electron 二进制；非 0 退出不得继续（详见下文「构建供应链」）。

### 构建供应链（Electron 二进制）

- v1.8.0 审计 ▲V308：Electron 二进制默认走国内镜像：`.npmrc` 的 `electron_mirror` 与 `package.json` 的 `build.electronDownload.mirror` 都指向 `https://npmmirror.com/mirrors/electron/`（覆盖方式见上）。
  **镜像只是下载加速，不是来源证明**：镜像被替换 / 构建机被投毒时，产物本身没有任何可验证锚。
- **官方校验清单已随仓库入库（WP15 / 审计 E1=O-N2）**：`build/electron/SHASUMS256.txt` 是 Electron v45.1.0 官方 release 的原始 `SHASUMS256.txt`（逐字节入库；来源 URL、取回时间与文件 SHA-256 见同目录 `SHASUMS256.provenance.json`）。
- **发版门禁必做（打包前）**：

  ```bash
  node scripts/supply-chain-check.js
  ```

  它用内置清单核对 `%LOCALAPPDATA%\electron\Cache`（或 `ELECTRON_CACHE` 指向的目录）里的 `electron-v<版本>-win32-x64.zip`。清单缺失、清单与本地 Electron 版本对不上、缓存里找不到 zip、zip 与官方清单不一致、zip 读不了，都直接非 0 退出，**不得继续打包 / 发版**。`--zip <文件>` / `--cache <目录>` / `--version <版本>` 可定位问题。也可以直接跑底层命令 `node scripts/verify-electron-checksum.js --shasums build/electron/SHASUMS256.txt`。这一步**不联网、不自动下载**，也**不在** `pnpm run dist` 里自动执行（离线 / CI 构建不应该多一个网络失败面），但它是**发版门禁的一步，必须显式跑**。
- **CI 同口径**：`.github/workflows/e2e-weekly.yml` 在 `pnpm install` 之后、跑 E2E 之前执行同一条 `node scripts/supply-chain-check.js`；校验红就不跑 E2E（`verify.yml` 跳过二进制下载，没有 zip 可核对，不挂这一步）。
- **升级 Electron 时**：从官方 release 重新取对应版本的 `SHASUMS256.txt` 覆盖入库，并同步 `SHASUMS256.provenance.json` 的 `version / sourceUrl / fetchedAt / sha256 / bytes / entries`；`tests/wp15-supply-chain.test.js` 会把「清单版本 ≠ 本地 Electron 版本」拦在门禁里。
- 目前**没有代码签名**（见安装说明，属成本决策）：校验和能证明「二进制来自官方发布」，证明不了「安装包是这个仓库构建出来的」——后者需要代码签名，长期看比上面两条都重要。

## 数据在哪

```
%USERPROFILE%\Documents\我的小说\   ← 书架目录（默认位置，可在设置里改）
├─ _trash\                       ← 回收站不可用时，删除的整本书移到这里（可人工找回）
├─ _碎片\                         ← 灵感箱：所有书共用的碎片速记，普通 txt，按日期编号
│  ├─ 2026-10-31-1.txt
│  └─ 2026-10-31-2.txt
├─ 星海旅人\                     ← 一本书 = 一个文件夹
│  ├─ 书目.json                  ← 书名、章节顺序、章名、章节状态/备注、作者/简介/分组/标签（可选）（唯一事实来源）
│  ├─ 书目.json.bak              ← 最近一次**结构性变更**（增删章 / 改名 / 分卷 / 导入）前的版本（json 写坏时用；普通保存不再每次覆盖它）
│  ├─ 001-未命名.txt             ← 创建序号 + 名字，文件名永不修改
│  ├─ 002-夜雨.txt
│  ├─ 003-未命名.txt
│  └─ _trash\                    ← 删除的章节、替换/整理/还原前备份、可选每日快照，不真删
│     └─ 快照-YYYYMMDD\          ← 只有开启「可选每日快照」后才有
└─ 另一本草稿\
```

应用配置单独存放在 `%APPDATA%\chapter-writer\config.json`（书架目录、窗口位置、全局显示设置、每本书的显示设置覆盖 `bookDisplay`（含**不可见字符 / 超长段落两个开关 `marksInvisibles` / `marksLongParagraphs`**、**超长段落阈值 `longParagraphThreshold`**）、**当前段落高亮的开关与颜色 `caretParagraph` / `caretParagraphColor`**、**中西文自动间距开关 `editorTextAutospace`（默认开，可按书覆盖）**、排版规则、上次导出的目录、书架顶部「继续上次写作」的 `lastBook` 记录、可选每日快照的 `snapshotEnabled` / `snapshotKeepDays`、可选崩溃恢复草稿的 `crashDraftEnabled`（默认关）、每日写作目标的 `dailyGoal`、写作时长开关的 `writeDurationEnabled`、章节模板的 `chapterTemplate`、敏感词表的 `sensitiveWordsPath`、校对词表的 `proofreadWordsPath`、导出简繁转换的 `exportConversion`、**查找书签 `findBookmarks`**）。**书的作者 / 简介 / 分组 / 标签不属于应用配置**：它们跟书走，只存在每本书自己的 `书目.json` 里（可选字段），换电脑 / 同步书文件夹时一起带走；**查找书签只记「书 + 章 + 查询词 + 大小写选项」，不存正文，也不跟着书文件夹走**。

每日字数统计单独存放在 `%APPDATA%\chapter-writer\stats.json`（按本地日期 + 书 id 记「保存时新增的正字数」，**绝不写进书架/书内**；文件坏了会归档成 `stats.json.corrupt-时间戳` 再从空统计继续，不影响正文）。**码字日历 / 连续写作天数 / 月度汇总都从这份统计现算**，不另存日历缓存、不新增配置字段；翻月只读。打开「记录写作时长」（默认关）后，同一天会多一个可选的 `seconds` 字段：**只记整秒、不记内容**；旧统计没有这个字段照常读，按 0 处理。

灵感箱的碎片就是书架根目录 `_碎片\` 里的普通 txt（不属于任何一本书，**不写 `书目.json`、不碰章节文件**）：每次保存生成 `YYYY-MM-DD-N.txt`（当天序号自动递增、不覆盖旧文件），UTF-8 无 BOM + CRLF。应用里只提供「记一条」和「插入到正文」（点面板里的「插入到光标处」，或者直接把碎片**拖进正文**），不提供删除；要清理请自己到 `_碎片` 文件夹处理（删除请走回收站）。

敏感词预检用的**词表是作者自己的 txt**（每行一个词），放在哪里都行，应用只在设置里记住路径（`config.json` 的 `sensitiveWordsPath`）。**应用不内置、不下载、不复制任何词表**，也从不改写词表文件：预检时只读它，按你的词表把命中的位置列出来，不改正文、不写盘。词表被移走 / 编码不对 / 是空文件时，面板会直接说明原因，不会误报。

校对面板可以再挂一份**自己的校对词表**（错别字 / 禁用词，和敏感词表是两份独立的文件，`config.json` 的 `proofreadWordsPath`）：每行一个词，也可以写 `错词 → 建议`（箭头 `=>` / `->` / `→` 都认，建议只用于显示），`#` 开头是注释。它**只参与「校对」面板**，只报告命中位置与建议，**绝不替你改字、不写盘、不改词表文件**；不设置也完全没关系（校对照常跑九条内置规则）。词表被移走 / 编码不对 / 是空文件时，面板照样给内置结果，只在词表状态行说明原因。

从 1.7.0 起还可以**挂多份校对词表**：`config.json` 的 `proofreadWordlists` 是一个数组（默认 `[]` = 沿用上面的单份 `proofreadWordsPath`；最多 8 份、每项必须是存在的绝对路径）。面板里逐份列出数量并单独开关（开关只对本次会话有效），也能在面板里添加 / 移除（添加 / 移除会立刻写配置）；旧配置的单份路径照旧生效。挂了多份词表时，「设置 → 校对词表」那一行改为显示份数与合计词数，单份路径框与「选择…」收起（多份都在写作页的校对面板里管理），保存设置也不会清掉配置里旧的单份路径。

朗读**不产生任何文件**：它只把编辑区里的正文交给 Windows 本地语音（Electron 内置的 speechSynthesis），不写配置、不写书库、不生成 `_trash`；语速 / 语音选择只在本次朗读小条打开期间有效，关掉就回默认。

编辑器小件的标记**不产生任何书库文件**：超长段落黄线、全角空格 ␣、行尾空白、**当前段落高亮**、选中字数、章节字数对比都画在编辑区上面一层影子层里（`renderer/editor-logic.js` 只算位置和数字），**不改正文、不改 `书目.json`、不改章节 txt、不生成 `_trash`**。其中「不可见字符 / 超长段落提示」两个开关、**超长段落阈值**和**「当前段落高亮」的开关 / 高亮颜色都按书记忆**：存在 `config.json` 的 `bookDisplay`（两个提示开关没单独设置过的书按默认关；阈值没设置过的书沿用全局默认 500；当前段落高亮与颜色没设置过的书跟随顶层全局默认），切换 / 保存设置只写 config.json，重启 / 换书都还在。**查找命中的淡琥珀色高亮**是另一层只读影子层（`#editor-find-marks`，窗口与片段由 `renderer/find-logic.js` 现算），只跟着当前这一次查找走，不改正文、不写书库；**查找书签**（v0.8-11b）按「书 + 章」把查询词与大小写选项存进 `config.json` 的 `findBookmarks`，打开这一章时按当前正文重新扫描并自动高亮，**不存正文、不记命中位置、不写书库**。

专注模式（连同它的「打字机」开关）**同样不产生任何文件**：它只是给写作页加一个 CSS class（隐藏左栏 / 分隔条 / 顶栏）并按需要调 `textarea.scrollTop`，不碰正文、不写 `书目.json`、不写配置；开关状态只记在内存里，退出 / 回书架 / 重启都回到普通布局。

诊断日志单独存放在 `%APPDATA%\chapter-writer\logs\`（每天一个 `chapter-writer-YYYY-MM-DD.log`，单份超过 256KB 自动换下一个序号，只保留最近 12 份）。**日志只记时间、错误类型、错误码、IPC 频道、文件名、应用版本和调用栈，绝不写任何正文**；本机绝对路径统一收成「`…\最后一节`」（栈里保留最后两节，`…\core\storage.js:395:11` 仍看得懂是哪一行），本机用户名 / 书库的上级目录不会落进日志（v0.9 C-4）。只在保存失败 / 主进程未捕获异常 / 未处理的 Promise / IPC 出错 / 渲染进程崩溃时才记一条，正常写作不产生日志；日志写不进去也绝不影响正文保存。设置 →「诊断日志」里有「打开日志文件夹」按钮，也可以直接在资源管理器里打开这个目录。删掉这些日志只会少一份排查记录，不动书库、不影响设置。**日志里除了错误码和文件名，也可能出现书名 / 章名**（它们不是正文，但仍是作品信息；v1.8.0 审计 ▲V310）：设置里的「诊断日志」分组已经放了提示，把日志发给别人（贴 issue / 群里反馈）之前请先自己看一遍。

**正文搜索索引**单独存放在 `%APPDATA%\chapter-writer\search-index.json`（不进书库、不写 `书目.json`、不动章节 txt）。它只记「每本书的双字哈希位图 + 每章的 mtime/size 指纹 + 书名/章名」，**不保存任何正文**（位图只回答「这本书里有没有这几个双字」，有误报、没有漏报；命中后再去读真实 txt 核对）。索引是自动维护的：打开书架 / 回书架 / 搜正文时校验，只有正文变过的书才重建位图，改章名 / 调顺序只更新元数据；删书 / 删章 / 外部改 txt 都会被下一次校验发现。索引文件坏了、版本不对或书架目录换了会自动重建；删掉 `search-index.json` 只是让下次打开书架重扫一遍，不影响书库和设置。索引写失败（磁盘满 / 没权限）只影响这一次搜索结果，绝不会挡保存、不会改正文。

**可选崩溃草稿**（默认关）的目录是 `%APPDATA%\chapter-writer\crash-drafts\`（`session.json` 运行标记 + `draft-<16位hash>.json` 草稿）：只有打开开关后才可能创建，只存**未保存的编辑区正文**，**不进书库、不写 `书目.json` / 章节 txt / `config.json`**。**这不是自动保存**：恢复出来的正文仍只在编辑区、要按 `Ctrl+S` 才写盘；干净退出会删掉运行标记与全部草稿（超过 7 天或超过 8 份的旧草稿也会清理）。默认关时**一个字节都不写**（不建目录、不建标记、不写草稿）；目录不可写（磁盘满 / 没权限 / 被占用）只回错误码并吞掉，不挡保存、不影响写作。

「检查更新」**不产生任何文件、也不写配置**：只有你在「设置 → 检查更新」里点按钮时，应用才会用 Electron 内置的网络请求访问一次 GitHub 的 Release 接口，比较版本号；发现新版本只显示版本号 + 一个「打开下载页」按钮（交给系统浏览器打开 GitHub Release 页）。**不会自动检查、不会下载安装包、不会安装、不会替换程序文件**；检查结果只在内存里，关掉设置或重启就没了。没网 / 超时 / GitHub 限流都只显示一句提示，正文编辑和保存完全不受影响。

**多窗口不产生任何文件、也不写配置**：同时开两本书时，主进程只在**内存**里登记「哪个窗口开着哪本书」（`windowId → bookPath`），关窗 / 回书架 / 切书时自动释放；书库、`书目.json`、章节 txt、`config.json` 都不会因为多窗口多出字段或文件。窗口位置 / 大小仍然只存在现有的 `windowBounds` 一个字段里，**只记最近使用的那个窗口**（下次启动按它恢复；第二窗口会在旁边错开一点打开）。

> `lastBook` 只记“上次写的是哪本书、哪一章、什么时候”，给书架顶部的「继续写」入口用；**打开书回到哪一章仍以书内 `书目.json` 的 `lastOpenChapterId` 为准**。删掉配置文件只会丢这些便利记录，不会动书库。

关键规则：

- **章节显示名 = 「第N章：名字」，N 由章节顺序现算，不写死**。插入/删除后章号自动重排。章号有两种编法（按书设置，2026-11-10）：默认**全书连续**；在写作页「设置 → 显示 → 章号」可选**每卷重新编号**（未分卷单独一组，也从第 1 章起）。设置写在 `书目.json` 的 `chapterNumbering`，旧书没有这个字段 = 全书连续、零迁移；目录（含**目录筛选**里的章号）/ 顶栏 / 状态栏 / 跳章 / 模板 `{n}` / 复制 / 导出文件里的章标题用同一份口径——按卷编号时筛选「2」「第2章」命中的是**各卷各自的第 2 章**，不是全书位置。**两个已知差异（本版只写清、不改语义）**：导出范围对话框的「第 X–Y 章」与书架「正文命中」里的章号仍按**全书顺序**显示——导出范围填的是全书第几章，书架搜索不读每本书的编号设置；它们和写作页按卷编号时显示的卷内号不同，原因见「已知限制」。标题栏 / 章节列表 / 阅读目录 / 校对结果和 TXT / EPUB / DOCX 导出、复制本章用的是**同一份规则**（`core/chapters.js` 的 `formatTitle()`，v0.8.6 R3）：原文已带号标题（`第1章 …` / `Chapter N`…）原样显示；楔子 / 序章 / 前传 / 外传 / 尾声 / 后记 / 番外 / 终章 / 大结局 / 附录 / 开篇等不带号特殊标题（2026-11-10 起）补「第N章：」；空名章只显示「第N章」，书目里若有自定义 `titleTemplate` 界面也按模板显示（模板缺 `{num}` / `{name}` 时特殊标题回落默认，避免把原词或章号吞掉）。
- **插入章节只改 `书目.json` 记录，不重命名任何文件**。所以文件名前缀是「创建序号」，不需要和显示章号一致。
- 章节 txt 里只有正文：保存后是 UTF-8 无 BOM、`\r\n` 换行，记事本直接打开不乱码。**从应用外拿到的 LF 换行 / 带 BOM 的 txt，在本应用里保存一次会被统一改写成这个格式（CRLF、去 BOM）**：用 git 等外部工具跟踪章节文件时，第一次保存会看到整份 diff，之后才回到逐行 diff（审计 V303）。**单本 txt 用默认的「按原文章节导入」拆章时，解析阶段就会去掉 BOM、把 CRLF / CR 统一成 LF，拆出来的章文件从导入那一刻起是 LF 的 UTF-8（第一次保存后才是 CRLF）**；「整本一章」的 UTF-8 源文件、含 `书目.json` 的章回书整本复制、「一本书的章节目录」导入仍按字节原样复制，不改行尾 / BOM（审计残留 #34/V303）。
- **章节状态（草稿 / 待修 / 完稿）和一句话备注只存在 `书目.json` 里**，是可选字段；标记状态、写备注**不会碰章节 txt 一个字节**，旧书目没有这两个字段也照常打开（默认草稿）。
- **书籍信息（作者 / 简介 / 分组 / 标签）也只存在 `书目.json` 里**，都是可选字段：只在书架右键「书籍信息…」保存时写入，空值不落字段；**不分组的书、旧书完全不受影响**。分组 / 标签只是书架视图和搜索用的元数据，**不改书文件夹名、不动章节文件**，旧书目不会因为打开 / 保存就凭空多出这些字段。
- **阅读模式不产生任何文件**：正文只通过只读的 `chapter:load` 从磁盘读，字号 / 行距 / 阅读位置只记在内存里（本次运行，重开应用回到默认）；不进 `_trash`、不写 `config.json`、不改 `书目.json`，也不会把「看完哪一章」存成书签。
- **章节模板只存在全局配置 `chapterTemplate` 里**（一段纯文本，默认空 = 不套用）：新建 / 插入章节时把展开后的文字填进**编辑区**，**不自动写盘**——和手打一样，按 `Ctrl+S` 才保存、`Ctrl+Z` 可撤销；不写 `书目.json`、不改章节文件名、不生成 `_trash`。旧配置没有这个字段照常启动，按「没有模板」处理。
- **`书目.json` 顶层有 `schemaVersion`（当前为 1）**：旧书没有这个字段也照常打开；打开不会为了补版本号而写盘，等下次正常写盘（改名 / 保存 / 改状态）时才补上（首次扫描补字数缓存也会写一次书目）。比本应用新的版本号会原样保留，不会被旧版应用写成旧格式。
- 改名（书名、章名）只改 json，文件夹名/文件名都不动。
- 同步盘（OneDrive / 坚果云等）两边同时改过时，书文件夹里可能出现 `书目 (conflicted copy 1).json`、`001-起风-冲突副本.txt` 这类**冲突副本**。书架会在书卡上标黄提示，点开能看文件名并打开书文件夹；**应用只提示，不自动合并、不删除，也不把它们当成章节**（从目录重建书目时同样会跳过）。
- **书内 `_trash` 是备份区**：替换、整本整理、还原前、删除章节的备份都在这里，加上书文件夹根部的最近一次结构性变更前 `书目.json.bak`，统一在「本书历史」里查看。面板只**读**备份；还原前会先把书里现在的内容再备份一份到 `_trash\还原前备份-时间戳\`。除了**开启每日快照后**按保留天数清理应用自己生成的 `快照-YYYYMMDD` 目录，其它备份不会被自动清理。

## 怎么用

| 操作 | 方式 |
|---|---|
| 新建书 | 书架 →「＋ 新建一本书」 |
| 导入小说 | 书架右上「导入小说」，选一个或多个文件夹。先选导入方式：**按原文章节导入（默认）——按原文的「第X章 / 第X幕 / 第X话 / 楔子 / 番外 / 后记 / 附录」等标题拆成多章，章名照抄原文、正文一字不改（支持上百字的长标题和奇怪标点写法）**；或「整本一章」——不拆章，整本放在一章「全文」里（UTF-8 源文件按字节原样复制）。三种来源自动识别：① 章回书（含 `书目.json`）整本复制；② 一本书的章节目录（txt 名如 `001-xxx.txt`）合成一本书；③ 一堆独立小说 txt（一个放满小说 txt 的文件夹）→ 每个 txt 一本书。自动识别 UTF-8 / UTF-16 / GBK 编码；只复制不移动源文件；重名自动加 `-2`；大批量导入显示进度；**没有任何章节标题且超过 6 万字的长文会自动按段落切片**（约 5 万字一段，章名「第 1 部分 / 第 2 部分…」，正文一字不改） |
| 删除小说 | 鼠标移到书卡右上角「⋯」→「删除这本书…」，或右键书卡 → 删除。整本书移到 Windows 回收站（回收站不可用时移到书架 `_trash`），不会真删 |
| 打开书 | 点书卡；如果 `书目.json` 损坏，卡片会标红并提供修复 |
| 书籍信息（作者 / 简介 / 分组 / 标签） | 书架右键书卡（或右上角「⋯」）→「书籍信息…」：可以填作者、分组、标签（逗号 / 顿号分隔，最多 10 个）和简介（可多行）。保存后书卡会显示「作者：…」「分组：… · #标签」和两行简介；书架上方出现**分组 / 标签筛选**（两个下拉，选项带计数：全部分组（N）/ 未分组（N）/ 各组（N）、全部标签（N）/ #标签（N）；两者与搜索词一起按 AND 生效）。点筛选条右侧的**「管理分组…」**可以给分组**改名 / 合并**（大小写与首尾空白归一，能对上已有分组就并进去；目标留空 = 移到未分组），书卡右键还有**「移到分组…」**：点开在菜单里直接选已有分组（每项带「· N 本」、当前分组打勾，末尾还有「未分组」和「新建分组…」），选完只改这一本；分组按名字排序、不另存顺序，改名 / 合并只写每本书的 `书目.json` 的 group，书签与「继续上次写作」不受影响。书架搜索也能按作者 / 分组 / 标签命中。**只写这本书的 `书目.json`（可选字段），不改书文件夹名、不动任何章节 txt**；留空保存 = 清掉该字段。旧书没有这些字段照常打开、不会自动补 |

> **字数口径（X3）**：全应用的「正字数」都按 **UTF-16 码元**计（与 JavaScript 的 `String.length` 一致）——普通汉字 / 英文 / 标点算 1 字，**emoji 与扩展区汉字（如 `𠮷`，U+20000 以上）算 2 字**。状态栏、章节列表、书架统计、导出 / 复制摘要与各处阈值共用这一个口径；含大量 emoji 时字数会比作者的「字符数」偏大，这是统一口径的已知取舍。

## 查找替换与章节排序

**查找替换**（右上「查找」或 `Ctrl+F`）—— **字面量**查找，不搞正则（`.*` 就只是三个字符），避免误伤全稿：

- 范围「当前这一章」：只算编辑区，不写盘；替换只改编辑区（未保存），`Ctrl+Z` 可撤销。
- **上一处 / 下一处 + 结果持续高亮**（`v0.8-11`）：当前章查找后，本章**所有命中**都在正文上用淡琥珀底色高亮、正在看的那一处颜色更重；面板里「↑ 上一处 / ↓ 下一处」、查找框里 `Enter` / `Shift+Enter`、关掉面板后 `F3` / `Shift+F3` 都能前后跳（到末尾 / 开头会绕回，摘要里会说明），状态栏的「查找 3/12」小标签点一下也是下一处。`Esc` 清除高亮。高亮**只跟着这一次查找**：改正文、改查找词、改大小写 / 范围、切章、回书架或离开写作页就自动结束；不写配置、不写书库、不改正文。命中太多（超过 **500 处**）时正文里只高亮**当前附近的一屏**（导航仍对全部命中有效，单章上限 5000 处），摘要会说明。
- **从整本查找跳进某一章**时，那一章的命中也会自动全部高亮，接着按 `F3` 继续跳。
- **「替换这一处」**（只用于当前章）：只替换光标处的这一处，替换完自动选中下一处，可以连续按；改的只是编辑区，`Ctrl+S` 才写盘。整本范围下这个按钮不执行，避免误以为只改一处。
- 范围「整本书」：点「查找」列出命中的章节和上下文片段，点一条就跳到那一章并选中第一处。
- 「全部替换（整本）」：**先弹确认**（几章、几处），确认后才写盘；写盘前把改动的原章节**备份到书内 `_trash\替换备份-YYYYMMDD-HHMMSS\`**。
- **整本替换点错了可以退**：替换后打开「查找」面板，下方会出现「最近一次整本替换的备份」→ 点「还原到替换前…」，二次确认后把备份覆盖回书里；并且还原前会先把**当前内容**再备份一份到 `_trash\还原前备份-时间戳\`（所以还原这一步也能回头）。只还原最近一次替换；更早的备份在 `_trash` 里可手动拷回。
- 整本替换前如果有未保存的修改，会先问「保存 / 不保存 / 取消」，不会静默丢掉。

**章节拖拽排序**：

- 左栏按住章节上下拖动，松手生效；拖到最上面/最下面会自动滚动。
- 只改 `书目.json` 的顺序：**章节文件不移动、不改名**，内容和文件名的对应关系不变。
- 显示章号（第N章）按新顺序现算，所以拖完章号会自动重排。

## 整理与显示（写作页右上「整理 ▾」/「显示 ▾」）

排版功能参照同类写作软件常见的「排版设置」补齐：智能排版（文字级）+ 字体 / 间距 / 背景（显示级），两半互不干扰。v0.8.5 起顶栏拆成两个按钮：**「整理 ▾」管文字**（点一下直接整理本章，悬浮出选择卡），**「显示 ▾」管显示**（点一下展开菜单）。

**1. 智能排版（改 txt 内容，仅当前章）** —— **点「整理 ▾」就直接整理当前这一章**（用上次记住的规则，不弹窗）；想改规则就从悬浮选择卡进「排版设置…」：

| 选项 | 默认 | 说明 |
|---|---|---|
| 段首缩进 | 缩进 2 字符 | 三选：**缩进 2 字符**（先去掉原有行首空白，再统一加两个全角空格 `　　`）/ **缩进 0 字符**（只去掉缩进）/ **不处理缩进**（保留原样） |
| 段落之间 | 空一行 | 四选：保持原样 / 空一行 / **空一行（含缩进）** / 不空行（紧凑）。**所有模式都会丢掉正文开头的空行、结尾连续空行只保留一个**；「保持原样」保持的是段与段之间的空行数 |
| 删除每行行尾空白 | 开 | 只删行尾的空格、制表符、全角空格 |
| 中文旁边的半角标点转全角 | 开 | `, . ; : ! ?` → `，。；：！？`；**只在中文旁边转**，`3.14`、`www.a.com`、`12:30`、`A.开端` 这类不动 |
| 直引号转中文弯引号 | 关 | `"…"` → `“…”`；**只在中文语境里转**，英文撇号（`don't`）、英文引语（`"Hi"`）、`他叫"Jack"` 这类不动 |
| 省略号 | 关 | 连续 3 个以上英文句点 → `……`；数字（`3.14`）、网址（`www.a.com`）里的点不动 |
| 删除中文之间的多余空格 | 关 | 可能改变语感，默认不勾 |

- **空一行（含缩进）**：空行里放两个全角空格（`　　`）。有些平台/软件会吃掉纯空行，粘过去就粘成一坨；带缩进的空行不会丢（口袋写作把这个叫「解决粘贴后丢失空行」）。
- **首尾空行不在「保持原样」的范围内**：源文开头的空行在整理时一律丢掉；结尾有一处换行就保留一个换行，连续多个尾随空行会被收成一个。这个行为对所有「段落之间」选项都相同（排版对话框里也有一句说明）。
- **引号 / 省略号两项默认关**：改了会动正文标点，所以不默认打开，由你在对话框里勾；勾选框旁边有说明，预览里会给出转换数量。
- 对话框里先看**预览和改动统计**（几段、缩进几段、删几处空白、转几个标点、转几个引号/省略号），确认后才套用；直接点「整理」则是**上来就整理**，结果用右下角提示告诉你这次的规则和改动统计。
- **整理 ≠ 保存**：结果只进编辑区，窗口标题 / 状态栏仍是**未保存**，按 `Ctrl+S` 才写盘——和本应用「完全手动保存」一致。
- **可撤销**：`Ctrl+Z`，或悬浮「整理」→「撤销上次整理（可撤销 N 步）」。撤销同样只是改编辑区，不会写盘；内存快照最多 50 步，关掉应用后不可撤销。
- **没有可改的地方就不动**：点「整理」时提示「本章已经是整理后的格式，没有可改的地方」（带这次的规则），正文一个字不动，撤销栈也不会多塞一步；对话框里「套用到本章」与实时预览面板用的是同一句结论（文案只从 `renderer/format-ui.js` 来，单测会拦「渲染层又自己拼一句」）。
- **只处理当前章**，不会碰别的章；章名、`书目.json` 一概不动。
- **光标不会乱跳**：整理/撤销后光标按原位置映射回同一段落，长章里接着写不会插到全章最前。
- 重复整理是安全的：已经整理过的正文再整理一次不会重复加缩进、不会重复转引号。

**整本一起整理：悬浮「整理」→「一键整理本书…」**（显式写盘动作，v0.4 起）

- 规则直接沿用点「整理」用的那套（也就是「排版设置…」里定下的规则），不用重新勾。
- 先做**预检查（只读）**：统计全书共几章、其中哪几章会被改动，一个字节都不写。
- 弹确认框，列清「规则、共几章、哪几章会改、写盘前会先备份」，点「开始整理」才真正执行。
- 写盘前把**要改动的原章节**复制到书内 `_trash\整理备份-时间戳\`；没改动的章既不备份也不重写（所以反复点也不会越备越多）。
- 逐章原子写盘，右下角显示「正在整理整本书：N/M 章」；整理完自动重载当前章、同步书架字数。
- **当前章有未保存修改会先问**：「保存后整理 / 不保存（按磁盘内容）/ 取消」。
- 已经是整理后格式的书再点一次**不会弹框**，只提示「没有可改的地方」。
- **整本整理不进「撤销上次整理」**：它是直接写盘的显式动作。要退回只能把 `_trash\整理备份-时间戳\` 里的 txt 手工拷回书文件夹（应用内还没有「一键还原整本整理」）。

**2. 正文显示（一字不动）** —— 「显示 ▾」→「显示：紧凑 / 标准 / 宽松」，或「设置」里细调：

| 项 | 可选值 |
|---|---|
| 正文字体 | 宋体 / 黑体 / 楷体 / **自定义字体文件**（.ttf / .otf / .ttc，选一次即可；只读取、不复制文件） |
| 字号 | 16–24 |
| 行间距 | 1.6 / 1.8 / 1.95 / 2.2 / 2.4 |
| 字间距 | 0 / 0.02 / 0.05 / 0.08 em |
| 左右边距 | 16–120 px |
| 正文宽度 | 通栏（默认），或 720 / 800 / 840 px 居中（840 ≈ 39.6 字，落在中文排版推荐的单行 17–40 字内；1.3.0 起 900 / 1000 下线，旧配置里的这两个值照常显示、不被改写） |
| 中西文自动间距 | 开（默认）/ 关；中文与英文 / 数字之间由系统自动留出细微间距，**只影响显示，不改正文、不进导出**（1.3.0） |
| 背景主题 | 原纸白 / 米黄（护眼）/ 豆绿（护眼）/ **夜间（深色）** / 牛皮纸（纹理）/ 网格纸（纹理） |

- 这些只改 CSS，**不写任何正文**；设置里改动会实时预览，点「取消」恢复原样，点「保存设置」才记住。
- **按书记忆**（v0.3 起）：书架右上「设置」改的是**全局默认**；在写作页里用「显示：紧凑 / 标准 / 宽松」、「正文显示设置…」或拖章节栏改的，只记在**当前这本书**上，换书会自动切回那本书自己的设置。写作页设置弹层底部有「恢复本书默认」，点了就回到全局。「显示 ▾」里的「不可见字符 / 超长段落提示」和「当前段落高亮」三个开关、**超长段落阈值**、以及高亮颜色也一样按书记住（只写 `config.json` 的 `bookDisplay`）。
- 自定义字体只记住文件路径：**换电脑或挪走字体文件后会自动退回宋体**，重新选一次即可。
- 夜间主题是新配的一套深色纸色 + 浅色墨色，不影响你的 txt。

> 说明：正文是纯文本 textarea，「视觉上的段首缩进」不能只靠 CSS 做，所以缩进是作为文本真的写进 txt 的（这也是导出/复制后仍然整齐的原因）。背景图片 / 背景特效 / 主题色 / 会员主题这些口袋写作里的附加项没有做（纯文本编辑器不需要，也避免往书库里塞图片文件）。

## 防丢稿设计（当前保证）

> 完整的逐轮改动记录（25–82 条，v0.8.5 起）已归档到内部文档（`内部文档/归档-2026-11-15/沿革.md` 的「防丢稿设计逐轮记录」）；下面只列当前生效的保证。

虽然不做自动保存，但底层仍然为「不丢稿」做了这些：

1. **所有写盘都是原子写**：临时文件 → fsync → rename（失败重试 3 次）。不会出现写一半的半截文件。
2. **`书目.json` 每次写入前保留上一版 `.bak`**：json 写坏可以从上一版恢复。
3. **删除不真删**：章节文件移到 `_trash\{时间戳}-{原文件名}`。
4. **未保存状态四处可见**：窗口标题前 `*`、状态栏橙点、保存按钮高亮、章节名后 `•`。
5. **三处拦截**：切章、关窗、返回书架，都会先问。**导出 / 复制不拦**：当前章未保存的内容会直接拼进导出结果（不写盘），导出完仍保持未保存状态。
6. **关窗保存失败会阻止退出**：弹「返回保存 / 放弃修改退出」，不会静默关掉。
6b. **破坏性动作都能退一步（1.4.0；1.5.0 起可连退最近 3 步）**：删除章节、跨卷移动、移到卷、删除卷、一键整理本书、整本替换、
    还原到替换前、本书历史还原，都改成「直接执行 + 左下角撤销条」——**10 秒内**点「撤销」或按 `Ctrl+Z`
    就退回去（撤销资源来自各动作自己写的 `_trash` 备份，不额外存一份）。撤销条按后进先出留最近 3 条：
    撤销一条后条子换成更早那条，`×` 或没有弹层时按 `Esc` 收起；连做第 4 步会顶掉最旧一步并提示
    「上一步（…）的撤销已被新动作替换」。撤销失败（文件被占用等）条子会留着可再点，但不会重新续满 10 秒。
    **1.5.0 起撤销前会核对备份没变**：还原到替换前 / 本书历史还原 / 整本整理的撤销，登记时记下那份
    `_trash` 备份的目录名 + 文件数 + 最新修改时间；10 秒窗口里这份备份被外部增删或改写，就提示
    「备份已变化，撤销取消」并早退（不拿变了的备份覆盖正文）。
    弹确认框的只剩两处：**未保存拦截**（切书 / 关窗 / 还原前先处理没写盘的字）与**删除整本书**（整本进回收站，应用内没有还原通道）。
7. **外部修改检测 + 保存前置校验**：窗口重新获得前台时比对**当前章**的 mtime —— 没变不打扰；有未保存修改只 toast 警告；否则问「重新加载 / 保留我的」。其它章不主动查，打开时才核对（`renderer/statusbar-ui.js` 的 `setupExternalChangeWatch`）。保存链路另带 `expectedMtimeMs` 前置条件：载入 / 上次保存回执记下 mtime，保存前磁盘上的 mtime 已经变了就抛 `EXTERNAL_CHANGE`、**一个字节都不写**，界面给「取消 / 放弃我的修改并重载 / 仍然覆盖保存 / 先另存一份」四选（`saveCurrent({ force: true })` 才跳过校验；判定在 `core/open-books.js` 的 `verifySaveTarget`）。
8. **损坏恢复**：`书目.json` 坏了，可以从 `.bak` 恢复，或按目录里的 txt 文件名重建书目（损坏文件改名为 `.corrupt-时间戳` 保留）。
9. **保存失败不更新「已保存」状态**：状态栏红字显示具体错误。
10. **整本替换前自动备份**：改动的原章节先复制到书内 `_trash\替换备份-时间戳\`，再原子写盘；应用内可「还原到替换前」一键退回，还原前还会把当前内容再备份一份到 `_trash\还原前备份-时间戳\`；这些备份不会被自动删（每日快照是唯一例外，见下一条）。备份目录名精确到秒，**同一秒内连做两次替换会自动加 `-2`**（两份备份各存各的，不会互相覆盖）。**1.5.0 起还原读盘前先验大小**：还原到替换前 / 本书历史还原读备份文件前先看 `stat.size`，单文件超过 128 MB（与导入上限同一口径）就明确拒绝 —— 不读进内存、不建还原前备份、一个字节都不写。
11. **配置坏了不会悄悄回默认**：`config.json` 损坏时会先归档成 `config.json.corrupt-时间戳` 再回默认值，并在界面上提示一句（否则书架路径会突然变回「文档\我的小说」，像书全丢了一样）。
12. **可选每日快照（默认关）**：开启后每次保存前把当天第一次的上一版复制到 `_trash\快照-YYYYMMDD\`，同章每天一份、只增不覆盖；按保留天数清理时只删**名字严格是 `快照-YYYYMMDD`** 的目录，别的备份 / 文件 / 乱写目录一律不碰。快照失败不会阻塞保存，最多在保存结果里带一句原因。**1.5.0 起单章正文超过 128 MB 时直接跳过快照并写明原因（不把整份读进内存）**。
13. **每日字数统计不写书库**：只把「保存时新增的正字数」记到 `%APPDATA%\chapter-writer\stats.json`（按本地日期 + 书 id）；不统计未保存内容，删字不倒扣，统计读写出错只影响数字显示，**绝不阻塞正文保存**。每日目标是可选的全局设置（0 = 不设）。**码字日历 / 连续写作天数 / 月度汇总**都从这份统计现算（`core/stats.js` 纯函数），不另存日历缓存、不新增配置字段；日历只读，翻月不会写 `stats.json`。**写作时长**（默认关）只在你手动点「写作计时」时按实际经过时间累计整秒，只记秒数、不记内容，和字数存在同一份 `stats.json` 的 `seconds` 可选字段里；关掉后主进程直接忽略上报，不写盘。**按书 / 按年筛选**只是主进程在读取时用 `aggregate` 现算一份汇总（`stats:get` 多收一个可选 `filter` 参数），不改 `stats.json` 结构、不新增配置字段 / IPC 频道，也不缓存汇总结果；CSV 只生成文本（BOM + CRLF）供复制，落盘要新增写盘通道，留给作者拍板。
14. **校对只报告、不改正文**：都在 `core/proofread.js` 里算（纯函数），半角标点判定直接复用「排版」的 `convertPunct`，不会各判各的；当前章用编辑区里的最新内容（未保存也算），整本逐章**只读磁盘**。校对不写任何 txt / 书目、不生成 `_trash`，点结果只是选中正文位置。第六条「自定义词表」来自你自己的一份 txt（`core/glossary.js` 只读解析；可写「错词 → 建议」，`#` 开头是注释），和敏感词表是两份独立文件；没有词表时九条内置规则照常跑，词表有问题只在状态行提示。
15. **碎片独立存放、绝不覆盖**：灵感箱的碎片写在书架根目录 `_碎片\`（纯 txt），文件名按本机日期 + 当天最大序号 + 1 生成，写盘走原子写，**不会覆盖已有碎片**；不写 `书目.json`、不碰章节 txt，也不在书架上冒充成一本书。插入碎片只改编辑区（`Ctrl+Z` 可撤销），原碎片永远保留；应用不提供「用后删除」。
16. **敏感词预检只读你的词表、只报告**：词表是你自己的 txt，应用不内置、不复制、不改写；预检只读词表 + 只读正文（当前章可用编辑区未保存内容），不写任何 txt / 书目、不生成 `_trash`。词表路径存在 `config.json` 的 `sensitiveWordsPath`，删掉配置只会忘掉路径，不会动词表文件。
17. **朗读只说不动**：正文只在渲染层读给系统语音听，主进程只做纯文本切分（`core/tts.js`，不读盘、不写盘）；发声全程不改编辑区、不改 `书目.json`、不生成 `_trash`。一改字、一切章、一回书架或按 `Esc` 就立刻 cancel，不会拿着旧段落继续念。语速 / 语音选择只在本次朗读小条打开期间有效，不写配置。
18. **编辑器小件只画不写（三个开关的按书记忆、超长段落阈值与当前段落高亮颜色除外）**：超长段落黄线、全角空格 ␣、行尾空白标记、**当前段落高亮的底色与左侧细线**、选中字数、章节列表字数对比都只改显示层——标记画在 `pointer-events: none` 的影子层里，**正文不改一个字节、不写书库、不改 `书目.json`**。其中「不可见字符 / 超长段落提示」和「当前段落高亮」三个开关、**超长段落阈值**（默认 500，50–20000）**都是按书记忆的可选显示设置**，按书存在 `config.json` 的 `bookDisplay`（两个提示开关没设置过的书按默认关；阈值没设置过的书沿用全局默认；当前段落高亮的开关与颜色没设置过的书跟随顶层全局默认），保存设置时只原子写 config.json，**绝不碰正文 / 书目 / 章节文件**，旧 config 没有这些字段时照常启动（两个提示开关关；阈值 500；当前段落高亮按其全局默认；颜色跟随主题）。颜色只认 `#rgb` / `#rrggbb`，写坏了回落主题色；自定义色由 `core/caret-color.js` 换算成淡底 + 细线用的 rgba（有单测）。章节列表的字数来自 `书目.json` 的字数缓存（保存时更新），标记层的位置每次从编辑区实测字体 / 行高 / 宽度算，不写死也不会错位到正文之外。当前段落只按「光标落在哪一行（一个非空行 = 一段）」现算，不缓存、不写盘。正文超过 **30 万字**时整层标记直接不建（`renderer/editor-logic.js` 的 `marksTooLarge` 门控，正好 300000 字仍然画），只提示一次——不会为了几个标记去重建整章 DOM 镜像；正文 / 保存不受影响。
19. **专注模式只收起面板、不碰内容**：它只给写作页加一个 CSS class（隐藏左栏 / 分隔条 / 顶栏）并调 `textarea.scrollTop`，不改正文、不写 `书目.json`、不写配置；「打字机」开关只记内存。进入时只把焦点交回编辑区，不改变窗口大小、不进 Windows 全屏；退出时按「光标行顶端 - 滚动位置」还原视线，正文变宽导致换行变化也不会跳错位置。
20. **错误日志不含正文、也不挡写作**：日志只记元数据（时间、错误类型、错误码、IPC 频道、文件名、应用版本、栈），`core/logs.js` 只接受这些字段，还会把连续 24 个以上汉字当正文隐去、把本机绝对路径收成「`…\最后一节`」（见内部归档沿革第 37 条）；保存失败 / 主进程异常不会让应用退出（先让你 `Ctrl+S` 保存），写日志本身失败（目录被占用、磁盘满、没权限）只吞掉，绝不阻塞保存正文或弹出错误。日志文件按天 + 按大小滚动、只留 12 份，只删本应用命名的 `chapter-writer-*.log`，不碰日志目录里别的东西。
21. **正文搜索索引只读、不含正文**：索引存在 `%APPDATA%\chapter-writer\search-index.json`，不写书库、不写 `书目.json`、不动章节 txt；文件里只有「双字哈希位图 + 每章 mtime/size 指纹 + 书名章名」，**没有任何正文句子**。搜正文时只读章节 txt 来核对命中并截上下文，不改一个字；索引读写失败只让这一次搜索降级（显示为空 / 提示），绝不挡保存、不挡书架。删掉索引文件只损失「下次搜索要重建」这点时间。
22. **多窗口不会互相覆盖、也不会重建影子文件**：主进程用「窗口 → 打开中的书」登记（**只在内存**）做唯一事实来源：同一本书**只允许一个窗口打开**（再点只聚焦已有窗口），别的窗口正开着的书**禁止删除 / 改名 / 整理 / 整本替换 / 导入覆盖**（明确提示先关 / 先切窗口）。每次保存正文前都要校验「书文件夹、书目、章节记录、章节文件」都还在（且书不在别的窗口），任何一项失效就**报错阻止写盘**；保存用的原子写关掉了 `mkdir` 兜底，**绝不重建目录 / txt**，不会出现「另一个窗口删了章，这边一保存又长出一个不在书目里的影子 txt」。窗口之间有独立的编辑区 / 脏状态 / 关闭询问，关一个只关一个，最后一个关掉才退出。
23. **查找高亮只画不写**：当前章查找后，全部命中画在 `#editor-find-marks` 只读影子层上（和编辑器小件共用同一套「按编辑区实测字体 / 宽高对齐、跟着滚动」的逻辑），当前那处只切一个 class，**不重画正文、不改正文**；「上一处 / 下一处」只移动选区与滚动。命中超过 **500 处**时只画当前附近一屏，导航仍覆盖全部命中（单章上限 5000 处，`findMatchesAll` 会明确回报是否被上限截断）；绕回 / 窗口 / 正文切片 / 行号都在 `renderer/find-logic.js` 里，有单测。会话只记内存：改正文、切章、换书、离开写作页就结束，`Esc` 也能清除，不写配置、不写书库。
24. **查找书签只记查询条件、不记正文**：书签按「书 + 章」存 `config.json` 的 `findBookmarks`（`core/bookmarks.js` 负责清洗 / 按「书 + 章」去重 / 增删，有单测），每条只有 `bookId` / `chapterId` / `query` / `caseSensitive` 与几个显示字段（书名 / 章名 / 章号 / 书路径）+ 时间戳，**没有正文、没有命中位置**。打开这一章时由渲染层按**当前编辑区正文**重新扫描并高亮（正文改过也能重新定位；改到没有命中时高亮收起、书签保留）；面板里可以列出本机书签、跨书跳转、删除。存 / 跳 / 删全部走主进程的只读 IPC + 原子写配置：**绝不写书库 / 书目 / 章节文件**，渲染层仍然没有 fs 权限；旧 config 没有这个字段 = 没有书签，照常启动。最多 200 条，同一「书 + 章」只保留一条（再存 = 更新查询词 / 大小写）。
25. **可选崩溃草稿只写 userData、只用于崩溃恢复（默认关）**：**这不是自动保存**。「设置 → 数据安全」里打开后，写作页有未保存修改时每 30 秒把编辑区正文原子写进 `%APPDATA%\chapter-writer\crash-drafts\`（单条最多 500 万字、最多 8 份、超过 7 天自动清理），**绝不写书库 / `书目.json` / 章节 txt / `config.json`**；渲染进程崩溃重载或上次异常退出后，启动时逐条弹一次「恢复 / 丢弃 / 先留着」，恢复只把正文放进编辑区（仍为未保存状态，`Ctrl+S` 才写盘），当前编辑区已有未保存修改时不覆盖。干净退出删运行标记与全部草稿；目录不可写（ENOSPC / EPERM / 被占用）只回错误码、不抛、不挡保存；默认关时**一个字节都不写**。

### 测试与静态闸门策略（X14，不强制削减）

- **静态闸门是有意的防漂移锚点，不强制削减**：`tests/` 里约 289 处「读源码 / 读 index.html 再断言字符串」的用例钉的是接线与口径（脚本加载顺序、唯一实现、IPC 频道清单、文案逐字、状态字段声明、UI 与 core 同源等）。它们防的是「改一处忘了另一处」这类行为测试覆盖不到的漂移；本版只要求新增静态闸门有明确事实源，不为了数量好看去删或批量替换。
- **新增功能优先写行为断言**（真实调用入口、比对结果）；只有「跨文件接线 / 唯一实现 / 顺序 / 逐字文案」这类行为上无法稳定观察的东西才用静态闸门。
- **闸门变红先分辨原因**：是回潮就修代码；结构确实变了就同步改闸门、注释与事实源，**不许批量删除或用正则放宽到永远通过**；同一事实只留一条闸门（单测与 E2E 不重复钉同一句）。
- **静态闸门分两类，新增的必须标类（2026-11-16 定口径 / 审计 #27-M2）**：**政策类**＝钉产品与工程决策的接线事实（打包配置与 fuse、开关默认值、IPC 白名单与频道清单、脚本加载顺序、唯一实现、逐字文案、主题令牌与允许清单）——这些事实要打包后或真实 Electron 里才观察得到，本地 `node --test` 看不到，所以用静态闸门；**行为类**＝能用真实调用稳定观察的行为（输入→输出、错误码、状态迁移），必须写 `node --test` 行为用例。新增闸门请在测试名或紧邻注释里标「政策类 / 行为类 + 事实源」，以后按类评估，不再逐个文件争论。
- **现有读源码闸门的逐文件分类与「行为迁」分批迁移暂不做**（审计 M2 建议的瘦身）：它需要先由作者确认「政策类」边界，且与上面两条（不强制削减、不许批量删除 / 放宽）一致；本轮只落分类定义与新增规则 —— 既有闸门**一条不删、一条不放宽**。

## 已知限制（仍有意不做）

- 安装包**未签名**：首次安装 Windows SmartScreen 会提示「已保护你的电脑」，点「更多信息 → 仍要运行」即可；自动更新只做了**轻量版**（手动检查 → 打开 GitHub 下载页），**没有自动下载、自动安装、后台静默升级，也没有代码签名**，升级仍需你自己下载安装包覆盖安装
- **Electron 安全开关之外的残余风险（v0.9 C-1 审计结论，本阶段只记录不修改）**：页面仍用 `file://` 加载（没有换成自定义协议），打包配置**已开** `enableEmbeddedAsarIntegrityValidation` 与 `onlyLoadAppFromAsar` 这两个 fuse（`grantFileProtocolExtraPrivileges` 未显式关，仍是 Electron 默认）——它们只有打包后才验证得出来，本阶段按约定不打包，发版时由打包后的冒烟检查覆盖；`Ctrl+Shift+I` 只在**开发 / 自检构建**里能打开开发者工具（**打包后的正式版已不绑定**，见 2026-11-05 审计整改；窗口开着 `sandbox` + `contextIsolation`，里面同样没有 Node 能力）。这些都不改变「渲染层没有文件系统权限、正文只能由主进程按既有校验读写」这条主线
- **路径校验的剩余边界（v0.9 C-2 / C-2b 审计结论）**：①书文件夹如果本身是**符号链接 / 目录联接**并指向书架外，文本路径判定拦不住（要先有人在你自己的书架上造出这种链接）；②`config:set` 里的 `booksRoot` 与两份词表路径现在只认**主进程自己弹出的对话框刚选中的那个**（来源校验见第 35 条），所以设置里的「书架目录」输入框改成只读——改目录请点右侧「选择…」，行为与提示跟以前一致；③来源校验按**字符串等价**判断：如果你先在对话框里选了 `D:\书架`，再手动写出它的子目录 `D:\书架\子目录` 当书架，会被当成「来源不明」忽略（重新点「选择…」选一次即可）；④改坏了也只是读不到，不会写坏书库
- **目录联接书库（2026-11-06 拍板）**：书架根目录可以是指向别的盘 / 别的目录的**目录联接**（Windows junction）——列书、打开、读章、保存都照常走真实目录，「整个书库放在别的盘、用联接挂进来」这种用法**受支持**，并由回归用例 `tests/junction-library.test.js` 钉住（防止以后的路径规范化改动把它弄坏）。代价是应用**不做 realpath、也不校验符号链接指向**：安全边界依赖本机文件系统权限（只有你自己能在这台机器上造链接）；同一个物理书库用两个不同路径名打开时会被当成两本（正常从书架入口打开不会发生——书架永远只用配置里那一个书库路径）。另一条现有边界：**书文件夹本身**若是联接，书架列举只认直接子目录，它不会自动出现在书架（路径已知时仍能读章 / 保存）；要让它自动出现属于行为变更，本版未做（见 `下一阶段提案.md` §6）。
- **2026-11-05 审计整改后的四条边界**：①`config.json` 只认已知字段——手动往配置里塞的未知键在加载 / 保存时会被丢弃（旧配置缺新键照常打开、自动补默认值）；路径字段（书架目录 / 两份词表 / 编辑器自定义字体）只认「原值 / 设置里刚用「选择…」选中的那个」，其它来源一律忽略并留一条日志。②`font:read` 先 `realpath` 再按真实路径校验 `.ttf` / `.otf` / `.ttc` 与 24MB 上限；按书 / 全局配置解析出的本机绝对路径**不再回传给渲染层**。③打包后的正式版**不认** `--e2e` / `--bench` / `--contrast` / `--screenshot` 这些自动化开关（自检频道不注册、窗口与关闭流程都走正常路径）；安装版冒烟用的 `--user-data` / `--books-root` 与 Chromium 自己的 `--remote-debugging-port` 保留。④关窗放行由主进程按「自己掌握的未保存状态 + 最近一次保存成功回执」交叉判定，界面单方说「可以关」不再足够；「不保存退出」会在界面侧先如实清掉脏状态再放行
- **错误文案 / 日志脱敏的两条边界（v0.9 C-4 审计结论）**：①界面与日志里的本机绝对路径只留最后一节（`…\001-第1章.txt`）——**文件名仍在**（书里的章节文件名本来就带章号，看得出是哪一章；书名只在文件夹名里，已经不会出现）。分享日志 / 截图前扫一眼仍然是好习惯。②「设置」里看到的书架目录、词表路径是你自己选的那几个配置值（设置界面需要显示），它们**不会**被脱敏；脱敏只作用于错误提示、状态行与诊断日志。原始英文错误信息（`EPERM: operation not permitted, open '…'`）只留在本机日志里，界面上看到的是中文结论 + 文件名
- **导入 / 导出的两条边界（v0.9 C-3 审计结论）**：①「导入小说」的单本 txt 上限是 **128 MB**（纯文本小说远到不了：1000 万字中文约 30 MB）；超过会提示体量并跳过，**不会先读进内存**。把图片 / 程序改名成 `.txt`（含 NUL 字节）或没有 BOM 的 UTF-16 会被当成「不是纯文本」拒绝；UTF-8（含 BOM）/ 带 BOM 的 UTF-16 / GBK 照常识别。整本书文件夹导入与「一本书的章节目录」导入也是**原样复制、不读正文**，但从 1.6.1 起复制前逐 txt 过同一条 128 MB 闸门（V25）：超限的单个文件不复制、记进导入结果的「跳过 N 个」汇总，其余文件照常导入，整批不中断；现成书形态里被跳过的那一章会从复制出的书目里去掉，不留打不开的悬挂章节（单章特别大时，打开那一章的编辑体验仍受 30 万字标记层上限保护）。②EPUB / DOCX 的 zip 条目名**只用本应用生成的 ASCII 名字**（`OEBPS/text/chapter-0001.xhtml` / `word/document.xml` 这种），书名 / 卷名 / 章名只进正文——所以包里的文件名与书名无关（用阅读器 / Word 打开看到的内容才是书名），这是长期设计，现在由 `core/zip.js` 的条目名闸门强制保证：以后谁把作者输入拼进条目名，会直接在导出时报错，而不是产出解压时能把文件写到包外面的包
- **默认拆章导入对「部 / 集 / 篇 + 无分隔符 + 直接接字」按正文处理（审计残留 #50/E15）**：为了不把「第一部电影…」「第三集播出后…」「第一篇论文…」误切成章，这类行不会当标题；代价是「第一部风起」这类无分隔符短标题会被并进上一章正文 —— 真标题请用空格 / 冒号分隔（「第一部 风起」「第一部：风起」），或把「第一部」单独写成一行
- **单章 128 MB 读取闸门的三条边界（1.5.1 H6 起，1.6.1 R3 补齐）**：① 编辑区打开超限章一律 `CHAPTER_TOO_LARGE`，不整份读进内存；② **书架扫描的字数回填**（含「从目录重建」后缺 `chars` 的章、老版本书目）先 `stat` 再读，超限章跳过、字数保持未缓存、书照常列出且**不标「书目损坏」**，下次扫描再试；③ **「还原到替换前」刷字数**只重算本次真正还原的章（不再整本重读），超限章同样跳过。三者共用 `MAX_CHAPTER_READ_BYTES = 134217728` 与同一套 `readSizeProblem` 文案；扫描的全局并发上限 **≤ 8**（外层 4 × 内层 2），1000 章的书不再 96 路同时读盘。④ **整本查找 / 替换 / 排版预览 / 整理**（1.6.1 R4 起）遇到超过 128 MB 的章**跳过并汇总**：超限章不读盘、不写盘，结果里多一个可选 `skippedTooLarge`（跳过章数），界面提示「有 N 章超过 128 MB，本次已跳过（文件没动）」，**不整批失败**；导出与校对仍按章读正文，碰到超限章会照旧明确报错（这两条路径本轮没动）。
- **IPC 参数上限（v0.9 C-5 审计结论）**：渲染层交给主进程「一次算完」的数据有硬上限——**正文 500 万字**、**查找词 / 替换词各 1 万字**、**替换结果约 2000 万字**（按「原文 + 命中 × 增长」估算，不先生成字符串）、**Ctrl+G 章节列表 2 万条**（超出只取前 2 万条）、编辑区未保存内容（override）同样 500 万字；超过时回固定错误码 + 中文提示（如「正文太长（5,000,001 字，最多 5,000,000 字）」）。这些值远高于正常写作（一章通常几千到几万字），碰到只可能是手误或注入脚本；被拒的调用**不写盘、不改书目、不留 `_trash`**。**单章正文超过 500 万字时**排版 / 查找 / 替换 / 校对 / 朗读会提示太长（`Ctrl+S` 保存与编辑本身不受影响，作者自己的正文永远原样写盘）；**`chapter:save` 同样受这条 500 万字上限约束**（2026-11-05 审计 E6 补齐；正常一章远到不了），导入（写作者自己的整本文件）不在这一层的限制里。导出范围 / 覆盖内容沿用「坏形状降级」的旧口径（非对象 range 当全书、越界收紧到 1–总章数；override 形状不对当没传），只有非文本 / 超长正文会报错。另有一条边界：整本替换入口限制替换词 1 万字、单章命中上限 5000 处，极端输入下单章最多多出 5000 万字——正常换词 / 换句远到不了，且整本替换必须先确认、写前备份到 `_trash`

- 每日字数统计按**本机本地日期**归天（跨时区/手动改系统时间会记到另一天）；`stats.json` 只保留最近约 400 天，更早的日期在下次记录时清掉（不影响书库）。目标只有**全局一份**，写作页按书设置里不显示目标/柱状图/日历
- **码字日历只读最近约 400 天**的统计：更早的日期在下次保存时被清掉，日历翻到更早的月份会是空格子；连续写作天数也只看这段窗口。日历按**周一开头**，翻月不记录「上次看到哪个月」（重开设置回到本月）。「连续 N 天」按当天有没有正字数算：今天还没写时连续天数先保留（从昨天往前数），到第二天仍没写才会断；只在本机时区算，手动改系统时间可能让连续天数看起来不对
- **写作时长默认关**，只有你自己点「写作计时」才累计：忘了点开始 / 忘了暂停，数字就不准（它是手动秒表，按实际经过时间算，不做「检测到打字才计时」）。计时中最小化 / 窗口被挡、或者离开电脑却没暂停，这段时间也会算进去——离开前记得点一下暂停（回书架 / 换书 / 关窗会自动停表）。时长按本机本地日期归天，跨午夜的那一轮可能把不到 30 秒算到次日；单日上限 24 小时（坏数据也夹住）
- 写作时长只按天合计，**不按书 / 不按章节分开**，也不和字数目标联动；「连续写作天数」仍按「当天有保存的新字数」算，只计时不存字的日子不算连续。计时只在你点暂停 / 按保存 / 每 30 秒 / 回书架 / 关窗时把整秒写进 `stats.json`（每 30 秒一次是为了少写盘），应用被强杀最多丢不到 30 秒；上报失败只影响统计数字，不影响写正文
- 自定义字体只记路径、不复制字体文件：换电脑、挪走/删掉字体文件后会自动退回宋体；字体文件只由主进程按「刚在对话框里选的 / 当前书的显示设置 / 全局设置」这三种路径读取，**渲染层不能指定任意路径**（v0.8.6 R4，代码审计 F1）
- 查找是**字面量**查找，不支持正则/通配符（`.*` 只是三个字符）
- 书架搜索的**正文部分**是**字面量、不区分大小写**：不做正则 / 通配符 / 繁简转换 / 同音字 / 拼音；正文至少 **2 个字**才搜（一个字不搜）。结果按「书 + 章」分组，组头显示本章真命中数（单章计数上限 10000，超过显示 `N+`）；默认每章最多列 3 处，「展开本章全部」只读目标那一章、单章最多返回 200 条（更多时明确提示只列出前 N 处），一次整搜最多 40 条；常见两字词可能命中很多书，这时只查**最近修改的 60 本**并标「只查了最近的一部分书」，单次搜索约 1.8 秒预算（超出先返回已有结果；展开一章同样受时间预算保护，但不受整次 40 条限制）。书名 / 章名过滤仍然是输入即出的内存过滤。**结果里的章号按全书顺序显示**——书架不读每本书的编号设置，所以按卷编号的书在这里显示的是全书第几章，与写作页目录里的卷内号不同（本版只写清这个已知差异，不改显示语义）
- 正文索引是**每本书一份双字 Bloom 位图 + 每章 mtime/size 指纹**（存在 `%APPDATA%\chapter-writer\search-index.json`，280 本约 20MB），只用来「筛掉肯定没命中的书、再读真实 txt 核对」：位图有误报、**不会漏报**。索引里**没有正文句子**，所以不能当全文预览或离线备份用；索引里会存书名 / 章名 / 章节文件名 / mtime/size（分享索引文件前留意一下书名章名）。索引总量有 **32 MB** 预算（审计修复 #33）：超过时按书目最后修改时间从旧到新丢掉整本书的位图（**章节指纹保留**，不是把书从索引里删掉），被丢掉位图的书以后每次搜索都逐章核对——**只慢一点，结果不会少**；正文变过 / 换书架根时位图会重新建；预算是**尽力而为**：若超限时所有书都已没有可丢的位图（只剩章节指纹），索引仍照常写出（不为了凑预算删指纹），读侧另有 64 MB 兜底、超限按空索引重建；每章指纹是 mtime/size + 首尾各 4 KB 内容采样，只改文件中段且保留大小 / 修改时间的改写不会被指纹发现（要等大小 / mtime 变化或重建索引，审计残留 #R20）
- **首次打开书架会在后台建索引**（280 本 / 3256 章约几十秒），界面上有「正在为书架建正文索引 N/M 本」；建好前书名 / 章名搜索照常可用，正文结果建好后自动补上，**不需要作者手动点任何东西**
- 索引校验分两档：**回书架 / 启动时**逐章 stat 校验（约 10 秒节流，用来发现外部改过的 txt），**每次搜索**只做轻量的书目校验（约几十毫秒，不拖慢输入），距上次逐章校验超过 1 分钟时顺带做一次兜底。在别的编辑器里改过 txt：回一次书架或等约一分钟再搜就能看到；应用里按 `Ctrl+S` 保存会**立即**标记这本书重建索引。改章名 / 删章 / 删书同样由下一次校验发现。索引文件损坏、版本不对或书架目录换了会自动重建；删掉 `search-index.json` 只会让下次多扫一遍
- 搜索结果点一条只是**打开那一章并选中命中位置**（只移动光标 / 选区 + 滚动，不改正文、不会替你保存；当前章有未保存修改时照常询问）。「展开本章全部」也只在主进程读目标那一章、把命中片段交给界面，界面不读整章正文、不写盘。搜索全程只读：不写 `书目.json`、不改章节 txt、不生成 `_trash`
- 搜索时章节 txt 被别的程序占用 / 刚好被删掉，这一章会跳过（结果可能少几条），不会让整次搜索失败；索引写不进去（磁盘满 / 没权限）只影响下次重建，不挡保存和搜索
- 拖拽排序本身仍是「按住一章上下拖」（一次只拖一章）；要一次移动多章请用多选批量条的「移卷」（多选目前只在**章节列表**里，书架书卡还没有多选 / 批量动作）
- 多窗口同时编辑两本书已支持（书卡右键「在新窗口打开」），但仍是**同一个应用进程里的两个普通窗口**，不是标签页：没有「窗口分组 / 合并窗口 / 窗口间拖拽」，关掉窗口后也不能从应用内恢复「上次开了哪些窗口」（每次启动只开一个窗口）。**同一本书禁止同时开两个窗口**（会互相覆盖未保存内容），再点只聚焦已有窗口
- 跨窗口保护是**按「打开中的书」登记**做的：别的窗口正开着的书，不能从当前窗口**删除 / 改书名 / 改章名 / 删章 / 整理 / 整本替换 / 导入覆盖**，会提示「请先关掉另一个窗口，或先切换到那个窗口」。如果你在应用外（资源管理器 / 同步盘）把书文件夹或章节 txt 删了 / 改名了，另一个窗口再按保存会**报错阻止写盘**，不会偷偷 mkdir 重建一个「影子 txt」或影子书文件夹；这时请回书架刷新，或把文件放回原位
- 多窗口**共用同一份全局配置**：书架 →「设置」里改全局显示设置后，已经开着的其它窗口不会实时换装（重新打开书 / 重启后生效）；按书的显示设置（`bookDisplay`）、章节栏宽度仍只影响对应书。窗口的未保存状态彼此独立，A 窗口的「保存 / 不保存」不会动 B 窗口的编辑区
- **书籍信息（作者 / 简介 / 分组 / 标签）是纯文本的可选字段**：作者 ≤ 80 字、分组 ≤ 40 字、简介 ≤ 1000 字（多行会保留换行、合并多余空行）、标签最多 10 个、每个 ≤ 20 字（逗号 / 顿号 / 分号分隔，重复的自动去掉），超长会被截断；分组是**精确匹配**的一个名字，不做二级分组 / 分组重命名 / 批量改分组，也不会按分组移动或重命名书文件夹。分组筛选只记在**本次运行**里（重开应用回到「全部分组」），且只影响书架显示；书架搜索按作者 / 分组 / 标签是**字面量、不区分大小写**，不做拼音 / 同音字
- 书籍信息只在书架右键「书籍信息…」**显式保存**时写盘（原子写，只改 `书目.json` 和上一版 `.bak`），不会因为打开书 / 保存正文而自动补字段；书目损坏的书要先走「修复」才能改书籍信息。别的窗口正开着这本书时，当前窗口保存书籍信息会被拒绝并提示（和删除 / 改名一样的跨窗口保护）。书卡简介最多显示两行，鼠标悬停可看全文
- 书架自动刷新只发生在**正停在书架的窗口**：写作页里的窗口不打断你（避免一边写一边看到书架跳动），回书架时会自动刷新；别的窗口改了同一本书的情况已经被「同一本书不开两个窗口」挡住
- 「上次窗口位置 / 大小」只有**一份**（最近使用的窗口），第二窗口的位置不会单独记住；关机 / 注销时的未保存拦截是**每个窗口各问一次**的尽力而为（Windows 不强等应用，可能来不及）
- 章节状态只有**草稿 / 待修 / 完稿**三档（不做自定义状态、不按状态筛选/排序）；备注是一条 ≤200 字的一句话，不做多行便签、不进正文、也不参与搜索
- 复制本章（平台格式）**只复制正文、不含章名**，排版固定按「段首缩进两格 + 空一行（含缩进）」，不跟随「排版设置…」对话框里记住的规则（不改标点 / 引号 / 文字）；空章不覆盖剪贴板
- 范围导出（全书 / 按卷 / 第 X–Y 章）**TXT / EPUB / DOCX 都支持**，但「复制整本到剪贴板」始终是整本。按卷导出只列书里已有的卷（没分卷的书不显示这一项）；第 X–Y 章按**全书连续章号**算（按卷编号的书也一样：范围输入填的是全书第几章，不是写作页的卷内号；导出文件里的章标题才按卷内号），导入的原文标题章节也按序号排，不按标题里的数字。一次只能选一种范围（全书 / 某一卷 / 章节区间），不能「未分卷 + 某卷」拼着导
- **导出 / 复制里的「当前章未保存内容」（override）按章节 id 认章**：编辑区那一章还在书目里时，用它现取的内容替掉磁盘正文（返回 `includedUnsaved: true`）；如果那一章刚被删除、或编辑区已经换了书（传给主进程的 chapterId 在书目里找不到），TXT / EPUB / DOCX 导出与「复制整本」**不报错，直接按磁盘内容导出**（`includedUnsaved: false`；也不会拼进同名 / 同文件名的别的章）。只有单章动作「复制本章（平台格式）」找不到这一章时明确报「找不到这一章（可能刚被删除）」——它本来就是「复制这一章」，章不在就不能拿别的章冒充
- EPUB 按卷 / 按范围导出**只打选中的章节**：卷名页只生成选中章所在的卷，封面章数 = 本次导出的章数，按卷 / 按范围的副本使用**独立的 identifier**（阅读器不会把它当成整本书的另一个版本）；章标题按这本书的编号方式（默认全书连续；按卷编号时卷内从第 1 章起）。本书没有封面图，固定生成一页纯文字封面；不含插图、脚注等富内容，也**不跟随**「排版」对话框里记住的规则（固定「段首缩进 2 字 + 段间空一行」）。正文里的空行会合并成段间留白（不再单独输出空段落），所以习惯用空行分段的书，导出后段距是统一的
- **DOCX 导出是固定版式**：标题页（书名 / 作者 / 范围与章数）+ 卷标题 + 章标题 + 正文，正文段首缩进 2 字、1.5 倍行距、宋体；**不跟随**「排版」对话框里记住的规则，不含页码 / 页眉 / 目录域 / 封面图；正文里的空行会合并成段间留白，一章不拆文件，章标题按这本书的编号方式（默认全书连续；按卷编号时卷内从第 1 章起）。按卷 / 按范围只写选中的章（卷标题只生成选中章所在的卷）。导出全程只读；当前章未保存内容参与但不写盘；简繁转换只作用于副本（书名 / 作者 / 卷名 / 章名 / 正文一起转）
- 「继续上次写作」只记**最近一本书**（不提供历史列表 / 最近打开的书单）；入口显示的是记录时的章号，若之后在别处删过章，点进去仍以书内 `lastOpenChapterId` 为准（失效时回退第 1 章）。上次那本书被删掉或移出书架后入口自动隐藏，不会提示「书不见了」
- Ctrl+G 跳章只在写作页生效，只匹配**当前这本书**的章节名（不做拼音/模糊纠错，不搜正文、不搜卷名）；输入纯数字按全书连续章号算，超出范围只提示不跳转；跳章本身不写正文，但切章会更新书目里的「上次打开章节」
- 同步冲突副本只检测**书文件夹顶层**的 `*conflicted*` / `*冲突副本*` 文件：不扫描子目录、不处理「整个书文件夹被同步盘复制成另一个文件夹」的情况，也**不提供自动合并**（冲突内容可能都没合并过，自动处理风险太大）。提示只针对当前书卡，处理完手动移走副本、回书架刷新即可
- 校对**只报告、不改动**，没有「一键修正」：半角标点要改请回到写作页点「整理」（或选择卡「排版设置…」里先看预览）；重复用词 / 超长段落 / 连续标点 / 多余空行目前只能在正文里自己改。阈值固定（超长段落 500 字、重复用词 300 字内 3 次、连续标点 3 个），不做自定义开关；重复用词按「双字词 + 不重叠命中」算，相邻二字词（如「突然想起」）会归并成一条，常用词多出现几次也会列为疑似，不是判定错误
- 单章校对明细最多保留 400 条、面板一次最多显示 300 条（总数 / 各规则条数照实统计，可切成当前章分开看）；整本明细上限 1500 条，超出时提示「明细只列出一部分」。整本只读磁盘（当前章未保存内容按编辑区算），章节文件缺失的章会跳过
- 敏感词预检**只报告、不改动**，没有「一键替换成星号」；词表完全由你自己维护，应用不内置、不下载任何词表，也不判断「该不该屏蔽」。词表文件本身只读，应用不复制、不改写
- 敏感词匹配是**字面量、区分大小写**（不做正则、不做大小写折叠、不处理同音字 / 拆字 / 拼音）；同一处有多个词重叠时只报最长的那个。词表每行一个词，空行忽略、重复的词只算一次，一行超过 100 字视为误粘的正文跳过
- 词表上限 **4MB / 5000 个词**（超出部分不读，设置里会提示）；单章明细最多 500 条、整本明细上限 1500 条，面板一次最多显示 300 条，总数照实统计。整本只读磁盘（当前章未保存内容按编辑区算），缺文件的章跳过并提示
- 词表文件被移走 / 编码不是 UTF-8 / UTF-16 / GBK / 是空文件时，预检只给出明确提示，**不会退回「内置词表」**（应用根本没有内置词表）；删掉配置里的 `sensitiveWordsPath` 只会忘掉路径，不会动你的词表文件
- 校对词表是**可选**的，只参与「校对」面板（不影响敏感词预检），和敏感词表是两份独立文件；不设置时校对照常跑内置五条规则
- 校对词表每行一个词，可写「错词 → 建议」（箭头 `=>` / `->` / `→` 都认），`#` 开头是注释；空行和重复的词忽略，一行超过 100 字跳过，最多 4MB / 5000 个词
- 校对词表只做**字面量、区分大小写**匹配（不做正则 / 同音字 / 拼音 / 繁简转换），同一处多个词重叠时只报最长的那个；「建议」只显示在结果里，**不会自动改字**，也不写词表文件
- 校对词表文件被移走 / 编码不对 / 是空文件时，面板只在词表状态行提示，**内置五条规则照常跑**；删掉配置里的 `proofreadWordsPath` 只会忘掉路径，不会动词表文件
- **简繁转换默认「不转换」**，只在「设置 → 导出」里主动选「简体 → 繁体 / 繁体 → 简体」才生效，而且**只作用于导出副本**（导出 TXT / EPUB / DOCX）：书库里的章节 txt、`书目.json`、复制整本 / 复制本章、阅读 / 校对 / 朗读 / 统计全部**不转换**，原稿一个字节不动。它是导出动作的一部分，不写盘就不会影响书库
- 简繁转换用的是**内置常用字表**（简→繁约 900 字、繁→简约 1000 字）+ 常见歧义词纠正（发 / 髮、干 / 乾 / 幹、后 / 後、里 / 裡、面 / 麵、只 / 隻、系 / 係 / 繫、台 / 臺 / 颱、周 / 週、松 / 鬆、余 / 餘、谷 / 穀、舍 / 捨、志 / 誌、制 / 製、表 / 錶、历 / 曆、复 / 複 / 覆、钟 / 鐘 / 鍾、须 / 鬚、脏 / 髒 / 臟、赞 / 贊 / 讚……），**不联网、不装依赖、不读参考软件的数据**
- 转换**不做分词 / 专名 / 地名 / 人名表**：一简对多繁只取常用写法，常见例外由短语表纠正（头发 → 頭髮、干净 → 乾淨、皇后 → 皇后、乾隆 → 乾隆）；**歧义字宁可保持原样也不硬转**（只 / 系 / 面 / 余 / 谷 / 舍 / 志 / 制 / 表 / 松 / 向 / 周 / 采 / 游 / 折 / 征 / 致 / 占 / 注 / 卷 / 刮 / 胡 / 回 / 家 / 克 / 困 / 累 / 蒙 / 佣 / 秋 / 姜 / 郁 / 丑 单独出现时不转，常用词走短语表）。繁→简里「著」也只在常见动词短语里改成「着」（著作 / 著名 / 显著 / 乾隆 保持原样），所以导出后**请通读校对一遍**，不要直接上架
- 简繁转换**只换字形、不改长度**（逐字或等长词替换）：BOM、CRLF、标点、数字、英文、表情、空行、章节标题行结构都不动，所以字数统计不受影响；TXT / EPUB / DOCX 的**默认文件名仍用原书名**（不转），EPUB 与 DOCX 里的书名 / 作者 / 目录 / 章名 / 正文会一起转。没有「只转选中文字」「简繁字体切换」「按书设置」——它是**全局一份**设置，写作页的按书设置里不显示
- **导出范围对话框里的字数预览优先用书目里保存时算好的字数缓存**（每章 `chars`）：如果章节 txt 在应用外被别的程序改过、而这本书还没重新打开 / 刷新书目，预览字数可能暂时和磁盘正文略有出入（正式导出仍逐章读全文，文件名 / 章数 / 正文内容不受影响，重新打开书或回书架刷新后就一致）。当前章有未保存内容时，这一章按编辑区实时算，不用缓存
- 灵感箱的碎片是**所有书共用**的（放在书架根目录 `_碎片`，不按书分文件夹），只扫描 `_碎片` **顶层**的 `.txt`，不递归子目录，也没有标签 / 搜索 / 分组 / 批量整理
- **不提供「用后删除」**：插入碎片只改编辑区，原碎片永远保留；要清理请自己到书架根目录的 `_碎片` 里处理（删除请走回收站，应用内不会真删）
- 单条碎片写入上限 **10 万字**；从磁盘读取上限 **4MB / 20 万字**（超过会明确提示先拆分，不会把超长内容硬塞进编辑区）。列表一次最多显示 300 条，总数照实显示
- 碎片文件名按**本机日期** + 当天最大序号 + 1；删掉的号不回收（避免和回收站里的旧文件撞名）。你自己放进 `_碎片` 的 txt 也会列出来，只是没有日期 / 序号标识
- 插入位置固定为**打开「插入碎片…」面板前**的光标 / 选区；碎片不会自动加换行或空行，和上下文怎么衔接由你自己决定
- 朗读用的是**系统本地语音**（Windows SAPI，Electron 内置 speechSynthesis），不联网、不下载、不打包语音包；语音下拉里有什么取决于系统里装了什么，声音 / 音色由 Windows 决定（可在「设置 → 时间和语言 → 语音」里装更多）
- 朗读**只读正文**：不导出音频、不做字幕 / 逐字高亮 / 背景音乐 / 定时停止；「跟随高亮」只改编辑区选区（不改字），而且编辑区没有焦点时看不到高亮
- 语速（0.8×–2.0×）和语音选择**只在本次朗读小条打开期间有效**，不写配置；重新打开回到 1.0× + 系统默认
- 切分按**自然段**：一段超过 160 字按句末标点拆成几段再念；系统语音自己的断句 / 停顿由语音引擎决定，应用只保证不把字念漏
- 单章最多切 **5000 段**、正文超过 **100 万字**只念前面的部分（正常一章远小于这个数）；朗读中途改字 / 切章 / 回书架 / 收起小条会立刻停止，需要重新打开
- 「显示不可见字符 / 超长段落提示」两个开关**也按书记忆**（`config.json` 的 `bookDisplay`，没单独设置过的书默认关），重启 / 换书都还在；**「当前段落高亮」的开关和颜色按书记忆**（`config.json` 的 `bookDisplay`，没单独设置过的书用全局默认），重启 / 换书都还在。**超长段落阈值**同样按书：全局默认 500，写作页设置里改只影响当前这本书（`bookDisplay[本书].longParagraphThreshold`），书架设置里改全局默认（`longParagraphThreshold`）；没单独设置过的书回落全局默认。这些都只改显示层，只写 `config.json`，不碰正文 / 书目 / 章节文件
- 「当前段落高亮」按「**一个非空行 = 一段**」算（和朗读、`Alt+↑↓` 段落导航同一口径）：光标停在空行时不高亮；整段折成好几行时按行分别铺底；正文超过 **30 万字**（按去空白字数；原文超过 60 万字符也按超长处理，防空白灌水）时整层标记收起（不可见字符 / 超长段落 / 当前段落高亮都不画，只提示一次；`renderer/editor-logic.js` 的 `marksTooLarge` 门控），正文照常编辑 / 保存。默认「跟随主题」时高亮色 / 光标颜色跟着 6 套背景主题走；自定义颜色只认 `#rgb` / `#rrggbb`（色板 6 色 + 取色器），写坏了自动回落主题色。自定义色是**整章统一**的淡色底，不会按主题再调深浅；颜色 / 开关只作用于写作页，阅读模式没有当前段落高亮
- 「不可见字符」只标**全角空格（U+3000）**和**行尾空白**（空格 / 制表符 / 全角空格）：不标行内半角空格、换行符、零宽字符等其它不可见内容；纯空白行不标（避免整行泛色）；一次最多画 4000 个标记，正文超过 **30 万字**（按去空白字数）或原文超过 60 万字符时整层标记都不画（不可见字符 / 超长段落 / 当前段落高亮一起收起，只提示一次；30 万字以内三样照常）
- 超长段落阈值默认 **500 字**（按去掉空白后的字数，和「本章字数」同口径），可在「设置 → 正文显示设置 → 超长段落阈值」里改成 **50–20000**：写作页里改只影响这本书，书架设置里改全局默认；输入越界会夹到边界，留空 / 非数字保存时回落 500。黄线画在正文左边距里，左右边距调得很小时会贴着正文左缘
- 标记层是**画在正文上面**的一层只读影子层（不是富文本）：极少数情况下会和选区高亮叠在一起（字仍然看得清），它不参与编辑、不被复制、不会进导出，也不改 `书目.json` / txt
- **查找高亮本身仍是一次性的**：不点「存成书签」的话，它只服务当前这一次查找——改正文、改查找词 / 大小写 / 范围、切章、回书架或离开写作页就自动结束，不记历史、不写配置；关掉面板后 `F3` / `Shift+F3` 继续跳，`Esc` 清除。想保留就用面板里的「存成书签」（见下面一条）。整本查找只列章节清单，**点进某一章后**才高亮那一章，不会一次把整本书的命中都画出来
- **查找书签是「查询条件」不是「位置」**：按「书 + 章」只记查询词与大小写选项（最多 200 条；同一章再存 = 更新那一条），**不存正文、不记命中位置 / 上下文**；打开这一章时按**当前正文**重新扫描定位，所以正文改过、命中位置移动了也跟着走，改到没有命中就暂时不亮（书签还在，改回来或删掉即可）。书签存在 `%APPDATA%\chapter-writer\config.json`（和书库分开，删书 / 换书架不会跟着书走）；删除书签只删配置里这条记录，**不删章节、不动正文**；书签只在写作页生效，阅读模式没有
- 单章命中超过 **500 处**时正文里只画**当前附近的一屏**（500 处），导航仍对全部命中有效；单章命中上限 **5000 处**，到上限还多找出一处时会明确提示「命中太多」。当前命中同时是编辑区的系统选区（方便直接替换），所以会和蓝 / 灰的选中底色叠在一起；高亮层不参与选择、复制、导出，也不会写盘
- 章节列表的字数来自 `书目.json` 的缓存（打开书时补齐、保存后更新）：在应用外改过 txt 不会立刻变，回书架刷新 / 下次保存后才更新；「比上章短」只在上一章 **≥500 字**时提示，只是软提醒，不判断你是不是故意写短
- **专注模式只改应用自己的界面**：隐藏的是左栏、分隔条和顶栏，按 `F11` **不会**让 Windows 窗口全屏 / 最大化（窗口大小、标题栏都不变）；它只在写作页有效，书架页按 F11 不响应
- 专注模式的开关（专注 / 打字机）**只记在内存里**：回书架、切到别处或重启应用都回到普通布局；不会写进 `config.json`，也不按书记忆
- 「打字机」在**正文超过 30 万字**时暂停自动对齐（每次按键都去量光标位置开销太大），正文编辑 / 保存照常；正常一章远小于这个数
- 打字机对齐按**光标所在行**算（长段落自动换行后，光标在段中间就按那一行对齐），到章首 / 章尾会停在 0 / 最底部，不会滚出正文；它只调滚动，不移动光标、不改字
- 专注模式下顶栏按钮不可见，但快捷键照常可用（`Ctrl+S` / `Ctrl+F` / `Ctrl+G` / `Ctrl+N` / `Ctrl+Shift+C` / `Alt+↑↓`）；`Esc` 会**先**关弹层、停朗读（如果开着），**再**退出专注模式
- **阅读模式是只读视图**：里面没有编辑框 / 保存按钮，不能改字、新建章节或保存；顶栏的字号、行距只记在**本次运行**里，而且**按书各记一份**（换一本书回到默认档，回到这本书还是刚才的档位；重启应用都回到「大 / 标准」），不写 `config.json`，也不影响写作页的正文显示设置。阅读位置**只在本次运行内记一份**（按书分：退出阅读再进、换本书再回来，回到上次读到的那一章和章内位置；在编辑器里明确换了章则以编辑器当前章为起点），同样不写 `config.json` / 不改 `书目.json`，重启应用回到默认（从当前写作章开始）——所以它**不是书签 / 断点**，想从头读点「从头」
- 阅读模式**按章节连续滚动**：滚到接近底部自动接下一章，一次最多接 8 章（很多空章时避免一口气扫全书）；同时最多保留 40 章在页面上，再多只从最前面回收显示（不写盘、不影响书）。目录一次列出全书章节（**有分卷的书按卷分段**，卷名就是左侧章节栏里的那个卷名；单卷 / 没有分卷的书仍是平铺一串，外观与以前一样），特别大的书打开阅读时目录会稍慢
- 阅读模式显示的是**磁盘上的正文**：当前章如果还有未保存修改，阅读视图不会显示这些修改（顶栏会明确提示），退出阅读后它们仍在编辑区、照常可以保存。阅读不计入码字日历 / 写作时长（进入阅读会自动停掉写作计时）
- 阅读时章节文件被外部删掉 / 挪走，这一章会显示「读取失败」提示，**不会重建 txt、不会改书目**；把文件放回原位再重新进入阅读即可。阅读模式不检测外部修改（不会弹「外部修改」对话框）
- **章节模板是全局一份、只作用于新建 / 插入章节**：不做按书不同模板，也不会给已有章节补模板；模板上限 **2000 字**（超长截断），只有空白的模板视为没设置。套用后只是编辑区里的未保存内容，**不自动写盘**——按 `Ctrl+S` 才会进章节 txt，按 `Ctrl+Z` 可退回空章；如果模板展开后是空串（例如只写了 `{title}` 但章名为空），则不会套用
- 模板占位符只有 **`{n}`（章号，阿拉伯数字）/ `{title}`（章名）/ `{date}`（本机本地日期 YYYY-MM-DD）**，大小写敏感，别的花括号原样保留（不做 `{{` 转义、不做条件 / 循环 / 日期格式自定义）。`{n}` 没有章号上下文时也会原样保留，不会悄悄替换成空
- 章节模板**不跟随按书设置**：写作页「正文显示设置」里的设置只影响当前这本书，模板统一在**书架 →「设置 → 新建章节」**里改（写作页的设置弹层里不显示模板项）。设置了模板时导出 TXT / EPUB / DOCX 仍会自己加章节标题，模板里再写「第{n}章：」导出后会出现两遍，按需使用
- 错误日志**没有内置查看器 / 一键上传 / 一键清空**：设置里只有「打开日志文件夹」，要清空请自己删 `logs` 里的文件（应用下次出错会重新建）。日志目录就是 `%APPDATA%\chapter-writer\logs\`，删日志不会动书库和设置
- 日志按**本机日期**分文件（跨时区 / 手动改系统时间会记到另一天的文件）；单份超过 **256KB** 换下一个序号，最多保留 **12 份**，超出时删最旧的。只删名字严格是 `chapter-writer-YYYY-MM-DD[.N].log` 的文件，日志目录里其它文件一律不碰
- 日志只覆盖**主进程错误**：保存失败 / 主进程未捕获异常 / 未处理的 Promise / IPC 出错 / 渲染进程崩溃 / 窗口无响应。渲染层普通 JS 报错（DevTools 控制台里那种）不会自动进日志；`Ctrl+Shift+I` 的开发者工具报错也照常只在控制台
- 日志虽然只记元数据、还会把连续 24 个以上汉字当正文隐去，但**文件路径 / 章节文件名 / 书名**会出现在日志里（其中可能有你的书名、章名）。把日志发给别人排查前请自己先看一眼；日志里没有正文句子，但路径隐私要你自己判断
- 主进程未捕获异常时应用**不会退出**（先让你 `Ctrl+S` 保存再重启），界面只弹一句固定提示；这属于尽力兜底，如果异常反复出现，建议保存后重启应用，别在异常状态下继续写
- **检查更新只在手动点「检查更新」时联网**：启动、写作、切章、保存都不会自动访问网络，也没有「启动时静默检查」开关。检查失败不会重试、不会后台轮询，想再试就再点一次
- 更新检查走的是 GitHub 的 **Release 接口**：未登录时每小时最多 60 次（正常手点远不到）；被限流 / 被代理拦截 / 没网时只提示，不影响写作。GitHub 的「latest」接口通常只返回正式版，但如果仓库只有预发布版本，可能会拿预发布版来比较（会如实显示版本号，是否升级由你决定）
- 「打开下载页」只是用**系统默认浏览器**打开本仓库的 GitHub Release 页：应用**不下载安装包、不校验 SHA256 / 数字签名、不自动安装**，下载哪个文件、装不装、什么时候装都由你自己决定；下载页链接只接受 `https://github.com/ANAN1124-OSS/chapterly/releases...`，Release 数据里的其它链接会被丢弃
- 检查更新**不写配置、不写书库、不上传任何内容**：只发一次 GET 请求拿版本号（请求头只有 User-Agent / Accept），不发送书名、章节或正文；检查结果只记在内存里，关掉设置或重启就没了
- `书目.json` 的 `schemaVersion` 目前是 1，迁移函数是空的（为将来加字段留口子）；旧版应用读新版本书目时只会保留版本号、按已知字段尽力读，不保证能理解将来版本新增的字段
- 「Windows 关机拦截」是尽力而为：系统关机不强等应用，可能来不及弹提示
- **原子写会重试 3 次（间隔 80ms）后就报错**：正常写作里碰不到（同一个文件本来就被串行化：书锁 + 同一本书只开一个窗口 + 一次只保存一章），只有杀掉软 / 同步盘 / 备份软件长时间霸占目标文件时才会走到「保存失败」——这时磁盘上仍是完整的上一个版本，等占用结束后再 `Ctrl+S` 即可。极端情况下（同一路径十余路并发写同一个文件）重试会被争用耗尽，同样只报错、不写半截；这一条由 `tests/atomic.test.js` 钉住
- **每次保存都会重建章节文件（原子写）**：临时文件 → rename 覆盖目标，所以 Windows 上文件的**创建时间会被重置**，文件上的**自定义 ACL / 备用数据流（ADS）不保留**（权限通常继承父目录，书库放在自己的目录时感觉不到；书库放在共享 / 受控目录，或用「按创建时间归档」的备份工具时才可能注意到）。磁盘上永远不出现半截文件比保住这些元数据重要，这是有意取舍（审计 V304）
- **剪贴板捕获的边界（2026-11-07 单列表改造 + 漏记修复后）**：只取**纯文本**（剪贴板里的图片 / 富文本格式不会带进来）；面板一条复制记录只新建一章，不做批量拆章 / 自动分卷（要整本拆章请走「导入小说」）；单章正文上限 30 万字（按去空白字数，与界面「N 字」/ 队列同一口径），标题行（≤40 字）后正文 ≥50 字才把首行认成标题；整条不足 100 字时整条当章名（这种短标题允许超过 40 字，文件名仍按 40 字截断）；**记录口径：后台监听开着时，每次复制（非空白）都记一条，20 字门槛只控制「要不要弹轻提示」**；**点「正文」插入成功后该条也立即从队列删除**（2026-11-08 起与「章节」一致，失败保留）；轮询间隔 300ms，打开面板前会主动补读一次；全局快捷键 `Ctrl+Alt+V` 被其它程序占用时注册失败只写日志、不挡启动，界面上的「捕获」按钮照常可用；**队列只驻本次运行内存**（最多 50 条 / 单条 30 万字按字数 / 总量 300 万字按原文长度，超了淘汰最旧），**不落盘、不写日志、不做磁盘历史**，关闭监听或退出应用即清空；单条超上限（字数 > 30 万）会给一条明示提示，不再静默丢弃；捕获面板「正文」插入 > 2 万字时走整串赋值（快通道），代价是会清空浏览器撤销栈——可用提示条「撤销」或正文上第一下 `Ctrl+Z` 退回插入前；默认**不做后台全量记录**（剪贴板里可能有密码 / 验证码，后台监听必须由你在设置里主动打开）

## 无障碍（键盘 / 焦点 / 目标尺寸）

> 2026-11-08 · 1.3.0 起把无障碍从「只量对比度」扩到可执行的门禁。产品代码这一批**没有为此改动**（T8 只做工具侧），下面写清现在**已经做到什么**、**还差什么**、以及怎么自己验。

- **全部可交互元素都能键盘到达**：Tab 顺序 = 视觉顺序；书卡 / 章节列表 / 菜单 / 弹层各有方向键与 `Home` / `End`；`Esc` 收起弹层与菜单并把焦点还给打开它的元素；焦点环是 2px 朱红（只在 `:focus-visible` 出现，永不清除 outline）。章节排序的**拖动有键盘替代**：焦点在章节列表时 `Alt+↑` / `Alt+↓` 在本卷内挪一格（到卷边界再按一次跨卷，跨之前先确认）——满足 WCAG 2.5.7。
- **2.5.8 目标尺寸（≥24×24）**：`node scripts/a11y-gate.js` 在真实窗口里量所有可点元素的盒子。当前实测 **610 条全部达标**：小于 24×24 的那 16 条都走 WCAG 的「间距例外」（24px 圆不与相邻目标相交），**允许清单已清空**（1.4.0 把最后一条——书架搜索框右侧清除键 20×20——补到 24×24，搜索框右侧留白与按键位置一起微调）。**1.4.0 起设置弹层按 5 个分区各扫一遍**（分区一次只显示一个，不扫就等于把其余分区的控件漏出判据）；顺带量出码字日历的翻月按钮只有 20×24，已补到 24×24（只补宽度，不改字号 / 颜色 / 间距）。
- **2.4.11 焦点不被遮挡**：门禁在 16 个弹层 / 面板状态里逐个聚焦（设置弹层按 5 个分区各扫一遍），检查焦点框有没有被视口、滚动容器或上层元素（弹层背景 / toast / 悬浮条）盖住。当前 185 条焦点全部合格（1.4.0 起含设置弹层的 5 个分区）。
- **对比度**：6 套主题 504 条规格全过 WCAG 2.1 AA，另有 12 条禁用态豁免（`node scripts/contrast.js`）。APCA 只在门禁里当**影子参考**打印，不参与通过判定（APCA-W3 是非商业 Beta 许可，不内置进产品）。
- **3.3.7 不重复录入**（人工走查结论）：新建一本书只问一次名字（标题就是文件夹名），导入小说时**不再追问书名**；作者 / 分组 / 标签只在「书籍信息」里填一次，之后导出 / 复制都沿用；导出范围（整本 / 按卷 / 按章）只问一次，不会在下一步再问一遍。
- **怎么自己验**：`node scripts/a11y-gate.js`（或 `pnpm run a11y`；`--static` 只跑静态、`--report` 只报告不报错）。它只读：书库与 userData 都在系统临时目录，跑完不会碰你的书架，默认书架目录（「文档」下的 `我的小说`）一个字节都不动。
- 还没做到的（已知边界）：菜单没有挂 `role="menu"` / `role="menuitem"`（见「已知限制」里那条，是有意取舍，不是漏做）；书卡里套着「⋯」按钮的嵌套按钮语义仍是 1.4.0 之后的候选（目标尺寸已全部达标，允许清单为空）。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 书架是空的 | 书架目录里还没有书。一本书 = 一个文件夹，正文就是里面的普通 txt 文件（用记事本也能打开）；点右上「导入小说」把现有稿子导进来，或点书卡区右侧（或下面）的「新建一本书」从零开始，也可以直接把书文件夹放进书架目录 |
| 书架底部那行提示是什么、还会再出现吗 | 第一次打开应用、书架还是一本都没有时，书架底部会显示一条 **4 秒**提示，指向「＋ 新建一本书」和「导入小说」；出现一次就记住，重开应用不再出现。书架本来就有书的老用户升级上来不会看到它。它不写书库、不改书目，只在 `%APPDATA%\chapter-writer\config.json` 里记一个 `firstRunTipShown` 标记 |
| 窗口最上面那条是什么、怎么拖窗口 | 1.3.0 起窗口用的是**自绘标题栏**：原生标题栏去掉了，网页内容一直铺到窗口最上面，所以「书架顶栏 / 写作页顶栏 / 阅读页顶栏」本身就是**拖动区**——按住顶栏空白处（按钮以外的位置）就能拖窗口，双击顶栏空白处 = 最大化 / 还原。右上角的最小化 / 最大化 / 关闭仍是 **Windows 自己的按钮**（不是应用画的）：悬停最大化按钮照常出 Snap Layouts，`Win` + 方向键、双击最大化都和普通窗口一样；顶栏右侧给这三个按钮留了位置，所以按钮不会钻到它们下面。顶栏空白处**右键**会出窗口菜单（还原 / 最小化 / 最大化 / 关闭）；「移动 / 大小」仍用 Windows 自带的 `Alt+Space` 系统菜单。弹层（设置 / 整理 / 导出…）盖住顶栏时拖不动窗口，这是「不额外加一条标题栏」的取舍，关掉弹层即可。窗口变窄时写作页顶栏会自动折成两行，按钮一个不少 |
| 左下角那条「已删除…撤销」是什么 | 1.4.0 起破坏性动作改成**直接执行 + 10 秒撤销**：删章节、跨卷移动、移到卷、删除卷、一键整理本书、整本替换、还原到替换前、本书历史还原，做完左下角会出现一条提示 + 「撤销」按钮。**10 秒内**点它或按 `Ctrl+Z` 就退回去；10 秒后自动收起，只保留**最近一条**（新动作会顶掉旧的）。撤销用的都是这些动作自己写进 `_trash` 的备份（删章备份 / 整理备份 / 替换备份 / 还原前备份），不额外多存一份正文。焦点在正文 / 输入框 / 下拉框里时 `Ctrl+Z` 仍是**文本撤销**，不会被撤销条抢走；回书架、换一本书也会收起（撤销不会跨书执行） |
| 为什么有些操作还弹窗 | 只留了两类：**未保存拦截**（切书 / 关窗 / 还原前，先问你「保存 / 不保存 / 取消」，含保存失败后仍要退出的二次询问）和**删除整本书**（整本进 Windows 回收站，应用内没有还原通道）。另外三类是**选择**不是确认：导入小说（按原文章节 / 整本一章）、修复书（从目录重建 / 从备份恢复）、检测到外部修改（重新加载 / 保留当前）。除此之外的动作都不再弹确认框 |
| 窗口切到别的程序后，界面为什么暗一点、朱红变灰了 | 这是 1.3.0 的**非激活降级**：窗口失去焦点时，纸色整体压暗 2%、强调用的朱红降成低饱和的一档（6 套主题都做过对比度实测，仍满足 AA）；回到窗口立刻恢复。纯显示层：不写配置、不改正文、不影响保存，也不改变任何功能 |
| 保存成功后为什么不再弹右下角提示了 | 1.3.0 起保存成功的反馈收敛到底部状态栏左侧：圆点 + 「已保存 HH:MM:SS」，2 秒后整段淡到 60%（不消失；鼠标移上去或键盘聚焦回到 100%），不再弹 toast。鼠标悬停在「已保存」上能看到这次保存的完整摘要（章数 / 本章字数 / 今日快照 / 字数未计入）。状态栏中间是「第 N 章 · 本章 X 字」，窗口窄于 1040px 时这一段让位，保存态和今日字数 / 计时优先 |
| 保存失败除了红字还能怎么办 | 1.3.0 起保存失败时状态栏左侧是朱红的「保存失败：原因」，旁边会出现「重试」按钮——点它（或点朱红文字）就再存一次，和按 `Ctrl+S` 是同一条保存路径；失败原因消除前不会自动重试，也不会丢编辑区里的内容 |
| 章节栏是空的（这本书一章都没有） | 正常新建 / 删到空都会自动补一章；只有手改 `书目.json` 或从外部导入的书才会 0 章。点左下「＋ 新建章节」或按 `Ctrl+N` 开始写第一章；新章会自动套用「设置 → 新建章节」里的章节模板（填了才生效） |
| 「捕获」会一直记录我复制的所有东西吗 | **默认不会**。只有你按 `Ctrl+Alt+V` 或点「捕获」的那一下才读一次系统剪贴板；没有剪贴板历史、不写日志、不写配置。如果你在「设置 → 剪贴板联动」里主动打开**后台监听（默认关）**，应用运行期间约每 0.3 秒看一次剪贴板，**每次复制（非空白，短标题也算）都会在本次运行的内存队列里各记一条**（最多 50 条、单条 30 万字、总量 300 万字，超了淘汰最旧）——**不落盘、不写日志、不做磁盘历史**，关闭监听 / 退出应用即清空；≥20 字的新复制才浮一条「新复制 N 字，要捕获吗？」轻提示（点提示才开面板），短复制只记不提示。面板里不点「正文 / 章节」就什么都不写 |
| 复制了好几段，怎么分别变成章节 | 先在书架 →「设置 → 剪贴板联动」打开**后台监听（默认关）**：运行期间每次复制都会在内存队列里各记一条（只记本次运行，短标题也记）。然后按 `Ctrl+Alt+V` 或点顶栏「捕获」打开**列表**：每条记录旁边两个按钮——点「**正文**」把整条插进当前章光标处（不自动保存）；点「**章节**」直接用这一条新建一章（章名按「第X章标题行 / 不足 100 字整条当章名 / 否则自动第N章」三条规则，插入位置可选全书末尾或当前章之后）。**面板不会自己关**，可以接着处理下一条；**点「正文」插入成功或点「章节」写章成功后，该条记录都会立即从列表消失**（失败保留、可重试），「清空队列」只清内存、不删已建章节、不碰磁盘 |
| 想换书架目录，输入框里为什么不能手打 / 粘贴路径 | 书架 →「设置 → 书架目录」点右侧「选择…」在系统对话框里挑目录即可（输入框是只读的：保存时主进程只认**刚在对话框里选中的那个目录**，防止被注入的脚本让程序去读写别的盘；换目录不会移动 / 删除旧目录里的书）。词表路径同理，用各自旁边的「选择…」 |
| 书卡标红「书目损坏」 | 点开修复：从 `.bak` 恢复 / 从目录 txt 重建。不要自己删文件 |
| `pnpm start` 闪退、提示 `Cannot read properties of undefined (reading 'whenReady')` | 环境里有 `ELECTRON_RUN_AS_NODE=1`；确认用 `pnpm start`（走 scripts/start.js），或手动清掉该变量 |
| `pnpm start` 报「无法加载文件 …pnpm.ps1，因为在此系统上禁止运行脚本」 | Windows PowerShell 5.1 执行策略限制，与应用无关。改用 `pnpm.cmd start`、双击 `启动章回.cmd`，或 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 后重试（详见「安装与启动」） |
| Electron 下载很慢/失败 | 检查 `.npmrc` 的镜像；或 `pnpm approve-builds` 放行 electron 的 install 脚本 |
| 记事本打开 txt 是乱码 | 章节文件是 UTF-8 无 BOM；较老的记事本请升级到 Win11 自带版本，或用 VSCode 打开 |
| 保存失败 | 看状态栏红字：磁盘满 / 文件被占用 / 无权限。处理后再按 `Ctrl+S`，或直接点红字旁的「重试」；关窗时也会阻止退出 |
| 关窗时一直停在「正在保存」 | 保存真的卡住时，应用会等 **8 秒**再弹「编辑器无响应」（默认停在「继续等待」）。点「强制退出」也不会立刻硬关：先给编辑器一次收尾机会（约 0.5 秒）再关窗；编辑器已卡死时仍以已自动保存的内容为准（最后一点未保存的输入仍可能丢）。慢盘 / 大文件优先点「继续等待」 |
| 想回退到昨天的版本 | 应用**默认没有每日自动备份**（按作者要求）。可以先去「设置 → 数据安全」打开**可选每日快照**（默认关）：开启后每次保存会把当天第一次的上一版留在书内 `_trash\快照-YYYYMMDD\`，之后可在「本书历史」里预览 / 还原。没开过快照时，先看「本书历史」能找回的替换 / 整理 / 删章备份和上一版 `书目.json.bak`；更早的版本请从你自己的同步盘 / 文件历史记录里找 |
| 「本书历史」在哪、能看到什么 | 写作页右上「导出 ▾ → 本书历史…」，或在书架右键书卡 →「本书历史…」。它把书内 `_trash` 的**替换备份 / 整理备份 / 还原前备份 / 每日快照 / 删除章节**和书文件夹里的上一版 `书目.json.bak` 按时间新→旧列出来，标出每个文件还在不在书里，可以预览原文、还原单章或整组。**每日快照那一组默认收起**（点组头展开 / 收起，组头照样写日期、文件数和大小），其它备份组默认展开。**只读扫描，不改文件**；还原前会把现在的内容再备份到 `_trash\还原前备份-时间戳\` |
| 删除的章节能找回吗 | 能试：右键书卡 →「本书历史…」→ 找「删除章节」那一组 →「放回书文件夹…」。txt 会原样回到书文件夹，但**不会自动加回章节列表**（避免乱改章号）；确实要完整找回时，再用书卡的修复 →「从目录重建」按目录里的 txt 重建书目（重建会生成新的书目 id、丢掉状态/备注和按书显示设置） |
| 书目.json.bak 能一键还原吗 | 不能，本书历史里的书目备份**只供预览**：旧书目可能和现在的章节文件对不上，自动覆盖风险太大。书目损坏请在书卡上点「修复」→「从备份恢复」，那条流程会先把损坏文件改名保留 |
| 本书历史里的「还原整组」会删掉备份吗 | 不会。备份只读、不消耗，可以重复还原；每次还原前还会把书里现在的内容再备份一份到 `_trash\还原前备份-时间戳\`。除了每日快照按保留天数清理自己生成的 `快照-YYYYMMDD` 目录，其它备份不会自动清理，嫌多可以自己按文件夹名删 |
| 书架上的「今天 +N 字」怎么算的 | 只算你**按保存**（`Ctrl+S` / 保存按钮 / 建章前自动保存）时，这一章比以前缓存字数多出来的**正字数**：没保存的输入不算，删字/改短也不倒扣。所以刚打了一段还没保存时数字不会动，按一下保存才涨。统计只写 `%APPDATA%\chapter-writer\stats.json`，不碰书库 |
| 怎么写每日目标 / 进度条怎么看 | 书架右上「设置 → 写作统计」，填每日目标字数（0 = 不设目标，默认关）。设了目标后，写作页状态栏会出现「今日 N 字 / 目标 M 字」和一条细进度条；书架顶部也会显示目标百分比，达标后标「已达标」。设置里还能看近 30 天柱状图（今天在最右）。**写作页状态栏的「今日 N 字」点一下也能直接打开这份设置**（落到码字日历，见下一条） |
| 码字日历怎么看 / 颜色代表什么 | 书架右上「设置 → 写作统计 → 码字日历」，或**写作页状态栏点一下「今日 N 字」**（直接打开全局设置并定位到日历）：**周一开头**的月历，每月自动补空格对齐；格子里的数字是几号，**颜色越深表示当天保存的正字数越多**，绿点表示当天达到你设的每日目标，深色描边是今天，带斜纹的淡格子是还没到的日期。点「‹ / ›」翻到上一个月 / 下一个月（不会翻到未来），点「本月」回到当前月。下面一行是**月度汇总**（当前月显示「本月 N 字」，翻到过去月份显示「N月 N 字」）：合计、写了几天、日均、达标天数、最高一天；「连续写作 N 天 · 最长 M 天」是连续写作天数。入口只负责打开 / 定位：日历本身只读，不写 `stats.json`，点「取消」也不写 `config.json` |
| 连续写作天数怎么算、昨天没写会断吗 | 只认「当天有保存过正字数」的日期：**今天已经写了就从今天往前数；今天还没写就从昨天往前数**，所以白天还没动笔时连续天数不会提前断，到第二天仍然没写才会归零。书架顶部也会显示「连续 N 天」。最长连续按 `stats.json` 里最近约 400 天的记录算；手动改系统时间 / 跨时区可能让连续天数看起来不对 |
| 写作时长怎么开、会记录我打了什么吗 | 书架 →「设置 → 写作统计」勾「记录写作时长」（默认关），写作页状态栏就会出现「⏱ 写作计时」：点一下开始、再点暂停。它只把**实际经过的整秒**记到 `%APPDATA%\chapter-writer\stats.json` 当天的 `seconds` 字段，**不读正文、不记录按键、不分析内容**，也不写书库；关掉开关后主进程连上报都不接收 |
| 写作计时忘了暂停会怎样 | 它会按实际时间继续走：去倒水 / 接电话前点一下暂停（或者直接回书架 / 换书 / 关窗，会自动停表并记下）。计时中最小化窗口也会继续算——语义就是手动秒表，不做「检测到打字才计时」的自动判断；单日最多记 24 小时 |
| 今天写作时长为什么和预计的不一样 | 只有「点了开始 → 点了暂停」之间的时间才算，按整秒累计、按本机本地日期归天：暂停时不足 1 秒的零头会留到下次；回书架 / 换书 / 关窗会自动停表并上报（这时不足 1 秒的零头直接舍弃）。设置里显示今天 / 近 30 天，码字日历的当天格子悬浮能看到用时，不做饼图 / 导出 |
| 每日统计文件在哪、删了会怎样 | 在 `%APPDATA%\chapter-writer\stats.json`（不是书库）；删掉只丢历史统计，不影响小说和设置。文件坏了会归档成 `stats.json.corrupt-时间戳` 再从空统计继续，不会影响保存正文。旧版配置没有 `dailyGoal` 字段也照常启动（按不设目标处理） |
| 同时写几本书，今天字数怎么算 | 按天合计：今天所有书保存带来的新增字数都会加在一起；`stats.json` 里同时按书 id 分开记，删掉某本书也不会删掉它已经贡献过的当日字数 |
| 每日快照会自动帮我保存吗 | **不会**。快照只在你自己按 `Ctrl+S`（或建章前自动保存）时发生，跟着保存走：先留上一版、再写新正文。没按保存的内容仍然只在编辑区里，关窗前照常提醒 |
| 同一天改了十几次，快照会有十几份吗 | 不会。每章每天只留**当天第一份**（第一次保存前的上一版），后面再保存不会覆盖它；第二天再保存才会新建 `快照-新日期`。想找回当天更早的中间版本，目前只能靠 `Ctrl+Z` 或你自己的副本 |
| 快照会越积越多吗 | 会按你在设置里选的保留天数（1–90 天，默认 7）自动清理：每次保存时，删掉早于保留窗口的 `快照-YYYYMMDD` 目录。只删应用自己生成的这种目录，不认识的目录 / 散文件一律不动；关掉开关后不再新增也不清理 |
| 快照存在哪、怎么还原 | 每本书自己的 `_trash\快照-YYYYMMDD\`，文件名和章节 txt 一样。打开「本书历史」→ 找「每日快照」组（默认收起，点组头展开）→ 预览 / 还原单章 / 还原整组；还原前会把当前内容再备份到 `_trash\还原前备份-时间戳\` |
| 快照占地方，能清掉某一天的吗 | 能：打开「本书历史」→ 展开（或不用展开）「每日快照」那一组 →「清空这天的快照」→ 二次确认。它只把那一个 `快照-YYYYMMDD` 目录**移入 Windows 回收站**（可以从回收站恢复），不动章节文件、书目和其它备份；回收站不可用时只报错返回、一个文件都不动。想清别的天的，逐天点一次即可 |
| 删除的小说去哪了 | 默认进 **Windows 回收站**（可还原）；回收站不可用（例如某些网络盘）时移到书架目录的 `_trash\`，同样不会真删 |
| 导入支持什么格式 | 支持三种：① 章回自己的书文件夹（含合法 `书目.json`）→ 整本复制；② 一本书的章节 txt 文件夹（文件名带序号 `001-xxx.txt`，或 `第一章 xxx.txt`）→ 合成一本；③ 一堆完整小说 txt（每个 txt 是一整本小说）→ **默认「按原文章节导入」：按原文的「第X章 / 楔子」标题拆成多章，章名照抄原文、正文原样保留；也可以选「整本一章」不拆章。** 编码自动识别 UTF-8 / UTF-16 / GBK；原文件夹不会被移动或删除 |
| 导入时提示「超过单本导入上限 128 MB」/「看起来不是纯文本文件」怎么办 | 前者说明这个 txt 已经超过 128 MB（纯文本小说远到不了：1000 万字中文约 30 MB），为了防止主进程一次读进内存，应用直接跳过它——请先在别的工具里确认这个文件真的是小说（合并了多本 / 混进了附件的情况很常见）；后者说明文件里含 0 字节，通常是把图片 / 程序改名成了 `.txt`，或没有 BOM 的 UTF-16；用记事本「另存为」成 **UTF-8** 或 **UTF-16（带 BOM）** 再导入即可。被跳过的文件不会建书、不会留临时目录，同批其它 txt 照常导入。③ 章回书文件夹 / 章节 txt 文件夹这两种「整本复制」形态也逐 txt 过 128 MB 闸门（1.6.1 V25）：超限的单个文件不复制、记进「跳过 N 个（原因）」汇总，其余文件照常导入；现成书形态里超限那一章会从复制出的书目里去掉，不留打不开的悬挂章节，源文件夹一个文件都不会少 |
| 解开 EPUB / DOCX 后看到的文件名为什么都是 `chapter-0001.xhtml` / `word/document.xml` | 这是长期设计：导出包里的条目名**只用应用自己生成的 ASCII 名字**（书名 / 卷名 / 章名只写进正文，不参与文件名），这样任何阅读器 / Word 都不会因为书名里的特殊字符（`../`、`:`、引号、超长名字）出错。用阅读器 / Word 打开看到的内容才是你的书名与章名；从 v0.9 C-3 起还有一层闸门（`core/zip.js` 的 `assertEntryName`）拦住任何可疑条目名——真有人把作者输入拼进条目名时，导出会直接报错而不是产出能写到包外面的包 |
| 排版会不会改坏我的稿子 | 点「整理」只改空白和中文旁的半角标点（引号/省略号要你在「排版设置…」里手动勾才转），只动当前章；结果只进编辑区，不按 `Ctrl+S` 就不会写盘。想先看预览就从悬浮选择卡进「排版设置…」，看好了再点「套用到本章」。不喜欢就 `Ctrl+Z` 退回 |
| 整理完发现不对，怎么回去 | `Ctrl+Z`，或悬浮「整理」→「撤销上次整理（可撤销 N 步）」，最多连退 50 步。撤销只退编辑区，不写盘；若已经按过 `Ctrl+S`，磁盘上就是整理后的内容（应用内没有备份，见上面三条提醒） |
| 为什么有的半角标点没转全角 | 规则只在**中文旁边**转，并跳过数字、英文、网址、时间（`3.14`、`www.a.com`、`12:30`、`A.开端`）和省略号 `...`，避免误伤正文。直引号/省略号要在「排版设置…」里单独勾，默认关 |
| 行距/正文底色/正文宽度会丢吗 | 全局默认和每本书的覆盖都保存在 `%APPDATA%\chapter-writer\config.json`，重启保持；手动删了配置文件会回到默认（行间距 1.95、通栏、原纸白、中西文自动间距开）。这些设置**只改显示，不动正文** |
| 书架搜索怎么用 | 书架右上搜索框，或按 `Ctrl+F`；输入书名 / 文件夹名 / 章节名 / **作者 / 分组 / 标签**即过滤，**同时会搜正文**：书名 / 章名没命中时，书卡上方会出现「正文命中」列表（按「书 + 章」分组，组头写「本章 N 处」，下面是带高亮的上下文），点一条直接打开那一章并选中命中位置。默认每章只列 3 处，章内还有命中时点「展开本章全部」就地列出该章全部命中（单章最多 200 条），再点「收起」恢复。`Enter` 打开第一本匹配的书（书名没命中时打开第一条正文命中），`Esc` 清空。正文至少 2 个字；首次打开书架会在后台建索引，界面会显示进度，建好后自动更新 |
| 怎么给书填作者 / 简介 / 分组 / 标签 | 书架右键书卡（或右上角「⋯」）→「书籍信息…」，填好点「保存」。书卡会显示作者、分组 + 标签、两行简介；书架上方出现分组筛选（全部分组 / 未分组 / 各组）。保存只写这本书的 `书目.json`（可选字段），**不改书文件夹名、不动章节 txt**；以后想改就再点一次，留空保存 = 清掉这一项 |
| 分组会把书文件夹挪走 / 改名吗 | 不会。分组只是 `书目.json` 里的一个可选文本字段 + 书架上的筛选，书文件夹名、章节文件名都不变，也不生成任何新文件；「未分组」就是没有填过这个字段的书。分组筛选只影响本次运行的书架显示，重启回到「全部分组」 |
| 书卡的作者 / 简介会进导出吗 | 作者会进 **DOCX** 的标题页（导出 Word 时书名下面一行「作者：…」），TXT / EPUB 不带；简介 / 分组 / 标签只给书架整理和搜索用，任何导出都不会带进稿子。复制整本 / 本章仍只有书名、章名和正文 |
| 为什么书架上没有分组筛选条 | 只有当书架里至少有一本书填了「分组」并保存后，筛选条才会出现；一本书都没有分组时自动收起。在「书籍信息…」里填一个分组保存，回书架就能看到 |
| 阅读模式会改我的正文 / 书目吗 | 不会。阅读模式只通过只读的 `chapter:load` 读磁盘，正文 / `书目.json` / `config.json` 一个字节都不写，也不会生成 `_trash` 或临时文件；字号 / 行距只改阅读视图的 CSS，不保存。章节文件也不会因为阅读被改名 / 移动 |
| 阅读模式从哪一章开始、怎么从头读 | 第一次进一本书从你当前写作的那一章开始；本次运行内退出阅读再进（或换一本书再回来）会回到上次读到的那一章和章内位置 —— 它只记在内存里、不写盘，所以重开应用又从当前写作章开始，**不是书签**。想从头读就点顶栏「从头」，或展开「目录」跳到任意一章；在编辑器里明确换了章再进阅读，以编辑器当前章为起点 |
| 阅读模式的字号 / 行距会记住吗 | 只在本次运行里记住，而且**按书各记一份**：退出阅读再进（还是这本书）是刚才选的档位，换一本书回到「大 / 标准」，回到原来那本又取回它自己的档位；重启应用都回到默认。它不写 `config.json`，也不影响写作页的正文显示设置 |
| 阅读模式里有未保存提示，会丢稿吗 / 能改字吗 | 不会丢。阅读视图是只读的，显示的是磁盘上的正文；当前写作章没保存的修改仍在编辑区（提示里会说明），退出阅读后照常可以编辑和 `Ctrl+S`。阅读模式没有编辑框 / 保存按钮 |
| 阅读模式能键盘翻章吗 | 能。阅读视图里按 `←` / `→` 翻上一章 / 下一章，和顶栏「‹ 上一章」「下一章 ›」是同一条路径（到章首 / 章尾停住；不先滚到章尾，滚动仍交给滚轮 / PageUp / PageDown）。焦点在字号 / 行距 / 目录下拉里时，方向键照常属于控件（改选项），不会翻章；翻章只切阅读位置，不写盘 |
| 阅读模式能快速调字号吗 | 能。阅读视图里按住 `Ctrl` 滚鼠标滚轮（上滚放大 / 下滚缩小），或按 `Ctrl+=` / `Ctrl+-`，一档一档调（小 17px / 中 19px / 大 22px / 特大 25px），到两端停住。它和顶栏「字号」下拉是同一个档位：只改阅读视图的 CSS，不写 `config.json`，也不会把整个界面一起缩放（会拦掉 `Ctrl+滚轮` 的整页缩放）；不按 `Ctrl` 的滚轮照旧滚动正文 |
| 阅读模式能看到现在读到第几章吗 | 能。阅读模式下窗口标题会带章号，形如 `章回 - 某某书（阅读 · 第 2/3 章）`：进入时是上次读到的那一章（第一次进是当前写作章），滚动到下一章、按 `←` / `→` 翻章、从目录跳章后都会跟着变；退出阅读立刻恢复成写作页标题（`* ` 未保存星号也照旧）。标题只是一行即时显示，不写 `config.json`；阅读位置只在本次运行内记一份内存（不落盘、不做书签），重开应用从当前写作章开始 |
| 章节模板在哪设、怎么写 | 书架 →「设置 → 新建章节」：填一段纯文本（比如 `第{n}章：` 加一个空行），点「保存设置」。上面有一行**展开预览**，会按下一个新章的章号和示例章名显示实际效果。可用 `{n}`（章号）、`{title}`（章名）、`{date}`（今天，YYYY-MM-DD）；留空 = 不套用。设置里写作页的按书设置不显示这一项（模板是全局的） |
| 套了模板还会自动保存吗 | **不会**。新建 / 插入章节时模板只是填进编辑区，状态栏显示「未保存」，和手打一样按 `Ctrl+S` 才写盘；按 `Ctrl+Z` 能退回空章。已有正文的章节不会被套模板，套用过程不改 `书目.json`、不改章节文件名、也不会生成 `_trash` |
| 模板里写了「第X章：」导出会重复吗 | 会。导出 TXT / EPUB / DOCX 本来就会在每章前面加「第N章：名字」，模板如果也写标题就会出两遍。模板更适合放分隔线、固定开场白、投稿用的说明段；只想加空行的话，模板里敲一个空行即可 |
| 界面上的章节标题和导出文件里的会不一样吗 | 不会。v0.8.6 R3 起，标题栏 / 章节列表 / 阅读目录 / 校对结果和 TXT / EPUB / DOCX 导出、复制本章都走同一份 `core/chapters.js` 的 `formatTitle()`；书目里如果有自定义 `titleTemplate`，界面也按模板显示（目前界面没有改模板的入口，建书 / 导入都写默认值，这条主要是给旧书目或手工改过书目的书准备的）。原文已带号标题的章（`第1章 …` / `Chapter N`…）仍原样显示；楔子 / 番外 / 大结局 / 前传等不带号特殊标题补「第N章：」；空名章只显示「第N章」，章节列表也不再额外补「未命名」 |

| 怎么导出一本 EPUB | 写作页右上「导出 ▾」→「导出 EPUB…」→ 在范围对话框里选全书 / 某一卷 / 第 X–Y 章 →「导出…」→ 选个位置保存（默认文件名 `书名.epub`，按范围时是 `书名-卷名.epub` / `书名-第X-Y章.epub`）。这是一本标准 EPUB 3，可以直接拖进微信读书 / Kindle / Apple Books 等阅读器，或发给编辑。书里的**分卷会变成目录里的二级目录**（每卷还有一张卷名页），**一章一个 XHTML**；没有封面图，会自动生成一页纯文字封面（书名 + 范围 / 章数 / 卷数）。当前章没保存的内容也会一起导出（不写盘），保存对话框默认还开在上次导出的文件夹 |
| EPUB 导出会改我的稿子吗 | 不会。导出全程只读：章节 txt 的字节、大小、修改时间都不变，`书目.json` 也不会多出字段。EPUB 里的段首缩进和段间空行是 CSS 排版，**不往你的正文里塞空格**；排版规则固定为「段首缩进 2 字 + 段间空一行」，不跟随「排版设置…」对话框里记住的规则 |
| EPUB 在阅读器里的目录对吗 | 目录按书目的卷 / 章顺序生成：有分卷的书是「卷 → 章」两级，没分卷就是一层章列表。包里同时带 `nav.xhtml`（EPUB 3）和 `toc.ncx`（EPUB 2 兜底），新旧阅读器都能认；章名 / 章号规则和 TXT 导出完全一致（原文已带号标题照抄；楔子 / 番外 / 大结局等不带号特殊标题补「第N章：」） |
| 怎么导出一份 Word（DOCX）稿子 | 写作页右上「导出 ▾」→「导出 DOCX…」→ 在范围对话框里选全书 / 某一卷 / 第 X–Y 章 →「导出…」→ 选位置保存（默认文件名 `书名.docx`，按范围时是 `书名-卷名.docx` / `书名-第X-Y章.docx`）。文档开头是标题页（书名 / 书目里填的作者 / 范围与章数），之后按「卷标题 → 章标题 → 正文」排；正文段首缩进 2 字、1.5 倍行距、宋体，用 Word / WPS / LibreOffice 都能直接打开。当前章没保存的内容也会一起导出（不写盘），保存对话框默认还开在上次导出的文件夹 |

| 校对面板会改我的稿子吗 | 不会。校对只**列出**可疑位置：点结果只是把光标选中到正文那一处，不会自动改字、不会写盘，也不碰 `书目.json` 和 `_trash`。要改就自己按正常编辑流程改，按 `Ctrl+S` 才会写盘 |
| 校对有哪些规则、阈值能改吗 | 五条内置本地规则：半角标点（中文旁边的 `, . ; : ! ?`，和「排版」同一个判定函数）、超长段落（> 500 字）、同一个双字词在 300 字内出现 ≥ 3 次、连续标点（≥ 3 个，连排的「……」/「——」按一个标点算）、多余空行（≥ 2 个连续空行）；外加可选的**自定义校对词表**（第六条）。阈值目前固定。重复用词只按「双字词、不重叠命中」统计，像「突然想起」连写三次这种，会归并成一条（只报最靠前的「突然」），不会刷出「突然 / 然想 / 想起」三条；常用词多出现几次也会列出来，属于「疑似」不是错误，判断由你自己做 |

| 敏感词预检的词表从哪来，应用会内置词表吗 | **不会内置、不会下载任何词表**。词表是你自己的 txt（每行一个词），在书架 →「设置 → 敏感词预检」里点「选择…」挑文件，应用只记住路径（`config.json` 的 `sensitiveWordsPath`），文件本身只读、不复制、不改写。想换词表随时重新选；点「清除」只是忘掉路径 |
| 敏感词预检会改我的稿子吗 | 不会。它只**列出**命中的词、章名、第几行第几字和上下文；点结果只是切到那一章并选中那个词，不会自动改字、不会写盘，也不碰 `书目.json` / `_trash` / 词表文件。要改就自己按正常编辑流程改，按 `Ctrl+S` 才会写盘 |

| 怎么标记哪章写完了 / 哪章要改 | 右键章节 →「标记为完稿 / 待修 / 草稿」，名字前的小圆点会变绿/黄/灰；再右键 →「编辑备注…」写一句提醒（最多 200 字），鼠标悬浮在章节上能看到。书卡会显示「完稿 X/Y 章」。这些**只写 `书目.json`，正文 txt 不会变**；旧书没有这些字段也照常打开（默认草稿） |
| 书卡上的「检测到同步冲突副本」是什么 | 书架目录在 OneDrive / 坚果云里，两边同时改过同一本书时，同步盘会在书文件夹里多生成 `书目 (conflicted copy 1).json`、`001-起风-冲突副本.txt` 这类文件。写作器只标出来提醒，点提示能看到文件名、打开书文件夹；**不会自动合并或删除**，也不会把副本当章节。请手动对比后把要保留的内容合并回原章节，再把副本移走 |
| 书目.json 里的 schemaVersion 是什么，旧书会坏吗 | 是书目格式的版本号（当前 1），给以后加字段留的保险。旧书没有这个字段照常打开；只是打开不会改文件，等下次正常写盘才补上。不会碰章节 txt，也不需要手动处理 |
| 章节状态和备注会写进正文导出吗 | 不会。状态/备注只是写作进度标记，存在书目里；导出/复制的 txt 仍只有标题行和正文，一个字节都不多 |
| 复制本章和复制整本有什么区别 | 「复制整本」（右上「导出 ▾」）复制全书，带章名和卷名，当前章未保存内容也算；「复制本章（平台格式）」（右键章节或 `Ctrl+Shift+C`）只复制这一章**正文**，套好「段首缩进 + 空一行（含缩进）」再进剪贴板，方便直接贴到平台作者后台的正文框（章名在后台单独填）。两者都**不写盘** |
| 复制本章后章名去哪了 | 故意不带章名：起点/晋江等平台的作者后台，章节名和正文是两个输入框，带上章名还得删。需要章名时可在侧栏双击章节名复制 |
| 复制本章粘过去空行没丢吧 | 用的是「空一行（含缩进）」：段与段之间的空行里放了两个全角空格（`　　`），平台/编辑器吃掉纯空行时也不会挤成一坨。如果你的平台把带空格的空行也吞了，那是平台编辑器在收空白，可试试 `Ctrl+Shift+V` 纯文本粘贴 |
| 朗读没声音 / 提示「系统语音没有响应」怎么办 | 朗读用的是 Windows 本地语音：先确认系统装了中文语音（设置 → 时间和语言 → 语音 → 添加语音），再看默认音频输出是否正常。应用不联网、不下载语音包，也**不会装作在读**：没有语音或没有音频设备时会直接提示，而不是一直显示「朗读中」 |
| 朗读会改我的稿子 / 会写盘吗 | 不会。朗读只把**编辑区里的文字读给系统语音听**，不改正文、不写盘、不切章、也不改 `书目.json`；当前章有未保存的修改时读的也是编辑区里的最新内容（和你看到的一致）。一改字、切章或收起小条就立刻停 |
| 朗读从哪一段开始念、能听完整本吗 | 打开朗读时从**光标所在的段落**开始念；刚打开章节、光标停在全文末尾时从头念。读完一段会自动接下一段，停止后从当前段继续。一次只读**当前这一章**（不做整本连读），换章请重新点「朗读」 |
| 能选朗读的声音和语速吗，会记住吗 | 小条上有**语速**（0.8×–2.0×）和**语音**下拉，列出系统里可用的语音。这两个选择只在本次朗读打开期间有效，**不写配置**，关掉小条再打开回到 1.0× + 系统默认；想换系统语音请到 Windows 设置里装 |
| 「跟随高亮」是什么、会乱动光标吗 | 它会把编辑区的**选区**移到正在读的那一段（只改选区，不改文字、不写盘），方便你边听边看；默认关。编辑区没有焦点时看不到选区高亮，但这只是显示问题。开不开都不影响朗读本身 |
| 怎么把整章听一遍找病句 | 点写作页右上「朗读」→ 自动从第一段开始念；中途想停就点「■ 停止」或按 `Esc`。听不惯系统语音的话，可以配合「校对」面板一起用：朗读负责语感，校对负责标点 / 重复用词 / 超长段落 |
| 正文里那些黄底的 ␣、浅红块、左边黄线和淡色底是什么，会改我的稿子吗 | 是「编辑器小件」的**只读标记**（写作页「显示 ▾ → 显示不可见字符 / 超长段落提示 / 当前段落高亮」）：黄底 ␣ = 全角空格，浅红底 + 小点 = 行尾空白，左侧淡黄竖线 = 这一段超过阈值（默认 500 字，可在「设置 → 正文显示设置 → 超长段落阈值」里改成 50–20000；写作页里改只影响这本书），光标所在段的**淡色底 + 左侧细线** = 当前段落高亮（跟着光标走，空行不高亮）。它们画在正文上面的一层影子层里，**不改正文、不写书库、不参与复制和导出**；关掉开关（或切回书架）立刻收起。「当前段落高亮」的开关和颜色会按书记住（只写 `config.json`，不碰正文 / 书目），另外两个开关和超长段落阈值也按书记住；正文超过 30 万字时整层标记会收起（只提示一次），避免超大单章每次都重建整章 DOM |
| 当前段落高亮的颜色能改吗、会跟着主题变吗 | 能。默认「跟随主题」：6 套背景主题各自配好了淡色底 + 左侧细线（夜间是暖色暗底，不刺眼）。写作页「显示 ▾」里的「高亮颜色」有 6 个预设色 + 取色器，也可以到「设置 → 当前段落高亮」里改（写作页里改只影响这本书，书架「设置」里改是全局默认；没单独设置过的书用全局默认）。开关和颜色都只写 `config.json`，章节 txt / `书目.json` 一个字节不动；换电脑时这两项跟着配置文件走，不跟着书走 |
| 查找后正文里一片淡黄色底纹是什么，怎么一处一处看 | 是**查找结果高亮**（`v0.8-11`）：范围选「当前这一章」查找后，本章所有命中都会在正文上高亮，当前那处颜色更重、同时被选中。用查找面板里的「↑ 上一处 / ↓ 下一处」、查找框里 `Enter` / `Shift+Enter`、或**关掉面板后按 `F3` / `Shift+F3`** 前后跳（到两端会绕回），状态栏「查找 3/12」小标签点一下也是下一处；`Esc` 清除。它只是显示层：不改正文、不写盘、不写配置，改字 / 切章 / 改查找词就自动结束。想长期保留这次查找就点面板里的「存成书签」 |
| 查找书签存在哪、会不会改我的书 | 不会改书。书签按「书 + 章」只把**查询词 + 大小写选项**（加书名 / 章名 / 章号 / 书路径用于显示）存进 `%APPDATA%\chapter-writer\config.json` 的 `findBookmarks`，**不存正文、不存命中位置**，也不改 `书目.json` / 章节 txt / 书文件夹。打开书签所在章会自动高亮（按当前正文重新扫描），正文改过也能定位；改到没有命中就暂时不亮，书签还在。面板里能列本机全部书签、点一条跨书跳过去、删除只删配置里那条记录。换电脑 / 重装不会跟着书文件夹走；删配置只会丢书签本身 |
| 怎么知道这一章比上一章短了 | 写作页状态栏「本章字数」后面会多一句「比上章短 45%」——只有上一章 ≥500 字、这一章比它短 40% 以上才出现；章节列表每一项右侧也有本章字数（来自书目缓存，保存后更新）。这只是提醒，不会拦你保存，也不代表写错了 |
| 选中一段文字想数字数 | 选中后状态栏会出现「选中 356 字 / 3 段」：字数去掉空白，和「本章字数」同口径；段数按选区触及的非空行算（只选段首缩进也算触及了一段，空行不算） |
| 怎么在两段之间快速跳 | 写作页按 `Alt+↓` / `Alt+↑`，光标会在自然段开头之间跳（跳过段首缩进），只移动光标、不改字；段落定义和「朗读」一致（一个非空行 = 一段） |
| 章节列表里按 Alt+↑ / Alt+↓ 能跨卷吗 | 能。焦点在左侧章节列表时，`Alt+↑` / `Alt+↓` 把这一章上移 / 下移一格：同一个卷里直接挪；已经在**卷尾**再按 `Alt+↓`、在**卷首**再按 `Alt+↑`，就跨到**相邻的那一卷**（卷尾 ↓ = 下一卷卷首、卷首 ↑ = 上一卷卷尾），跨之前先弹一次确认，点「取消」什么都不动。一次只跨**一个**卷（中间的空卷也算一步）；首卷首章往上 / 末卷末章往下不动；「未分卷」不是卷，键盘不会把章移进 / 移出「未分卷」（要用拖拽或右键「移到卷…」）。只改 `书目.json` 的顺序与卷归属，章节 txt 永不改名、正文一个字节不动 |
| 怎么进入专注模式 / 打字机模式 | 写作页按 `F11` 或点右上「专注」：左栏、章节栏分隔条、顶栏一起收起，正文占满窗口，右上角留一条极简退出条；`Esc`、再按 `F11` 或点「退出专注」都能退出，布局 / 章节栏宽度 / 滚动位置会回到进去之前。想要「光标行固定在屏幕上方 1/3」就点小条上的「打字机」（显示 ✓）——它只调滚动，不动正文 |
| 专注模式会不会改我的稿子 / 写配置 | 不会。它只给写作页加一个 CSS class 和调 `textarea.scrollTop`：不写正文、不写 `书目.json`、不写 `config.json`，也不生成 `_trash`。开关只记在内存里，回书架 / 重启就回普通布局（下次要再按 F11） |
| 为什么按 F11 窗口没有全屏 | 这里的 F11 是**应用自己的专注模式快捷键**（隐藏左栏和顶栏），不是 Windows / Chromium 的全屏；窗口大小、标题栏都不变。想要系统全屏请用窗口右上角的最大化 |
| 打字机模式有时候光标不在 1/3 处 | 两个已知情况：①正文超过 **30 万字**时打字机暂停自动对齐（每次按键量光标位置开销太大，正文照常编辑）；②只有光标在动（打字 / 方向键 / 鼠标点段落）时才对齐，用滚动条滚走以后不会自己拉回来，回到正文点一下或按方向键即可 |
| 应用弹「程序遇到一个内部错误」是什么意思 | 主进程遇到了一个没有接住的异常，应用已经把**错误类型 / 错误码 / 栈**写进日志，并且**没有退出**（避免你丢稿）。先按 `Ctrl+S` 保存，再重启应用即可；如果反复出现，打开「设置 → 诊断日志 → 打开日志文件夹」，把最近一份 `chapter-writer-*.log` 里的内容看清楚再决定要不要反馈 |
| 保存总是失败，怎么排查 | 先看状态栏红字（磁盘满 / 文件被占用 / 无权限）；文字提示只是结论，具体是哪个文件、什么错误码在日志里：设置 →「诊断日志」→「打开日志文件夹」，找 `save-failed` 那几条（带章节文件名和 `EPERM` / `EACCES` / `ENOSPC` 之类的错误码）。日志不含正文，可以放心贴出来 |
| 日志里会有我的小说内容吗？能删吗 | 不会有正文。日志只记时间、错误类型、错误码、IPC 频道、文件名、版本和调用栈，还会把连续 24 个以上汉字当正文隐去、把本机绝对路径收成「`…\最后一节`」（v0.9 C-4 起：本机用户名、书库上级目录都不会落进日志）；保存失败也只记错误码和文件名。**章节文件名仍在**（里面带章号，看得出是哪一章），分享前扫一眼仍然是好习惯。日志可以随时删：打开「设置 → 诊断日志 → 打开日志文件夹」，删掉里面的 `chapter-writer-*.log`，应用下次出错会重新建；删日志不影响书库 |
| 怎么检查更新？会自己下载安装吗 | 书架 →「设置 → 检查更新」→「检查更新」。**只有点这一下才会联网**（启动时不会检查、写作时不会后台偷查）：发现新版本会显示版本号并出现「打开下载页」，点了只是用系统浏览器打开 GitHub Release 页面；**应用不下载、不安装、不替换任何程序文件**，升级与否完全由你决定。已是最新则显示「已是最新版本」。检查过程不写配置、不写书库、不产生文件 |
| 检查更新失败 / 一直转圈怎么办 | 只会显示一句提示，不会卡住设置弹层，也不会影响写作和保存。常见原因：没联网、代理 / 防火墙拦住 GitHub、GitHub 限流（未登录每小时 60 次）、返回内容被代理改坏。确认网络后过一会儿再点一次即可；不想检查就关掉设置，应用不会自己重试 |
| 检查更新会泄露我的稿子吗 | 不会。它只向 GitHub 发一次 GET 请求拿最新 Release 的版本号，请求头里只有 User-Agent / Accept，**不发送书名、章名、正文或书架信息**；检查结果只记在内存里，不写配置、不写日志正文，关掉设置就没了 |
| 想同时写两本书怎么办 | 书架书卡右键 →「在新窗口打开」，就会在第二个窗口打开这本书，原窗口可以继续留在书架或打开另一本。两个窗口各自编辑、各自 `Ctrl+S`，互不影响；写作页里的「排版 / 设置 / 查找」等弹层也是各窗口独立的 |
| 为什么点「在新窗口打开」没有新窗口，反而跳了一下 | 说明这本书**已经在另一个窗口打开**了。为了避免同一个书文件夹被两个窗口同时改（互相覆盖未保存内容），应用会直接聚焦那个已有窗口并提示，不会开第二个；想在这个窗口打开它，请先关掉另一个窗口，或在那个窗口里写 |
| 为什么我删不掉某本书 / 某章，提示「正在另一个窗口打开」 | 那本书正开在另一个窗口里。跨窗口删书 / 改书名 / 改章名 / 删章 / 整理 / 整本替换 / 导入覆盖都会被拒绝，避免另一个窗口之后保存时把已删的内容又写回去。处理：先切到那个窗口保存 / 关掉它，或在那个窗口里自己删；如果你是想删这一本，回到书架刷新一下再删 |
| 关掉一个窗口应用就退出了吗 | 不会。关窗口只关这一个，有未保存修改时只针对这个窗口弹「保存 / 不保存 / 取消」，取消后另一个窗口照常写作。**只有最后一个窗口关闭时应用才退出**；Windows 关机 / 注销时，有未保存修改的窗口会尽力各拦一次（系统不强等应用，属于尽力而为） |
| 升级怎么办 | 在「设置 → 检查更新」里点检查，有新版本时点「打开下载页」去 GitHub 下载安装包，再双击新版本安装包覆盖安装即可；书架和配置不受影响。**应用不会自动下载或静默安装**，也不会替你校验安装包签名 |
